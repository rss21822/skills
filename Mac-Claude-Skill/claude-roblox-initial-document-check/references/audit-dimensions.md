# 監査観点

## 正本境界（最重要）

同じ事実を2つ以上の文書が権威として持っていると、片方を直したときにもう片方が古くなる。これが文書体系で最も壊れやすい箇所。

**確認すること**:
- 各文書のヘッダに「この文書が何の正本か」の宣言があるか
- 数値（バランス値・性能予算・報酬テーブル・閾値）が、データ定義以外の文書に**実値**として書かれていないか
- 参照（`DATA.XXX` のようなID）ではなく実値が散文中に埋まっていないか

**軟性の二重正本に注意**: 「3秒内」のような散文が、実はデータ定義の値と同じことを言っている場合。今は一致していても、データ側を変えたとき追従しない。ID参照に置き換える。

**版番号の二重軸**: 文書のバージョン（v2.5）とランタイムのスキーマバージョン（"2.4.0"）が別々に存在することがある。それ自体は正しいが、同期規則がないと将来ずれる。

## 矛盾

- 数値の食い違い（SKU数、件数、上限値）
- 用語の食い違い（同じものを別名で呼ぶ、別のものを同名で呼ぶ）
- 状態の食い違い（チェックリストが「完了」を主張しているが実態は未完了）
- **プラットフォーム前提と実環境の食い違い** — 見落とされやすい。文書がWindows専用APIを前提にしていて開発機がmacOS、といったケース

## 参照切れ

- 存在しない文書・節・IDへの参照
- 削除されたファイルへの参照（`git status` で削除を確認し、`git show HEAD:<path>` で内容を見る）
- **行番号参照** — 改訂のたびに腐る。節参照へ置き換えるべき負債として指摘する

## 未解決状態

`TODO` / `TBD` のような古典的マーカーがなくても、未解決はある。次を探す:

- 状態タグ（`[OPEN]` `[PROPOSAL]` `[ASSUMPTION]`）
- 決定台帳で `RESOLVED` 以外の状態
- チェックリストの未チェック項目
- 「〜が未承認なら停止する」のような条件付きブロッカー

各項目について **blocking かどうか**を判定する。実装開始を止めるものと、後のフェーズで決まればよいものを分ける。

## 実装可能性ギャップ

文書が「読める」だけでは実装できない。次が揃っているかを見る。

| 要素 | 確認 |
|---|---|
| 作業単位の定義 | ファイル単位のスコープ、変更禁止範囲、完了条件、テスト、ロールバック |
| 機械可読契約 | 通信スキーマ、保存スキーマ、イベント辞書。文書内の散文ではなくスキーマとして |
| ビルド/テスト/実行コマンド | 具体的なコマンド列。ツールのバージョン固定 |
| トレーサビリティ | 要件ID → 設計 → テストの対応 |
| リリース/復旧手順 | 公開、停止、切り戻し |
| 人間専用作業の分離 | AIが実行できない作業（ダッシュボード操作、権利承認、実機測定）が識別されているか |

**制作手段の欠落**に注意。「素材の制作主体はAI」と書いてあっても、AIが3Dモデルや音源を作る具体的な手段（ツール連携、パイプライン）が定義されていなければ、その部分は実装不能。コード実装より見落とされやすい。

| 公開・復旧 | 環境分離、ロールバック、監視 |

各項目に確信度ラベルを付ける（下記）。

## 確信度ラベル

所見は事実と推測を分ける。

| ラベル | 意味 |
|---|---|
| Confirmed | コード・設定・出力で直接確認した |
| Reported | 文書に書かれているが未検証 |
| Inferred | 証拠から推測できるが確認が要る |
| Missing | あるべきだが存在しない |
| Conflicting | 複数の情報源が食い違う |

「文書にこう書いてある」と「実際にこうなっている」を混ぜないこと。実装未着手のプロジェクトでは、ほとんどの成果物が Confirmed as spec / Missing as artifact になる。これは正常。

## 過剰厳密化

SKILL.md §3を参照。目的を1〜3個に言語化し、手段のコストと比べる。

**過剰の典型**:
- 実装が存在しない段階で、そのコードの内部構造を文書が決めている
- 1つの保証のために数十行の検証手順
- 特定OS・特定APIへの強い依存
- 形式的証明（隔離の証明、ハンドル継承の証明）が、達成したい機能保証に対して過大

**過剰でないもの**:
- 決定論の要求（同じ入力から同じ出力）
- バージョンとハッシュの固定
- 権威境界の明示
- 実測値の要求（推測禁止）

これらは実装コストが小さく、外すと実害が出る。
