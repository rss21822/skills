# チュートリアルの設計

## 目次
1. ステージの型
2. 基本操作（必須）: 移動方式別
3. first wall とコア/初成功
4. 時間配分と救済
5. サーバーの段階管理
6. 本編への受け渡し

## 1. ステージの型
`welcome → basics → core → first_success → complete`。名前と中身はゲームに合わせてよい。**basics は外さない**（`Config.validate` が確かめる）。各ステージは 1 つの学び。読ませるより、やらせる。

## 2. 基本操作（必須）
1 ステップ 1 操作。成功は操作の検出で判定（OK ボタンではない）。端末 3 種の文言を実際の割り当てから。

- **既定の歩行（オビー、アドベンチャー、シミュレーター）**: move_forward → move_side → (move_back) → jump（count 2）→ 必要なら camera（turn 90〜120）。検出は `MoveDirection`×カメラ。
- **独自の移動（スケート、車、ボート、飛行）**: 入力モジュールのアクション（accelerate / steer / brake / drift / boost）を `actions` に出し、`detect` にその名前。止まれない移動ならラインアウト等の罰を basics 中だけ外し、外れたら開始地点へ戻す。
- **クリック移動・トップダウン**: 目的地マーカーへ到達をサーバーで検出（stage を server 側に）。
- **戦闘・アクション**: 移動の次に主要アクション（攻撃、スピン、ダッシュ、ガード）を count で。
- **ツール/ビルド系**: 選択 → 設置 → 回転を各 count 1。
- 端末に無い操作（スマホにジャンプ無し等）は省くか別操作で。
- 1 ステップ 1〜2 秒の操作量、basics 全体で 1 分前後。

## 3. first wall とコア/初成功
文脈シートの「新規が最初につまずく一点」を core で練習させ、first_success で越えさせる。
- 対戦: 弱い NPC 1 体（逃げない・攻撃しない）を倒す。
- オビー: 最初に落ちやすい形のジャンプを、落ちても即リスポーンの短い区間で。
- シミュレーター: 最初の収集 → 売却 → アップグレードを一巡。
- レース: 最初のカーブをはみ出さずに抜ける、ドリフト 1 回。
初成功は**サーバーが検出**（撃破、チェックポイント、売却）して `flow:serverEvent`。失敗しても痛くない（ライフ無限、時間無制限、罰なし）。

## 4. 時間配分と救済
全体 2〜4 分。各ステップ `STEP_FALLBACK_SECONDS`（20〜30 秒）、各ステージ `STAGE_FALLBACK_SECONDS` で自動的に先へ。救済で進んだら文言で責めない。スキップボタンは Owner が望む場合のみ（`flow:finish` = 完了扱い）。

## 5. サーバーの段階管理（TutorialFlow）
- 段階はサーバーが持ち、属性（TutorialStage / TutorialStepId）で複製。クライアントは「今のステップをやった」と報告するだけ。
- report は段階・ステップ一致、`MIN_STEP_SECONDS` 以上経過、0.2 秒以上の間隔のときだけ受理。クライアントが進められるのは `clientStages`（既定 welcome, basics）だけ。
- 最後のステージに入った時点で `onComplete` → `gate:complete`。

## 6. 本編への受け渡し
complete では次にやることを 1 つだけ示す（最初の試合へ、ロビーのモード選択、次のステージ）。専用 Place なら Result/完了カードの後に自動でロビーへ。報酬を出すなら完了の記録と同じ判定で一度だけ。
