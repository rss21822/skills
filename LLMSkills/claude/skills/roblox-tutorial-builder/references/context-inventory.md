# 文脈シート

チュートリアルは「このゲームの操作と、このゲームで新規プレイヤーがつまずく所」を教えるためにある。文脈シートはその材料を、推測ではなくリポジトリと Owner の言葉から集めたもの。設計（step 2）に入る前に埋め、成果物として残す。

`scripts/scan_context.py <repo>` の出力は手がかりの一覧にすぎない。どのバインドが今も生きているか、どの文書が最新か、どのフラグが本番で真か、は grep では決まらない。手がかりのファイルを開いて確かめてから書く。

## 目次
1. シートの形式
2. 各項目の見つけ方
3. 食い違いと未確定の扱い
4. 記入例（短縮）

## 1. シートの形式

```
# 文脈シート — <ゲーム名>（<日付>）

ゲームの一言: <ジャンルとコアループを 1 文で>
対象: <年齢層・端末の比率がわかれば>
ソース言語: <英語 / 日本語 / …>（根拠: …）。翻訳: <LocalizationTable / 独自の表 / なし>

## 新規プレイヤーの壁（first wall）
- <最初につまずく一点>（根拠: プレイテストのメモ / GDD / Owner / 離脱データ）
- <二番目があれば>

## 操作（実際の割り当て）
| 操作 | キーボード | ゲームパッド | タッチ | HUD での呼び名 | 定義場所 |
- 移動: …
- カメラ: …
- ジャンプ: …（使わないなら「なし」）
- 主要アクション: …
- その他（チュートリアルで触れる物だけ）: …
リバインド: <できる / できない>（できるなら表示はその設定から）

## 移動とカメラ
- 移動方式: <Roblox 既定の Humanoid 歩行 / 独自（スケート・車・飛行・クリック移動・トップダウン）>（根拠: …）
- 既定の PlayerModule を使うか: <はい / いいえ / 一部>
- カメラ: <既定 / 固定 / 一人称 / 追従カメラ>
- 検出に使える値: <Humanoid.MoveDirection / 入力モジュールの押下状態 / 速度など>

## Place と到着
- Place: <名前と PlaceId（環境別）>
- 到着経路: <直接参加 / フレンド参加 / パーティ / Place 間テレポート / 予約サーバー / プライベートサーバー>
- チュートリアルを動かす場所の候補: <同じサーバー / 専用 Place>（理由）

## 保存と「遊んだことがある」
- プロフィール: <DataStore 名・ライブラリ・スキーマ版・新しい項目の足し方>
- 遊んだことがある印: <試合数・ステージ到達・所持品など / 無い>
- 環境ごとの分離: <staging と production で別のキー空間か>

## 環境
- 判定: <game.GameId / PlaceId / 定数モジュール / IsStudio>
- Studio で DataStore が使えるか: <未公開ファイルでは不可 / API アクセス有効の公開 Place>

## UI の語彙
- テーマ/スタイルのモジュール: <パス>
- 再利用できる部品: <パネル・ボタン・見出し・メーター・トースト・コーチカード…>
- 書体と色: <…>
- 安全域: <トップバー・親指スティック・ジャンプボタン・HUD が空けている場所>
- スマホのレイアウトの決まり: <…>

## 既存のオンボーディングとフラグ
- 既存のチュートリアル/コーチ/ヒント: <パスと動作、残すか置き換えるか>
- 強制表示・デバッグのフラグ: <名前、どこで真になるか>

## テストとビルド
- テストの走らせ方: <コマンド>
- スクリプトが Place に入る経路: <Rojo build / Studio で保存された Place に直接 / 両方>
- 触ってはいけないもの: <他の人の作業中のファイル、バイト固定のファイル、共有コード>

## 未確定（Owner への質問）
- …
```

## 2. 各項目の見つけ方

### ソース言語
- プレイヤー向けの文字列（`.Text =`、`title =`、`text =` など）の言語。`scan_context.py` が CJK の割合を出す。
- LocalizationTable や翻訳表があれば、その「元の言語」の列。
- 設計書が日本語でも、ゲーム内の文字が英語なら英語がソース。逆もある。迷ったら Owner に聞く。

### first wall
- プレイテストのメモ、設計書の「新規」「初心者」「離脱」の節、決定記録（DECISIONS）、Issue。
- 試合系なら「最初の撃破までの時間」「最初の死因」、オビーなら「最初に多く落ちる場所」、シミュレーターなら「最初の売却/アップグレードを見つけられない」。
- データが無ければ、コアループの中で操作が一番難しい所（タイミング、二つの操作の組み合わせ、隠れた仕組み）を候補にして Owner に確かめる。

### 操作
- 入力モジュール: `ContextActionService:BindAction`、`UserInputService.InputBegan`、`Enum.KeyCode.*`、`CreateTouchButton` / 独自のタッチボタン、`JumpRequest`。
- 同じ操作が端末ごとにどこへ割り当てられているか。タッチには独自のボタンがあることが多い（HUD のボタン）。
- HUD での呼び名（ボタンのラベル、アイコン）。チュートリアルの文言はこれに合わせる。
- リバインドの設定があれば、表示はその設定から取る（テンプレートの `{key:...}` は既定の割り当てにしか使えない）。

### 移動方式
- `Humanoid.WalkSpeed` / `MoveDirection` だけなら Roblox 既定の歩行。`BasicControlsDetector` の `move_*` がそのまま使える。
- `LinearVelocity`、`VectorForce`、`VehicleSeat`、`AssemblyLinearVelocity` の直接設定、`PlatformStand`、`AutoRotate = false`、独自のコントローラーなら独自の移動。入力モジュールの押下状態（加速・ブレーキ・旋回など）を `actions` として検出に渡す。
- 既定の PlayerModule を無効化しているか（`GetControls():Disable()`）。

### Place と到着
- `*.project.json`、Place ファイル、PlaceId の定数、`TeleportAsync` / `ReserveServer` / `GetJoinData` の使い方。
- 試合 Place からロビーへ戻る経路があれば、「ログイン」の判定に効く（`SourcePlaceId`）。

### 保存と「遊んだことがある」
- `GetDataStore` の名前、ProfileService/ProfileStore、スキーマの版と移行の仕組み。
- 新しい項目をプロフィールに足すのが安全か（全 Place に同時に出す必要があるか）。安全でなければ別の記録 DataStore（テンプレートの方式）。
- 試合数・クリア数・所持品・レベルなど、既存プレイヤーを見分けられる値。

### UI の語彙
- テーマモジュール（色表、書体、ボタン生成関数）、HUD の各ビュー、コーチカードやトースト。
- スマホのレイアウト（親指スティックとジャンプボタンの位置、HUD が空けている場所）。
- 既存の UI テストが縛っている名前や階層（壊さない）。

### テストとビルド
- テストの実行コマンド（Lune、TestEZ、独自のハーネス）。
- Rojo で組み立てるのか、Studio で保存された Place が正本なのか（後者なら差し込み方が変わる）。
- `git status` と最近の変更（他の人やセッションの作業中のファイルを巻き込まない）。

## 3. 食い違いと未確定の扱い

- 文書とコードが食い違えば、今動いているのはコード。ただし文書が「これから変える」と書いているなら Owner に確かめる。
- 割り当てが端末によって無い操作（スマホにジャンプが無い等）は、その端末ではそのステップを省くか別の操作で教える。
- 決められない点は「未確定」に書き、既定値を置いて先へ進める（例: 「production のテスターは空のまま。Owner の指示待ち」）。報告で必ず触れる。

## 4. 記入例（短縮）

```
ゲームの一言: 氷上で回転して相手をリンクの外へ弾き出す対戦（最大 12 人の FFA）。
ソース言語: 英語（UI 文字列の 97% がラテン文字。日本語は翻訳表）。
first wall: スピンを当てる前に自分がラインの外へ滑って落ちる（プレイテスト 2026-10-07）。
操作:
- 加速 W / RT / 親指スティック上、旋回 A・D / スティック、ブレーキ S / スティック下、スピン F / X / SPIN ボタン
移動: 独自（スケート。最低速度があり止まれない。MoveDirection では前後が取れない → 入力モジュールの押下状態）
Place: Lobby / Classic / Death Ball / Tutorial（専用、予約サーバー）
遊んだことがある印: プロフィールの試合数（公式・練習）と試合履歴
UI: 試合 HUD の Rinkside Broadcast（黒地・白の太字・黄色のアクセント）、Result 画面
未確定: production のテスター一覧（Owner）
```
