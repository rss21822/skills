# Roblox チュートリアル

そのゲームの新規プレイヤーが、最初の数分で「操作がわかった、勝てた、もう一回やりたい」となるチュートリアルを、**プロジェクトの文脈から**作る。

失敗は 4 通りある:

1. **汎用のチュートリアル** — スケートや車のゲームに「WASD で歩く」、スマホの親指スティックしか無い人に「W を押す」、ゲームが使っていない言語の文章、HUD と無関係な AI 既定のカード UI。どのゲームにも付けられる説明は、このゲームの説明になっていない。
2. **出る人を間違える** — 確認用の「毎回表示」フラグの消し忘れで全員に毎回出る。完了時にしか記録しないので途中でやめた人に毎回出る。壊れた記録を初回扱いして出し続ける。試合から戻るたびに「ログイン」と数える。
3. **詰まる・閉じ込める** — その端末に無いボタンを要求する、成功を検出せず「OK」を押させるだけ、時間切れの救済が無い、相手が強すぎる、送り出しに失敗してロビーで固まる。
4. **テスターが確かめられない** — テスターの記録を書いて 2 回目から出なくなる。テスト用の UserId を本番に残して他人の体験を変える。

## 成果物

1. **文脈シート**（`references/context-inventory.md` の形式）: 読んだもの、採ったもの、未確定の点。
2. **設計メモ**: ステージ構成、各ステップの検出方法と端末別の文言、初回判定とテスター、失敗時の扱い、UI の作り方、どこで動かすか（同じサーバー / 専用 Place）。
3. **実装**: テンプレート（下）をゲームへコピーして接続し、ゲーム固有の部分（UI、コア/初成功の検出、本編への受け渡し）を書く。
4. **テスト**: テンプレートの Lune テストをゲームのコピーに向けて全ケース合格させ、ゲーム固有のケースを足す。`Config.validate` が true。
5. **検証と報告**: Studio で実際に入力して確かめる。Owner の作業（テスター UserId の確認、チュートリアル Place の作成、公開、RTBF）を書き出す。

テンプレート（`assets/`。ゲームの共有フォルダへコピーして使う）:

- `TutorialRecord.luau` — 記録の規則（純粋関数）と DataStore ストア、Studio/テスト用のメモリストア。
- `TutorialGate.luau` — その参加でチュートリアルを出すか（ログインか、テスターか、既存プレイヤーか、記録）。開始の計上・返却・完了。
- `TutorialFlow.luau` — サーバーの段階管理。クライアントの報告を段階・ステップ・時間・頻度で検証、サーバー検出のステージ、フォールバック、完了。
- `BasicControlsDetector.luau` — 基本操作の検出（Humanoid.MoveDirection とカメラ向きで端末を問わず前後左右、ジャンプ、押し続け/回数の計測、端末判定）。
- `TutorialGuideController.luau` — クライアント側: サーバーの段階に追従し、検出してゲームの UI（view）を動かし、報告する。見た目は持たない。
- `TutorialConfig.luau` — ステージ、基本操作のステップ（検出・目標・端末別の文言）、テスター一覧（環境別）、フォールバック、`validate`。
- `TutorialRouting.luau` — 専用のチュートリアル Place へ一人ずつ予約サーバーで送る（ロビー側）。
- `examples/` — 同じサーバーで動かすときのサーバーとクライアントの配線例。
- `tests/test_tutorial_templates.luau` — 上の全部の契約テスト（初回のみ・テスター・失敗時の返却・段階管理・検出）。

## 手順

### 1. 文脈を読む

推測で作らない。チュートリアルの価値は「このゲームの操作と壁を正確に教える」ことにある。

1. `python scripts/scan_context.py <repo> --out context-draft.md` で手がかりを集める（操作、移動方式、カメラ、保存、Place とテレポート、環境、UI、言語、既存のオンボーディング、強制フラグ、テスト）。
2. 手がかりのファイルを開いて読む: 設計書（GDD、決定記録、プレイテストのメモ）、入力モジュール（キー・パッド・タッチの実際の割り当てと HUD での呼び名）、移動とカメラの仕組み、HUD/テーマのモジュール、プロフィールのスキーマと「遊んだことがある」の印、Place 構成と到着経路、環境の判定、既存のチュートリアル/コーチ/デバッグフラグ、テストとビルドの手順。
3. `references/context-inventory.md` の文脈シートを埋める。コードと文書が食い違えば、動いているのはコード。わからない点は「未確定」と書いて Owner への質問にする。
4. **新規プレイヤーが最初につまずく一点（first wall）**を特定する（プレイテストのメモ、設計書、離脱の多い場面、Owner の言葉）。チュートリアルの後半はそこを越えさせるためにある。

### 2. 設計する

`references/tutorial-design.md` に移動方式別の型と段取りがある。

**ステージ**（既定の並び。ゲームに合わせて名前と中身を変えてよいが、basics は外さない）:

- `welcome` — 何のゲームかを一言、ゴールを一言。長い読み物にしない。
- `basics` — **基本操作。必ず入れる**。そのゲームの移動方式で「動く」→（使うなら）カメラ・ジャンプ→ゲームの主要アクション。1 ステップ 1 操作、やって覚える。成功は操作の検出で判定する（OK ボタンではない）。文言は端末ごとに実際の割り当てから。
- `core` — ゲームの中心の動詞を、失敗しても痛くない場で。
- `first_success` — first wall を越える最初の成功（最初の撃破、最初のチェックポイント、最初の納品）。**サーバーが検出**する。
- `complete` — 本編への受け渡し（ロビー、最初の試合、次の目標）。ここに入った時点で完了を記録する。

全体で 2〜4 分、基本操作は 1 分前後が目安。どのステップ・ステージにも時間切れの救済を付け、誰も詰まらないようにする（`Config.validate` が確かめる）。

**初回ログインだけ・テスターは毎回**（`references/first-login-and-testers.md`）:

- 初回の判定は専用の記録 DataStore（`<prefix>_<env>_tutorial_v1`、キー `u:<UserId>`）。`MAX_STARTS = 1`。開始は**見せる前（送り出す前）に数える**ので、途中でやめても次のログインでは出ない。返却は確実に届かなかったときだけ（送信が例外、TeleportInitFailed、何も見せる前に退出）。応答の無い送信は返却しない（届くかもしれない）。
- 壊れた記録は初回扱いしない（そのログインは出さず、ログに残す）。読み書きの失敗でゲームを止めない（何も数えていないので次のログインでまた試す）。
- **ログイン = 体験の外からの参加**（`JoinData.SourcePlaceId` が自分の Place でない）。試合からロビーへ戻る・別サーバーへの移動はログインではない。テスターにも効く（ロビーとチュートリアルの往復ループを防ぐ）。
- 既存プレイヤー: プロフィールに「遊んだことがある」の印（試合数など）があれば `isExperienced` に渡し、記録を読まずに外す。チュートリアル導入前からいる人に出さないため。
- **テスター**: 環境別の UserId 一覧（`Config.TESTER_USER_IDS.studio / staging / production`）。一覧の人は**毎ログイン**出る。記録は読みも書きもしないので、何度でも初回として確かめられる。ユーザーが UserId を指定したら、指定の環境に入れる（環境の指定が無ければ studio と staging に入れ、production は確認してから）。数値以外・小数・0 以下は無視される。UserId はプロフィール URL `roblox.com/users/<数字>/profile` の数字（Owner に聞かれたらこれを案内）。
- 毎回表示のための一時フラグは作らない。既存の「常に表示」フラグはテスター一覧へ置き換える。

**どこで動かすか**: 単一 Place のゲームやロビーの一角で済むなら同じサーバー（`examples/`）。ロビーと試合が別 Place、NPC 相手や専用の場が要る、他プレイヤーから隔離したいなら専用 Place（ロビーに `TutorialRouting`、チュートリアル Place に到着ガードと `TutorialFlow`、完了の記録、ロビーへの帰還）。

**文言と UI**（`references/ui-and-text.md`）:

- 文言は**そのゲームのソース言語**（文脈シートから。翻訳はゲームのローカライズの仕組みに乗せる）。短く、操作名は HUD と同じ呼び方。キー名は `{key:W}` で書けば配列（AZERTY など）に合わせて表示される。
- UI は**ゲーム自身の部品・書体・色・安全域**で作る。汎用のカードを新しく作らない。HUD のパネルやボタンの作り方をそのまま使い、モチーフの翻訳が要るなら roblox-ui-designer を併用する。
- キーボード・ゲームパッド・タッチの 3 つ全部の文言を用意し、最後に使った入力で切り替える。タッチの親指スティック・ジャンプボタン・Roblox のトップバーを UI で隠さない。

### 3. 実装する

1. テンプレートをゲームの共有フォルダ（例: ReplicatedStorage の共有モジュール）へコピーする。既存の名前と衝突しないか確かめる。テストもコピーし、`ROOT` をゲームのコピーへ向ける。
2. `TutorialConfig` を文脈シートから書き換える: `STORE_PREFIX`、`TESTER_USER_IDS`、`STAGES`、`BASICS`（`detect` は既定操作なら `move_*`/`jump`、独自の操作ならゲームの入力モジュールのアクション名。`hold`/`count`、`title`/`text`/`prompt` はソース言語で）、フォールバックの秒数。
3. サーバー: `examples/TutorialServer.example.server.luau` を土台に、ゲームの環境判定、記録ストア（Studio はメモリ）、`Gate`（テスター、自分の PlaceId 一覧、`isExperienced`）、`Flow`、RemoteEvent、属性での状態の複製、完了 → `gate:complete`、PlayerRemoving を配線する。`core` と `first_success` は**ゲームの既存のイベントにフックして** `flow:serverEvent` を呼ぶ（クライアントの申告で進めない）。
4. クライアント: `TutorialGuideController` に `sample`（ゲームの移動方式での入力。独自の移動なら入力モジュールの押下状態を `actions` に）、`view`（ゲームの UI 部品で作った 4 つの関数）、`keyString`、`report` を渡す。
5. 新しい RemoteEvent は `TutorialFlow:report` が段階・ステップ・時間・頻度を検証する。プロジェクトに exploit レビューの手順があれば通す。報酬を付けるなら、完了の記録と同じ判定で一度だけ、ゲームの既存の付与経路で。
6. 既存の「毎回表示」系のフラグや古いチュートリアルは、削除するかこの方式へ移す。残すなら役割の違いを書く。

### 4. 検証する

`references/verification.md` の順に:

1. Lune: コピーしたテンプレートテストを全ケース合格させる（初回のみ・テスター・返却・段階管理の契約）。ゲームの設定で `Config.validate()` が true。ゲーム固有のテスト（ステージの順、サーバー検出、受け渡し）。
2. Studio Play（roblox-dev-skill の手順で）: 自分の UserId を `studio` のテスターに入れて **2 回 Play → 2 回とも出る**。テスターから外し、メモリストアに完了済みの記録を入れて Play → 出ない。各ステップを実際の入力（キーボード、Device Simulator のタッチ、あればゲームパッド）で進める。何もしない → 救済で進む。完了 → 記録に completedAt。スクリーンショットで UI が HUD に馴染むか、安全域を隠していないか。
3. DataStore とテレポートの本物は公開されたゲームでしか確かめられない。staging で確かめ（publish-roblox-private-staging）、Studio の結果を「本番で動く」と報告しない。

### 5. 報告する

文脈シートの要約（何を読み、何をチュートリアルに採ったか）、ステージ構成、変えたファイル、検証の結果（テスト数、Studio で入力したこと、スクリーンショット）、未検証のこと、Owner の作業（テスター UserId と環境、チュートリアル Place の作成と PlaceId、公開、RTBF の削除対象に記録ストアを加える）。

## 品質基準

- 基本操作のステージがあり、そのゲームの実際の移動方式と割り当てを、端末 3 種それぞれの言葉で教えている。
- 各ステップは操作の検出で進む。読むだけ・OK を押すだけのステップは welcome と complete 以外に無い。
- コア/初成功が文脈シートの first wall につながっていて、初成功はサーバーが検出する。
- 初回ログインだけに一度出る: 開始は見せる前に数え、確実な失敗だけ返し、壊れた記録・読み書き失敗・試合からの帰還では出さない。
- テスターは毎ログイン出て、記録は読み書きしない。テスター一覧は環境別で、production は Owner の指示があるときだけ。
- どのステップ・ステージも時間切れで先へ進む。誰も詰まらない、閉じ込められない。
- 文言はゲームのソース言語で、HUD と同じ操作名。UI はゲームの部品と安全域でできている。
- テンプレートの契約テストが全部通り、Studio で実際に入力して確かめた。

## よくある失敗

- 文脈を読まずに「WASD で移動、Space でジャンプ」を書いた → 独自の移動（スケート、車、飛行、クリック移動）やスマホで嘘になる。`detect` をゲームの入力モジュールのアクションにし、端末別の `prompt` を割り当てから書く。
- 完了時にだけ記録した → 途中でやめた人に毎回出る。開始を先に数える（`gate:begin`）。
- 送信に応答が無いから開始を返した → 実は届いていて、次のログインで 2 回目が出る。返すのは確実な失敗だけ。
- 試合から戻ったロビーで毎回判定した → テスターがチュートリアルとロビーを往復し続ける。ログインは `SourcePlaceId` で判定する。
- テスターに `markStarted`/`markCompleted` を書いた → 2 回目から出なくなる。テスターは書かない。
- Studio だけで「初回のみ動作 OK」と報告した → Studio は DataStore もテレポートも本物ではない。staging で確かめる。
- 汎用のダイアログ UI を新しく作った → HUD から浮く。ゲームの UI 部品で作る。
- 文言を英語で書いたが、ゲームのソース言語は日本語だった（または逆）→ 文脈シートの言語に合わせる。
- 「毎回表示」フラグを確認用に足して消し忘れた → 全員に毎回出る。テスター一覧を使う。
