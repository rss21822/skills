# ひな型の生成と配置

統計から実際の 3D を組む工程。

## ひな型（アーキタイプ）の設計

20〜30種で都市が成立する。カテゴリと、その中の形状違いで割る。

| カテゴリ | 例 |
|---|---|
| オフィス | 幕壁の塔／セットバック／低層の基壇／板状 |
| 住宅 | 戸建／集合／団地／タワー |
| 低層 | 店舗／商店街／学校／複合 |
| 産業 | 倉庫（大小）／プラント／サイロ／煙突 |
| タンク | 円筒／球 |
| インフラ | クレーン／桟橋／橋脚／格子塔／配管 |

各ひな型に**バリアント**（寸法や階数の振れ）を数個持たせる。同じ形が並ぶと
一目で人工物と分かる。

ひな型ごとに定義するもの:

- 階数と footprint の範囲
- 形状の様式（幕壁／帯窓／石の基壇／波板…）
- 屋根の種類（陸屋根／パラペット／設備／切妻／ドーム…）
- ゾーンごとの出現重み
- 配色

**配色と様式は共有定義に置くが、都市ごとの見た目は都市側の設定に置く**
（共有側に書くと他都市が巻き添えになる）。

## 生成時の注意

**部品は最初から目的の位置に作る。** 作ってから頂点をまとめて動かすと、
共有された頂点が複数回動いて部品が本体から飛ぶ。`id()` での重複除去も、
ライブラリが頂点ラッパを作り直すと効かない。

**LOD は元が十分小さければ作らない。** 箱に近い形状は簡略化に下限があり、
同じ密度のメッシュが2つできるだけになる。オブジェクト枠を無駄に食う。

**コリジョンは別に作る**（箱か凸包）。表示メッシュをそのまま当てない。

## スケール圧縮

実寸 1:1 では、プレイヤーとの相対感が成立しない。距離を圧縮する。

**圧縮率は位置と建物寸法の両方に、同じだけ掛ける。**

位置だけに掛けると、街区は詰まるのに建物は実寸のままなので、街区に1棟しか
入らない「村の集まり」になる。実測では圧縮の適用を直しただけで
配置数が 2,292 → 23,332 に増えた。

高さだけは別に補正してよい（相対感を優先して +10〜20%）。

掛ける順序と対象を**1か所に集約**し、マニフェストに記録する。後から検算できる
状態を保つ。

## 配置

街区ごとに解く。

1. 街区の**主軸に沿った格子**を作る（街区リズムを出す）
2. 目標の高さと建蔽率から、置くひな型とバリアントを選ぶ
3. 重ならないよう詰める

**ひな型の選択は「設定に書いた寸法範囲」でなく「実際に生成されたメッシュの寸法」で
突き合わせる。** 生成時に丸めや調整が入るので、設定値と実物はずれる。

インスタンスごとのスケール差は**作らない**。バリエーションはひな型の種類で出す。
差を作ると、後段でアトラス化するときに引き伸ばしが起きる。

## セクター分割

エンジンの読み込み単位に合わせて格子に割る。セクターごとに

- オブジェクト数の上限
- 三角形数の上限
- テクスチャ枚数の上限

を持ち、超過したら**設計を畳む**（LOD へ降格、ひな型を減らす）。

**降格は超過したセクターにだけ適用する。** 「LOD 距離」を静的な
「都心からの距離」と読み違えて全域に適用し、351セクター中271を板ポリ化して
都市を消したことがある。読み違えても例外は出ない。

## メモリで落ちる

数万オブジェクトを常駐させると 3D ソフトが落ちる。**未保存のシーンを失う。**

配置解を JSON（正本）に持ち、生成は

```
1セクター生成 → 使う → 破棄
```

を繰り返す。ピークがセクター最大に収まる。落ちても失うのは1セクターぶん。

**重い工程の後は必ず保存する。**

## 橋渡し層のタイムアウト

3D ソフトを外から駆動する場合（ソケット／CLI／プラグイン）、1リクエストの
実行時間に上限があることが多い。数千件を1回で送ると切られる。

**分割して送る。** 実測では 150 件ずつ（約3.5秒）に落ち着いた。300 件では
11.1 秒かかって切られた。

原因の切り分けを急がないこと。私は接続断の原因を purge のコストだと誤認して
調べ回ったが、実測すると 0.01 秒だった。**測ってから直す。**

## リンク複製にする

同じひな型を参照する複製にすると、

- メッシュ編集が全インスタンスに伝わる（UV の張り直しなどを後から一括でできる）
- メモリとファイルサイズが1棟ぶんで済む

後段で見た目を変えるとき、配置をやり直さずに済むかどうかがここで決まる。

## ランドマーク

抽選には乗せず、設定に書いた座標へ直接置く。都市の輪郭を決める1本なので、
確率に委ねない。

**実名・実ロゴ・商標的意匠は使わない。** シルエットを寄せた「もじり」に留め、
id も一般名詞の組み合わせにする（`TOWER_REDWHITE`, `RAINBOW_SPAN` など）。
類型（格子塔、吊橋、給水塔）は一般的な建築語彙であって商標ではない。
