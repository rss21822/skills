# 解析 — 陸海・街区・ゾーン・統計

取得したベクタから、配置に必要な統計を作る。この工程の誤りは
**例外を出さずに配置へ伝播する**ので、不変条件を先に決めておく。

## 陸と海の判定

海岸線から陸域マスクを作る。ここが**最も反転しやすい**。

素朴な方法（「海の方角に種を置いて塗る」）は、島・埋立地・入り組んだ湾で
簡単に裏返る。実測では建物103棟のうち100棟が「海上」と判定された。

**独立した2つの信号で検証する。**

1. **建物は陸に建っている。** 建物の重心が陸と判定される割合を数える。
   これが低ければ反転している
2. **海岸線の巻き方向。** OSM の `natural=coastline` は
   **進行方向の左が陸**と決まっている。線分を等間隔（60m 程度）で標本し、
   法線方向の左右どちらが陸判定かを数える

2つが一致しなければ反転させる。**一致率を数値で出し、閾値で判断する**。

巻き方向の検査は、1本の線につき1回だけ調べると標本が足りない。
**弧長で等間隔に標本する**（長い海岸線からは多く取る）。

## 海岸線が切れる

範囲でクリップすると、閉じた環が座標の継ぎ目で分割されて「開いた線」に見える。
断片だと誤診して取得側を疑いに行くと時間を溶かす。

**クリップ後に再度マージする。** 実測では 40本/開いた2本 → 39本/0本 になった。

## 街区の切り出し

道路網で囲まれた領域が街区。道路をバッファして陸域から引くのが素直。

街区ごとに以下を出す。

| 量 | 用途 |
|---|---|
| 輪郭ポリゴン | 配置の範囲 |
| 主軸の向き | 建物の向きを揃える（街区リズム） |
| 建蔽率 | ゾーン判定の主軸 |
| 建物数・密度 | 補助 |
| 高さの平均・分位 | 配置する高さの目標 |
| 海岸からの距離 | 港湾判定 |

## 街路の向きは円平均で

角度の平均を素朴に取ると、89° と 1° の平均が 45° になる。街路は 0〜90° で
折り返すので、**円平均**（複素平面か倍角）で求める。

グリッド角は都市の印象を大きく左右する。実測でニューヨーク 65.56°、
東京 37.78° と明確に違い、同じコードで両方を捉えられた。

## ゾーン判定 — 建物数を主軸にしない

**これが一番踏みやすい罠。**

OSM は木造密集地を40個の小さな footprint に、CBD を2個の巨大な footprint に描く。
建物数を主軸にすると **CBD が「疎」に分類される**。

**建蔽率と高さを主軸にする。** 建物数は補助にとどめる。

不変条件としてテストに固定できる。

- 建物2棟・建蔽率55%・平均80m → downtown
- 建物40棟・建蔽率50%・平均8m → residential

用途タグ（`landuse=industrial`, `harbour` など）は**観測事実**であって推定ではない。
自動平滑化で覆されないよう固定する（そうしないと港湾に住宅が並ぶ）。

ゾーン名の語彙は閉じる。綴り違いが混ざると配置側が黙って落とす。

## 高さ統計の汚染

高さタグが無い建物に用途別の既定値を入れると、**その既定値が統計を支配する**。
実測では 94.1% が既定値で、結果として低層ひな型が配置の 93% を占めた。

対処:

1. **実測率を都市ごとに測る**（東京 0.9% / ニューヨーク 74.6%）
2. 実測率に応じて、実測平均とゾーン既定値を**混ぜる比率を変える**
3. 分位（p90 など）へ引き寄せて、高い建物が消えないようにする

実測率が高い都市ではそのまま使い、低い都市ではゾーンの典型値へ寄せる。
同じコードで両方を扱えるかが、汎用性の実証になる。

## ヒストグラムは端を丸める

範囲外の値を捨てるヒストグラムは、外れ値を静かに失う。**端のビンに丸める**。
NaN と無限大だけは落とす。

失われる件数を実データで数えてから直すこと。私は「これで N 件助かった」と
言いかけて、実測すると 0 件だった（最大値が上端を超えていなかった）。
**直した効果も測る。**

## 未割当の建物

街区抽出が拾えない建物が必ず残る（実測で 24〜34%）。放置すると
その領域が空になる。全体分布から配置するなどの受け皿を用意し、
**割合をレポートに出す**。見えていない欠損は直せない。
