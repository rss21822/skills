# 剣の 3 連撃アニメーション（R15・ヒットストップ付き）実装報告

（サブエージェントがファイルに書けなかったため、最終メッセージの REPORT 本文を採点用にここへ保存。）

## 1. 作ったもの
既定の Animate を止めずに、その上に剣の 3 連撃を重ねる仕組み。Motor6D.Transform を毎フレーム書き込む方式。関節角はすべて ComboData の数値で決まるので、後で同じ数値から KeyframeSequence を書き出してアップロードできる。

- `ComboData.luau`: 正本。各段・各キーの全関節角（度）、時刻、イージング、当たり判定区間、ヒットストップ秒。`tools/bake_combo.luau` が生成（手で直さない）
- `PoseMath.luau`: イージング、キー補間（CFrame:Lerp）、FK、汎用 2 関節 IK、脚 IK（足を床に固定）、左手を柄に付ける IK
- `ComboPlayer.luau`: Roblox API に依存しない部分。連撃の状態管理、先行入力、ヒットストップで止まるアニメ時計、フェードアウト
- `SwordComboLayer.luau`: Roblox 側の本体。PreSimulation で Animator の値を基準に重み付きで上書き、脚 IK・左手 IK、刃の掃引レイキャスト → ヒット → ヒットストップ、見た目用の剣
- `KeyframeSequenceExport.luau`: アップロード用に KFS を 3 本作る。脚は IK の結果を焼き込み、Hit / ActiveStart / ActiveEnd / Chain マーカー付き。AnimationTrack 用のヒットストップ関数も
- `SwordComboClient.client.luau`: 入力（左クリック / R2 / F）で `layer:press()`
- `tools/ComboAuthoring.luau` + `bake_combo.luau`: 各キーの「剣の握り位置・刃の向き・腰・骨盤」を作画意図として書き、rig-r15.json の FK でオフライン IK して関節角に焼き込む（肘 0〜145°、手首は各軸 ±65°）

動きの中身:
- 1 撃目 袈裟斬り: 0.00〜0.15 s 腰を右へ 30° ひねり骨盤を後ろに残して右肩の上へ振りかぶる → 0.15〜0.20 s 溜め → 0.20〜0.27 s 頭の右上を通って右上から左下へ（0.27 s が当たり）→ 0.27〜0.42 s 左下へ振り抜き骨盤を前へ、少し戻る余韻 → 0.42〜0.64 s 構えへ。左腕は振りかぶりで前へ伸ばし振りで引き込む。
- 2 撃目 横薙ぎ: 1 撃目の左下からそのまま左へ巻き込む（腰 +42°）→ 溜め → 左前を通って水平に右後ろまで（腰 -40°、0.25 s が当たり）。
- 3 撃目 叩きつけ: 0.16 s で左手が柄頭を取り、0.32 s で頭上へ振りかぶって反る → 0.08 s 溜め → 頭の前上を通して振り下ろす → 0.49 s 腰を -28° 屈め骨盤を 0.55 stud 沈めて刃先を地面へ → 反動で少し跳ね、沈んで残心 → 0.80 s 左手を離し 1.08 s で構えへ。
- 首: 上体のひねりの 7 割、前後の傾きの 5 割を打ち消して目線を標的に残す。

## 2. 組み込み方
1. ReplicatedStorage に Folder `SwordCombo` を作り、`src/SwordCombo` の 5 ファイルを同名の ModuleScript として入れる。
2. `SwordComboClient` を StarterPlayerScripts に LocalScript として。
3. Animate は無効化しない。R15 であること。
4. Tool の剣を使う場合は `createSword = false`。刃の向きは「RightHand の -Z」（Roblox 既定の Tool の握りと同じ）。
5. アップロード時はコマンドバーで `require(game.ReplicatedStorage.SwordCombo.KeyframeSequenceExport).buildAll(workspace.Rig)` → ServerStorage に 3 本。
6. 動きを直す時は `outputs/` をカレントに `tools/ComboAuthoring.luau` を編集 → `lune run tools/bake_combo.luau` → `lune run tests/run_tests.luau` → `lune run tools/spec_tables.luau` の出力で SPEC.md の 5 章を差し替え。

## 3. 検証（Lune 0.10.5 の実測値）
**42 passed, 0 failed**（ログは `tests/last_run.txt`）。rig-r15.json の FK を 240 Hz でサンプリング、各段 t=0.25 s で次の入力を入れるフルコンボ、前方 4 stud にダミー標的。

- FK の正しさ: 静止姿勢の足裏 y = -3.2248（期待値 -3.2248）
- 袈裟斬りの軌跡: 振りかぶり頂点の握り位置 (1.00, 1.58, 0.08) = 右肩の上。刃の 60% 点が 0.24→0.34 s で (-3.95, -4.95, -0.42) 動く = 右上→左下、傾き 1.25
- 横薙ぎの軌跡: 刃の 60% 点が X 方向に +5.82 stud（左→右）。振りの間の高さの幅 0.96 stud（傾き 9.4°）
- 叩きつけ: 溜めの頂点で切っ先 y = 2.69（頭頂より上）。当たりで切っ先 (0.44, -3.19, -4.79)。地面 -3.22 に対して埋まりなし
- 重さ（切っ先の最高速、予備動作 / 溜め / 振り）: 1 撃目 99.9 / 7.1 / 325.7、2 撃目 78.9 / 27.1 / 331.8、3 撃目 121.0 / 7.6 / 375.5 stud/s。振りは予備動作の 3.1〜4.2 倍
- ヒット: 3 段とも命中。当たったアニメ時刻 0.263 / 0.238 / 0.458 s（作画上 0.27 / 0.25 / 0.49 s）
- ヒットストップ: 停止中の関節の変化 0.00000°。停止時間 0.0708 / 0.0833 / 0.1417 s（指定 0.07 / 0.08 / 0.14 s）。コンボ全体 ヒットあり 2.433 s / 空振り 2.146 s、差 0.287 s = 停止時間の合計 0.290 s。微振動は最大 1.12°
- つながり: 段の切り替わりの瞬間の関節差 0.011° と 0.003°。1 サンプルだけ飛び出す跳びはレイヤー出力・左腕 IK・脚 IK のいずれも 0 件
- 剣が体を通らない: 刃が頭・胴の範囲に入ったサンプル 0。刃と頭の最短距離 0.97 stud
- 両手持ち: 左手と柄頭のずれ キー上最大 0.034 stud、左手 IK が効いている全フレームで 0.000 stud
- 接地: 足首の誤差 0.0000 stud、足裏の最下点 -3.225（地面と同じ）、膝の最大屈曲 92.2°
- 可動域: 右肘 0〜126.2°。右手首はキー間でもキーの最大値（122.7°）を超えない

テスト中に見つけて直したもの: 振りかぶりが outCubic だと出だしが速すぎた（2.2 倍）→ inOutSine で 3.3 倍。3 撃目で右肘 131° + 手首で帳尻の解 → 複数初期値の探索で解消。頭上で左手が柄に届かない → 左手の向きを刃の軸まわりに回して解消。左手 IK から通常へ切替時に手首が 180° 反転 → 基準の向きと肘の向きを FK 側から取り、切替キー（t=0.80）を追加。骨盤を持ち上げると脚が届かない → 振りかぶりでは沈みを戻すだけ。

## 4. Studio での確認手順（未実施）
1. R15 ダミー（Rig Builder）をスポーンの正面 4 stud に置く。
2. Play: 左クリック 1 回で 1 撃目だけ出て構えに戻り 0.2 s で Animate の待機へ。3 回連打で袈裟斬り → 横薙ぎ → 叩きつけ。歩きながら / ジャンプ中は脚は Animate のまま上半身だけ振る。
3. ダミーに当てると `[SwordCombo] strike N hit ... hitstop 0.070s` が出て一瞬止まる。空振りでは止まらない。3 撃目は何もない所でも地面に当たって止まる。
4. 数値: `SwordComboClient` を Disabled にして `tests/studio/SwordComboVerify.client.luau` を置く。3 秒後に自動で 3 連撃し、各段の開始時刻、ヒット時刻と対象、`hitstop run`（約 0.07 / 0.08 / 0.14 s、その間の手の移動 ≈ 0）、1 フレームあたりの手の最大移動量、終了後の右肩の角度（待機時から数度以内なら Animate に戻っている）を出力。
5. 見た目: 静止中に足が埋まる・浮く・滑るがない、剣が頭や胴を通らない、溜めで一瞬止まって見える、30 fps 相当でも停止時間が変わらない。
6. アップロード版は `buildAll` の KFS を Animation Editor で開いて見た目と `Hit` マーカー位置を確認。

## 5. 制限・注意
- 他のプレイヤーには見えない（Transform の書き込みはそのクライアントだけ、剣もローカル）。マルチでは攻撃開始を RemoteEvent で配って各クライアントで同じレイヤーを再生するか、アップロードした AnimationTrack に移行。当たり判定もクライアント側なのでダメージはサーバーで検証。
- 体格: 関節角は rig-r15.json の寸法に合わせてある。体格の違うアバターでは握り位置が少しずれる（脚と左手は実行時 IK で追従）。
- Animator との合成: 「Animator のアニメーション段階の直後に PreSimulation」という更新順が前提。Animator がその関節を書かなかったフレームは前回の Animator の値で代用。Studio で要確認。
- 振りが速い: 振りの最中は 60 fps で手首が 1 フレーム最大約 89° 回る（Trail 推奨）。当たり判定は前フレームからの掃引レイなので速くてもすり抜けない。
- 手首が誇張寄り（合計最大約 123°）。横薙ぎは完全な水平ではなく傾き 9.4°。
- 3 撃目の左腕は IK の結果なので Euler 値が直感に反する大きさ。キー間の回転差は最大 162.7°（180° 未満で補間は安全）。
- KFS 書き出しは未実行（イージングの意味、CubicV2 への丸め、キー間の左手・足のわずかなずれ）。
- 未対応: モバイルのタップ入力、被弾側ののけぞり（`onHit` で実装する想定）。
