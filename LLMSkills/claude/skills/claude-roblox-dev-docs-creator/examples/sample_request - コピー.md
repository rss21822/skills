Operator-pinned proof verifies both messages before authorization.
3. Mobile mounted controls trigger a Feasibility Gate.
4. Network, persistence, commerce, analytics, performance, assets, Multi-Place, physics, localization, LiveOps, and rights specs plus their machine-readable contracts are required.

Post-P0 D4 requires zero inventory rows before B1.
6. D4 candidate → B0, P0 candidate → post-P0 D4 → B1, then a separate externally verified human D5 approval → B2.
7. D5/B2 only authorizes W0 handoff. The operator-pinned receiver enters `PREPARE → VALIDATE → ADMIT → signed receipt → bootstrap PASS`: external authority monitors before PREPARE process creation, signed PREPARE/prelaunch/postexecution proofs preserve one continuous project/source/temp lock, and VALIDATE retains that lock after package PASS. Presentation/challenge/transcript/statement/capture/PV/run-authorization/admission/signatures and the later receipt/signature are created only at predeclared operator-external absolute paths—never in the locked project or package. The pre-ADMIT admission is expected-only. After the second validator PASS, authority atomically consumes the admission token, launches the worker suspended/pre-entry, observes actual closure equality and zero product effects, and signs the ADMIT execution/worker-ready receipt. Bootstrap verifies it before PASS; the fresh unconsumed short worker-ready capability is atomically consumed only immediately before one scoped first effect.
