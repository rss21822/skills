# SNS 広報ムービー

試合のキャプチャ動画 1 本から、SNS に載せる 30 秒のクリップと各 SNS の投稿下書きを作る。

**納品する動画は必ず CapCut デスクトップで切り出す。**
- ユーザーは、ffmpeg などで作った動画は SNS で AI 生成と誤判定されやすいと考えている。
- CapCut の書き出しは、ユーザーが普段手作業で作る動画と同じメタデータになる。
- ffmpeg は解析と検証のための読み取りにだけ使う。納品物を ffmpeg で作ったり加工したりしない。

## 成果物（1 回の実行 = 1 フォルダ）

置き場所は `<プロジェクトの movie フォルダ>/[DailyPV] <YYYY-MM-DD_HHMMSS>/`（SpinOut は `artifacts/movie/`。例 `artifacts/movie/[DailyPV] 2026-10-13_090000/`）。フォルダは毎回新しく作り、前の回のものは使い回さない。名前の頭の `[DailyPV] `（半角スペースつき）は、movie フォルダにある他の広報動画と見分けるための印。`new_run.py` が付ける。

名前に `[` `]` と空白が入るので、パスは必ず引用符で囲む。PowerShell では `-Path` の代わりに `-LiteralPath` を使う（`[ ]` がワイルドカードとして解釈されるため）。

| ファイル | 内容 |
|---|---|
| `<元の名前>_<mmss>-<mmss>_16x9.mp4` | X・Reddit 用。1920x1080、**30fps**（X の上限が 40fps のため） |
| `<元の名前>_<mmss>-<mmss>_9x16.mp4` | TikTok・YouTube ショート用。1080x1920、元が 60fps なら 60fps。プレイヤー中心の切り抜き（左右の HUD は切れる） |
| `post_x.txt` `post_tiktok.txt` `post_reddit.md` `post_youtube_shorts.md` | 英語の投稿下書き。動画と同じこの実行フォルダに置く。そのまま貼れる形。X は、この本文をサイトにも下書き保存する（動画なし）。Reddit はファイルまで |
| `clip_report.md` | 選んだ区間と理由、書き出しの仕様、検証結果、アップロードの結果、残りの作業 |
| `verify_16x9.json` `verify_9x16.json` | 検証スクリプトの出力 |
| `selection_sheet_00.jpg` | 切り出した 30 秒を 1 秒おきに並べた静止画（見返し用） |

`<元の名前>` は元ファイル名の空白を `_` にしたもの（例: `2026-10-06_16-47-05_0120-0150_16x9.mp4`）。最終的にフォルダに残すのは、この 2 本の動画だけにする。途中で作り直した動画はごみ箱へ移す。

## 手順

### 0. 準備

1. 入力の動画が存在するか確かめ、長さ・fps・解像度を控える。`ffmpeg -i` を使う。ffmpeg の探し方はスクリプト冒頭の `find_ffmpeg` と同じ。
2. `python scripts/new_run.py <プロジェクトのルート>` で実行フォルダを作る。movie フォルダが複数見つかると止まるので、そのときは `--movie-dir` で指定する。
3. ゲームの情報を `references/<ゲーム>.md` から読む（名前・URL・公式アカウント・映像の見方・Owner の決めたこと）。
   - SpinOut は `references/spinout.md`。
   - ファイルが無いゲームなら、リポジトリの README・GDD・公開記録から同じ形で作って追加する。URL など確かめられなかった値はユーザーに聞く。
4. 投稿先の決まりを `references/platforms.md` で読む。

### 1. 最も白熱した 30 秒を選ぶ

ユーザーが開始時刻を指定したら、それを使う（中身を確かめるだけ）。指定が無ければ次の順で選ぶ。

1. `python scripts/heat_scan.py <動画> --json <scratch>/signals.json` で、音の立ち上がりと画面の動きのヒントを取る。BGM やカメラを振っただけでも値が上がるので、これだけで決めない。
2. `python scripts/contact_sheet.py <動画> 0 <終わり> 2 --out-prefix <scratch>/all` で全体を 2 秒おきに並べ、Read で全部見る。試合の始まりと終わり（イントロの俯瞰、リザルト）を確かめる。
3. 候補の区間を 1 秒おき、山場を 0.5 秒おきで見直して決める。

見る人は最初の数秒で離れる。だから、すぐに何かが起き、途中に山場があり、決着が見える区間が強い。

- **選ぶ場面:**
  - 画面に敵が複数いて、接触やスピンの応酬がある
  - KO・リングアウト・カウンターなどの決着の表示や、残機の変化がある
  - 冒頭にロックオンや場外ぎりぎりなどの「危ない」予兆がある
- **開始位置:** 山場が 8〜20 秒目あたりに来て、冒頭 3 秒以内に動きがあるようにずらす。開始は整数秒にする（CapCut で正確に合わせやすい）。
- **避ける場面:**
  - 試合前の俯瞰・待機・メニュー・リザルト
  - 1 人で滑っているだけの長い区間
  - 画面の大半が UI の場面
  - 映ってほしくない個人情報（チャット欄の他人の名前など）が大きく出る場面

選んだ区間と、何秒目に何が起きるかを `clip_report.md` に書く。迷った候補も 1 行ずつ残す（次回の参考になる）。ゲーム固有の見分け方は `references/spinout.md`。

### 2. CapCut で 16:9 を切り出して書き出す

`references/capcut-desktop.md` を読んでから操作する。要点:

- **許可は 2 つ要る:** 「CapCut」（ランチャー）と `capcut.exe`（`Apps\<版>\CapCut.exe`、編集画面の本体）。
  - 2 つ目は「同じものを 2 回聞かれた」と思われて拒否されやすい。`reason` に「CapCut の編集画面の本体」と書く。
  - 拒否されたら、AskUserQuestion で理由を説明し、もう一度出してよいか聞く。
- **切り出し:**
  1. 新規プロジェクトを作り、動画を読み込んでタイムラインへ置く。
  2. 定規をクリックして開始の付近へ移り、←/→（1 フレーム）で開始ちょうどに合わせて Ctrl+B。
  3. 終了ちょうどへ移って Ctrl+B。
  4. 前後を Delete し、合計が `00:00:30:00` になったことを確かめる。
- 時刻の表示は小さく、computer-use の zoom では読み違える。`scripts/read_screen.py` で実際の画素のまま撮って読む。
- **書き出し:** 書き出し画面は開くたびに名前とフレームレートが初期値（プロジェクト名、30fps）に戻る。毎回すべての項目を入れて確かめる。
  - 名前、書き出し先 = 実行フォルダ
  - 1080P、Bit rate Higher、H.264、mp4、**30fps**
  - 書き出し後に出る共有パネルは Close（16:9 は共有しない）。

### 3. 検証（16:9）

実行フォルダへ cd し、ファイル名を相対パスで渡す。日本語を含む絶対パスを Git Bash から渡すと、JSON に書かれる名前が文字化けする。

```
python <skill>/scripts/verify_clip.py --source <元> --start <開始秒> --clip <16x9.mp4> --json verify_16x9.json
```

調べること:
- 長さとフレーム数
- 元動画との位置合わせ（音の相互相関と画像の一致）
- 実際のフレームレート
- CapCut のメタデータ（AI 機能のフラグ、C2PA や XMP の有無）

FAIL なら原因を直してから次へ進む（切り位置のずれなら CapCut で直して書き出し直す）。

`is_use_vc_sing_clone=1` だけが立つのは CapCut の既定値で、AI 機能を使っていない書き出しでも付く。それ以外の AI 系のフラグが 1 なら、CapCut の AI 機能が使われた印。アップロードせずにユーザーへ報告する。

`python scripts/contact_sheet.py <16x9.mp4> 0 30 1 --out-prefix <実行フォルダ>/selection_sheet` で見返し用の静止画を作り、狙った山場が入っているか目で確かめる。

### 3b. いったん止めて、ユーザーの「OK」を待つ

30 秒の動画（16:9 版）ができて検証が済んだら、作業を止める。Owner の指定（2026-10-13）。下書き・X の保存・9:16 版・アップロードは、ユーザーが「OK」と返すまで始めない。

- チャットで次を伝えて、ターンを終える:
  - 16:9 版のパス（ユーザーが開いて見られるように）と `selection_sheet_00.jpg`
  - 選んだ区間（元の何分何秒から何秒まで）と、何秒目に何が起きるか
  - 検証の結果
  - 「確認して OK なら返信して。区間を変えるなら開始時刻を教えて」
- CapCut は閉じずに、プロジェクトを開いたままにする（OK のあと、同じプロジェクトで 9:16 版を作る）。
- 返信に応じて動く:
  - 「OK」（またはそれに当たる返事）: 手順 4 から続ける。
  - 区間の変更: 手順 2〜3 をやり直し、作り直す前の動画はごみ箱へ移して、もう一度ここで止まる。
  - やめる: 手順 7 の後片付けをして終える。
- この「OK」は、下書きの作成を始めてよいという意味だけ。TikTok・YouTube へのアップロードと X の下書きの保存は、これまでどおり手順 5 で確認を取る。

### 4. 投稿下書きを書く（英語）

`references/platforms.md` の型と上限に従って、4 つのファイルを書く。

**置き場所:** 下書きのファイルは、今回の動画と同じ実行フォルダ（movie フォルダの中の、手順 0 で作った日時の名前のフォルダ。例 `artifacts/movie/[DailyPV] 2026-10-13_090000/`）に保存する。movie フォルダの直下や別の場所には置かない。動画と下書きが 1 つのフォルダにそろっていれば、ユーザーはそのフォルダだけを見て投稿できる。

- `post_x.txt`
- `post_reddit.md`
- `post_tiktok.txt`
- `post_youtube_shorts.md`

**固定の紹介文:** `references/<ゲーム>.md` に「固定の紹介文」があれば、4 本すべてに、その文をそのまま 1 回入れる。Reddit は、サブレディットごとの案のすべての本文に入れる。
- SpinOut の場合は `SpinOut! is an ice-skating fighting game where players battle like human Beyblades!`（Owner の指定、2026-10-12）。
- 言い換え・短縮・翻訳をしない。文字数が足りないときは、紹介文ではなく他の部分（クリップの一言、補足、ハッシュタグ）を削る。
- 書いたら、各ファイルに入っているか数えて確かめる。`grep -cF '<固定の紹介文>' post_*` の結果が、X・TikTok・YouTube は 1、Reddit は案の数になること。

**X は本文だけの下書きをサイトに保存するところまで行う。Reddit はファイルまで（ツールから reddit.com を開けないため）。** 動画の添付と投稿はしない。
- 理由（2026-10-12 に確かめた結果）:
  - ブラウザ操作ツールの添付は 10 MB まで。16:9 版（約 48 MB）は付けられない。
  - X は、本文だけの下書きを保存できた。Reddit は、ツールから開けなかった。
- 投稿はユーザーが行う。下書きを開き、同じ実行フォルダの 16:9 版を添付して投稿する。

### 4b. X に本文だけの下書きを保存する

外部サービスへの書き込みなので、手順 5 の確認に「X に本文だけの下書きを保存する（投稿はしない）」を含めて聞く。

使うのはユーザーの Chrome（サインイン済み、Claude in Chrome のツール）。自分で開いたタブは、終わったら閉じる。

- **X:**
  1. `https://x.com/compose/post` を開く。左下のアカウントが公式アカウント（SpinOut は @roblox_spinout）であることを確かめる。
  2. 本文の欄をクリックして、`post_x.txt` の本文（notes より上）を入れる。
     - 改行は `Return` キーで入れる。`type` の文字列に改行を入れても入らない。
     - 入れたら、ページの欄の文字（`[data-testid=tweetTextarea_0]`）を読んで確かめる。固定の紹介文が欠けずに入っているかも見る。
  3. 作成画面の × を押し、「Save post?」で「Save」を押す。
  4. 下書き（Unsent posts → Drafts）に出ているか確かめる。
- **Reddit:** ツールでは開けない。下書きの保存はユーザーに頼む。
  - Claude in Chrome は reddit.com を「This site is not allowed due to safety restrictions」で拒否する（2026-10-12）。アプリ内のブラウザも reddit.com を開けない。
  - 迂回はしない。報告で「Reddit は `post_reddit.md` から手で下書きを作る」と伝える。
- **してはいけないこと:**
  - 動画の添付は試みない。ローカルのサーバーや JavaScript で動画を流し込む工夫もしない。どちらも自動許可の判定で止められる。
  - 投稿ボタン（Post / Submit）は押さない。
- **操作が許可の判定で止められたとき:** 迂回しない。止まった操作と理由をユーザーに伝え、続け方を決めてもらう。
- **記録:** 保存できた下書き（どのサイト、どのサブレディット）と、動画は未添付であることを `clip_report.md` に書く。

### 5. TikTok・YouTube へのアップロードの確認

アップロードは外部への送信なので、実行のたびにチャットで確認を取る。1 回の「はい」で行うのは、そこに書いたアップロードとその後の確認だけ。確認の文面には次を並べる:

- アップロードするファイル（9:16 版のパス）
- 送り先とアカウント（CapCut の共有パネルでサインインしているもの）
- 公開範囲: TikTok は Only me（Private）、YouTube は非公開。公開（Public）にはしない。
- キャプション・タイトル・説明（`post_tiktok.txt` と `post_youtube_shorts.md` の内容。固定の紹介文が入っていること）
- Owner の決めた設定（`references/<ゲーム>.md`）。SpinOut の場合:
  - TikTok の宣伝の開示: オフ
  - YouTube の子ども向け: いいえ
  - AI の使用: いいえ
- アップロード後に、ユーザーの Chrome（サインイン済み）で TikTok Studio と YouTube Studio を開いて結果を確かめること。YouTube は、そこで子ども向けの回答と AI の使用も設定する。
- BGM の権利が未確認であること
- X に本文だけの下書きを保存すること（動画は添付しない。投稿はしない）

断られたら、手順 6 の共有パネルは Close して、アップロードはしない。

### 6. 9:16 版を書き出し、確認済みなら非公開でアップロード

1. **書き出し:** `references/capcut-desktop.md` の「9:16 版」に従う。
   - 同じプロジェクトで比率を 9:16 にする。
   - クリップを高さいっぱいまで拡大し（316%）、位置を中央 (0, 0) にする。
   - 名前の末尾を `_9x16` にし、フレームレートは元に合わせて書き出す。
2. **検証:** 書き出しが終わると共有パネルが開く。パネルを開いたまま `verify_clip.py` で 9:16 版を検証する（`--json verify_9x16.json`）。
3. **共有:** PASS で、手順 5 で確認が取れていれば共有する。
   - **共有パネルは 1 回共有すると閉じる。**
     - 先に TikTok へ共有する。
     - 次に、同じ名前・同じ設定でもう一度書き出す。「File already exists」には OK を押して上書きする。
     - 開き直したパネルで YouTube へ共有する。どの書き出しをどちらへ上げたかを `clip_report.md` に書く。
   - **TikTok タブ:**
     - キャプション（固定の紹介文を含めて 150 字以内）を入れ、Visibility Private、開示は Owner の設定どおりにする。
     - 文字数の表示が古いまま変わらないことがあるが、送られるのは欄の文字。
     - Share 後の「Sharing...」の画面で、キャプションと Private を確かめる。
   - **YouTube タブ:** **サインインより前に**全部入れる。
     - 2026-10-12 には、サインインが終わった直後に共有が始まった。タイトルが「unknown」、説明が CapCut の宣伝文のまま、公開で上がった。
     - 入れるもの:
       - Name（タイトル）を入れる。
       - 最初から入っている CapCut の宣伝文（「Invite friends to download CapCut…」）を消して、説明を入れる。
       - 下へスクロールして公開範囲を非公開にする。
       - 「Also share to TikTok」はオフ。
     - 公開範囲の欄が見つからないときは、CapCut からは共有しない。ユーザーの了解を得て、YouTube Studio から非公開で上げる。
   - サインインはユーザーに頼んで待つ（CapCut が Chrome を開く）。パスワードは入力しない。
   - パネルにある自動の「9:16 (TikTok video size)」版は使わない（AI の自動リフレームの可能性がある）。自分で書き出したものを使う。
4. **共有の後:** ユーザーの Chrome で TikTok Studio（`tiktok.com/tiktokstudio/content`）と YouTube Studio を開き、次を確かめる。
   - 公開範囲（TikTok は「自分のみ」）、キャプション・タイトル・説明（固定の紹介文が欠けていないか）、長さ
   - YouTube は次を設定して保存し、再読み込みして確かめる:
     - 子ども向け: Owner の設定
     - AI の使用: いいえ（「詳細設定を表示」の中）
   - **公開になっていたら、すぐ非公開に直してユーザーに報告する。** 詳細ページは子ども向けが未回答だと保存できない。そのときは動画一覧の公開設定の欄から非公開にする。
5. 成功・失敗と画面に出た内容を `clip_report.md` に書く。

### 7. 後片付け

1. 編集画面を右上の × で閉じ、ホームへ戻る。
2. ホームの Projects で今回のプロジェクトを右クリック → Delete → 「Move to Trash?」で OK。
   - CapCut のゴミ箱から 30 日間は戻せる。ユーザーの方針: 作業プロジェクトは残さない。
   - 自分が作ったプロジェクト以外は触らない。
3. ホームを × で閉じて CapCut を終了する。保存するか聞かれたら、必ず「保存しない」（Don't save）を選ぶ。CapCut のプロセスが残っていないか確かめる。
4. 実行フォルダの途中のファイル（作り直す前の動画など）は、ごみ箱へ移す（完全には消さない）。
5. 他のアプリやウィンドウには触れない。

### 8. 報告

`clip_report.md` を仕上げ、チャットで次を伝える:

- 実行フォルダのパス
- 選んだ区間と理由（何秒目に何が起きるか）
- 書き出した 2 本の仕様と検証の結果
- 投稿下書き 4 本のファイル名
- TikTok・YouTube のアップロードの結果と、Studio で確かめた状態（非公開のまま。公開はユーザーが各アプリで行う）
- 予定と違うことが起きたら、その内容と数字（例: 公開されていた間の再生回数）
- X に保存した本文だけの下書き。Reddit はユーザーが `post_reddit.md` から下書きを作ること
- 残りの作業: X と Reddit は、ユーザーが下書きを開き、16:9 版を添付して投稿する。BGM の権利の確認。
- computer-use の文字入力でクリップボードを上書きしたこと

## 上げた後に文面を差し替えるとき

固定の紹介文が変わったときなど、上げた後の文面を直す手順（2026-10-12 に確かめた）。Owner に頼まれたときだけ行い、公開範囲などほかの設定は変えない。

- **ファイル:** 実行フォルダの下書きのファイルを先に直す。X は `x_count.py` で長さを確かめる。notes に、何をいつ変えたかを書く。
- **YouTube:** YouTube Studio の動画の詳細（`studio.youtube.com/video/<ID>/edit`）で説明欄を直して「保存」を押す。再読み込みして、説明と公開範囲（非公開）を確かめる。
- **X の下書き:**
  1. `x.com/compose/post/unsent/drafts` で下書きを開く。
  2. 本文を直す。
  3. × を押し、「Save post?」で Save を押す。Post は押さない。
  4. 下書きが 1 件のままで、本文が新しくなっているか確かめる。
- **TikTok:** TikTok Studio の投稿一覧で鉛筆のボタンを押し、キャプションを直して「保存」を押す。
  - キャプションとカバーの編集は **1 日 1 回、投稿後 7 日以内** だけ。1 回で正しく入れる。
  - 欄の中のハッシュタグは部品になっている。全部を打ち直さず、変える部分だけを選んで打ち替える（打ち直すとハッシュタグとして扱われないおそれがある）。
  - 欄は 4,000 字まで入る。CapCut の 150 字の制限はかからない。
  - 保存すると一覧へ戻る。再読み込みして、キャプション・「自分のみ」・再生数を確かめる。
- **Reddit:** ファイルだけ直す（ツールから開けないため）。
- **一部だけ打ち替えるやり方:** 欄をクリックしてから、置き換える部分を JavaScript で選択し（選択するだけで、中身は書き換えない）、`type` で新しい文を打つ。打ったあと、欄の文字を読んで確かめる。
- 結果を `clip_report.md` に書く。

## 守ること

- 公開（Public）の投稿はしない。X は本文だけの下書きをサイトに保存するところまで、Reddit はファイルまで。動画の添付と投稿ボタンは押さない。X・Reddit への投稿と、TikTok・YouTube の公開への切り替えはユーザーが行う。
- 共有パネルの「Sign in」も送信の引き金になりうる。キャプション・タイトル・説明・公開範囲を全部入れるまで、Sign in も Share も押さない。
- パスワードやコードを入力しない。サインインはユーザーに頼む。
- CapCut の AI 機能（自動リフレーム、AI キャプション、AI 音楽、音声変換、画質向上、背景除去など）を使わない。メタデータに AI のフラグが立ち、SNS で AI 生成の表示が付く原因になる。
- メタデータを消したり書き換えたりしない。確かめるだけにする。
- 元のキャプチャ動画は読み込むだけ。移動・変更・削除をしない。
- 操作するのは CapCut とそのダイアログ、確認の済んだ Studio のページだけ。
- 画面の取り込み（`read_screen.py`）は、スクリーンショットで CapCut が最前面にあることを見て、範囲が CapCut の中にあるときだけ行う。

## よくある失敗

- **2 つ目の許可（`capcut.exe`）が無い:** スクリーンショットで CapCut が隠れている。許可を取り直す。
- **「Textinputhost is in front」で操作できない:** Windows の入力補助の透明なウィンドウが前面を握っている。
  - textinputhost の許可は求めない。
  - ユーザーに CapCut のウィンドウを 1 回クリックしてもらい、そのあと CapCut の中をクリックしてから続ける。
- **書き出しの名前とフレームレートが初期値のまま:** 書き出し画面は開くたびにプロジェクト名と 30fps に戻る。書き出し先は前回の場所を覚えている。毎回、全部を確かめる。
- **16:9 を 60fps で書き出す:** X の上限（40fps）を超える。16:9 は 30fps にする。
- **9:16 で拡大せずに書き出す:** 小さな横長の映像に、上下の黒帯が付く。プレビューで縦いっぱいになっているのを確かめてから書き出す。
- **数値の欄に `type` で数字を入れる:** 日本語 IME が入力を横取りして入らない。拡大率はスライダーと ▲▼ で合わせる（capcut-desktop.md）。
- **固定の紹介文を言い換える・入れ忘れる:** Owner が決めた文なので、一字も変えずに全投稿へ入れる。TikTok の 150 字に収まらないときは、紹介文ではなく他の部分を削る。
- **YouTube の説明に CapCut の宣伝文が残る:** 説明欄には最初から CapCut の招待文が入っている。必ず消してから入れる。
- **YouTube のサインイン直後に共有が始まる:** 入力の前にサインインした。手順 6 の順番を守る。
- **2 つ目の SNS へ共有しようとしたらパネルが無い:** パネルは 1 回の共有で閉じる。同じ設定で書き出し直す。
- **書き出し直後の共有パネルで、確認の前に Share を押す:** 確認前のアップロードになる。確認が取れていなければ Close だけ。
- **`verify_clip.py --json` の後ろにパスを書き忘れる:** 引数エラーで止まる。`--json <出力先>` と書く。
