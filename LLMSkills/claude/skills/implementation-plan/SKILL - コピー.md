# 実装計画作成スキル

ユーザーが「実装計画作成」を含むメッセージを送ってきたとき、コードベースを調査・分析し、実装計画書を作成する。
**この段階ではソースコードの修正は絶対に行わない。** 計画の作成と提示のみがゴール。

## 手順

### 1. 要件の把握

ユーザーのメッセージから以下を読み取る:
- 何を実装したいのか（機能、修正、リファクタリング等）
- 制約や要望（技術スタック、パフォーマンス要件など）
- スコープ（どこまでやるか）

不明確な点があれば、計画作成前にユーザーに質問して確認する。

### 2. コードベースの調査

Explore エージェントや Grep / Glob / Read ツールを使い、関連するコードを徹底的に調査する:
- 既存のアーキテクチャとディレクトリ構造
- 変更が必要なファイルと影響範囲
- 既存のテスト、CI/CD設定
- 依存関係やインターフェース

また、プロジェクトルートに `CLAUDE.md` が存在するか確認し、パスを控えておく（後のレビューで参照するため）。

### 3. 実装計画書の作成

調査結果をもとに、以下の構成で実装計画書をMarkdownファイルとして作成する。
ファイルの保存先はプロジェクトルート直下の `plans/` ディレクトリとする（なければ作成する）。
ファイル名は内容に応じた分かりやすい名前にする（例: `plans/add-user-auth.md`）。

```markdown
# 実装計画: [タイトル]

## 概要
[何を実装するかの1-2文の要約]

## 背景・目的
[なぜこの実装が必要かの説明]

## 現状分析
[関連する既存コードの構造、現在の動作の説明]

## 実装方針
[アーキテクチャレベルの方針、採用する設計パターン等]

## 実装ステップ

### ステップ1: [タイトル]
- 対象ファイル: `path/to/file`
- 変更内容: [具体的に何をするか]
- 理由: [なぜこの変更が必要か]

### ステップ2: [タイトル]
...

## 影響範囲
[変更による影響を受けるモジュール・機能の一覧]

## テスト計画
[どのようなテストを追加・修正するか]

## リスクと注意点
[実装上のリスク、注意すべき点、代替案の検討]

## 見積もり
[各ステップの相対的な規模感]
```

### 4. codex によるレビュー（初回）

計画書を保存したら、codex コマンドでレビューを依頼する。
CLAUDE.md のパスは実際のプロジェクト内のパス（フルパス）を使うこと。
CLAUDE.md が存在しない場合は `(ref: ...)` 部分を省略する。

```bash
codex exec -m gpt-5.4-codex "このプランをレビューして。瑣末な点へのクリップはしないで。致命的な点だけ指摘して: {plan_full_path} (ref: {CLAUDE.md_full_path})"
```

- `{plan_full_path}` → 計画書ファイルの絶対パス
- `{CLAUDE.md_full_path}` → プロジェクトの CLAUDE.md の絶対パス

### 5. レビュー結果の反映

codex のレビュー結果を確認する:

- **致命的な指摘がない場合** → ステップ6へ進む
- **致命的な指摘がある場合** → 計画書を修正し、修正版のレビューを依頼する:

```bash
codex exec resume --last -m gpt-5.3-codex "プランを更新したからレビューして。瑣末な点へのクリップはしないで。致命的な点だけ指摘して: {plan_full_path} (ref: {CLAUDE.md_full_path})"
```

`resume --last` を必ずつけること。これにより初回レビューの文脈が引き継がれる。

このレビュー→修正のサイクルは、致命的な指摘がなくなるまで繰り返す（ただし最大3回まで）。

### 6. ユーザーへの提示

レビューを通過した最終版の計画をユーザーに提示する:

1. 計画書のファイルパスを伝える
2. 計画の要点をチャット上でも簡潔にサマリーとして提示する
3. codex レビューで指摘された点と、それに対する修正内容があれば併記する
4. ユーザーに計画内容のフィードバックを求める

## 重要な注意事項

- **ソースコードを修正してはいけない。** このスキルの範囲は計画書の作成のみ。
- codex レビューは必ず計画をユーザーに見せる前に実施する。レビューなしで計画を提示しないこと。
- 計画書は必ずファイルとして保存する（codex がファイルパスで参照するため）。
- `resume --last` は2回目以降のレビューでのみ使用する。初回レビューには使わない。
