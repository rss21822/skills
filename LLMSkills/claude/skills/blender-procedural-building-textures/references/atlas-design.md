# アトラスの設計 — 測って配る

直感で区画を切ると必ず外れる。実測の手順と、最適化の回し方。

## 1. 面を数える

対象メッシュを走査し、面ごとに分類する。

```python
# 疑似コード。Blender なら bpy、他エンジンでも同じ考え方
for mesh in meshes:
    for face in mesh.polygons:
        n = face.normal
        if abs(n.z) >= 0.5:
            roof_faces += 1            # 上下向き
            continue
        # 壁: 面の水平方向に沿った幅と、高さを採る
        axis = normalize((-n.y, n.x, 0))
        width  = max(proj) - min(proj)   # proj = 各頂点を axis に射影
        height = max(z) - min(z)
        if width < MIN_W or height < MIN_H:
            trim_faces += 1            # バルコニー帯・看板の側面・リブ
            continue
        wall_faces.append((width, height, category_of(mesh)))
```

実プロジェクトでの結果（90アーキタイプ）:

| 種別 | 面数 | 割合 |
|---|--:|--:|
| 屋根（上下向き） | 9,573 | 52% |
| トリム（小面） | 4,762 | 26% |
| ファサード（壁） | 4,683 | 26% |

**壁面 2,770 枚のうち 56% は小面だった。** バルコニーの帯、看板の側面、リブ。
これらにファサードを貼ると、幅2mの帯に窓が丸ごと1枚入る。無地のトリム区画へ
逃がす。

屋根が半分を占めるという事実は、面積配分を決定的に変える。初版は屋根に
256×256 しか与えていなかった。

## 2. 壁面の寸法分布を採る

カテゴリごとに、幅と高さの分位点を出す。単位は「ベイ」「階」に正規化しておくと
区画の設計にそのまま使える（1ベイ = 窓の間隔、1階 = 階高）。

実プロジェクトの値:

| カテゴリ | 面数 | ベイ p15/中央/p85/最大 | 階 p15/中央/p85/最大 |
|---|--:|---|---|
| office | 204 | 0.8 / 7.7 / 11.8 / 18.3 | 0.7 / 8.0 / 12.7 / 13.7 |
| residential | 342 | 1.8 / 6.3 / 12.1 / 18.3 | 0.6 / 1.2 / 6.0 / 36.0 |
| lowrise | 66 | 1.6 / 4.5 / 10.9 / 13.9 | 1.0 / 2.0 / 4.0 / 5.0 |
| industrial | 604 | 0.6 / 0.9 / 17.4 / 29.8 | 0.9 / 3.4 / 7.9 / 17.7 |

**幅と高さは独立ではない。** 分位点を別々に振った合成格子で評価すると
「幅50m・高さ2.2mのオフィス壁」のような実在しない面まで採点してしまう。
評価には**実測したペア**を使う。

## 3. 区画の寸法を最適化する

各区画が「何ベイ × 何階」を描くかを決める。面はこのうち最も近い区画に
割り当てられるので、比のずれが小さいほどよい。

**線形距離ではなく対数距離を使う。** 線形だと (30ベイ vs 18ベイ) の差が
(2ベイ vs 1ベイ) の差を圧倒する。見た目に効くのは比。

```python
def error(bays, floors, panel):
    pb, pf = panel
    return max(abs(log(bays / pb)), abs(log(floors / pf)))
```

6区画を選ぶ手順:

1. 候補集合（ベイ 1〜30、階 1〜36 の格子）を用意する
2. 貪欲法: 「平均二乗誤差を最も減らす区画」を1つずつ6個まで足す
3. 局所改善: 各区画を候補と入れ替えて、改善するなら採用。改善が止まるまで

実測 1,216 面に対する結果:

| | 手で決めた値 | 最適化後 |
|---|--:|--:|
| 最悪の比のずれ | 8.9倍 | **2.4倍** |
| p95 | — | 1.5〜2.0倍 |

手で決めた版では、industrial の 29.8ベイ × 0.9階（桟橋の腰壁）に (30,8) が
当たり、高さ3mの壁に窓が8段詰まっていた。

## 4. 区画をセルに割り当てる

区画の**寸法**（何ベイ×何階）と、それを描く**セルの大きさ**（何ピクセル）は別物。
使用頻度の高い区画に大きいセルを与える。

ただし解像度には頭打ちがある。**64 px/ベイ・64 px/階を超えると視認できない**ので、
それ以上は他へ回す。目的関数:

```
Σ over panels:  使用面数 × [ min(1, セル幅/ベイ数 / 64) + min(1, セル高/階数 / 64) ]
```

6区画の割り当ては 6! = 720 通りしかないので総当たりでよい。

実プロジェクトの結果（目標解像度の充足率＝この目標に届いた面の割合）:

| カテゴリ | 充足率 |
|---|--:|
| lowrise | 94% |
| residential | 85% |
| industrial | 73% |
| office | 63% |

office が低いのは面そのものが大きい（12ベイ×10階）ため。512px の区画では
構造的にこれ以上出ない。**上限に張り付いている理由が説明できる状態**にしておく。

## 5. 敷き詰めの検査

区画は重なっても隙間があっても静かに壊れる（重なれば片方の絵が消え、
隙間には黒が写る）。面積の合計が合っていても重なりは起こりうるので、
**画素単位で二重占有と未占有を数える**。

```python
grid = [[0] * (size // 32) for _ in range(size // 32)]
for x, y, w, h in rects.values():
    for gy in range(y // 32, (y + h) // 32):
        for gx in range(x // 32, (x + w) // 32):
            grid[gy][gx] += 1
assert max(flat) == 1 and min(flat) == 1
```

回転・反転を使う区画（絵柄の反復を崩すため）は**正方形でなければならない**。
矩形を90°回すと縦横比が壊れる。これも検査に入れる。

## 6. 絵柄の反復を崩す

同じ区画を全員が引くと、屋上の設備配置まで街じゅうで一致する。
**面ごとに区画内で反転・回転させる。** 画像は増えない。

- 壁: 左右反転のみ。上下を返すと1階が空に行く、90°回すと窓が倒れる
- 屋根・トリム: 正方形なので8通り（90°回転 × 反転）全部使える

乱数は**メッシュ名と面番号から決定論的に**引く。`str.hash` はプロセス毎に
変わるので使わない。

```python
def name_seed(name):
    return sum((i + 1) * ord(c) for i, c in enumerate(name)) & 0x7FFFFFFF

def fhash(base, i):
    h = (base * 1103515245 + i * 12345 + 7919) & 0x7FFFFFFF
    return (h ^ (h >> 13)) & 0x7FFFFFFF
```

## 7. UV を区画へ焼く

面ごとに、行き先の区画を決めて 0〜1 に収める。

```python
u0, v0, uw, vh = normalized_rect[panel_key]
s = clamp01((proj - proj_min) / (proj_max - proj_min))
t = clamp01((z - z_min) / (z_max - z_min))
if flip_a: s = 1 - s
if flip_b: t = 1 - t          # 屋根・トリムのみ
if swap:   s, t = t, s        # 正方形の区画のみ
uv = (u0 + uw * s, v0 + vh * t)
```

構成上 UV は必ず 0〜1 に入るが、**それでも機械的に検査する**。
テクスチャを持たないメッシュ（コリジョン殻など）に古い UV が残っていると
検査が赤くなるので、そちらは UV レイヤーごと落とす。

## 8. 元メッシュを編集すれば全インスタンスに伝わる

インスタンス（リンク複製）で街を組んでいるなら、**元メッシュの UV を編集する
だけで全インスタンスに伝播する**。配置解を再実行する必要はない。

前提として、インスタンスごとのスケール差が無い（あるいは小さい）こと。
実プロジェクトでは 8,839 体すべてが同一スケールだったので、アトラス方式の
最大の弱点である引き伸ばしが構造的に発生しなかった。**適用前に確認する。**
