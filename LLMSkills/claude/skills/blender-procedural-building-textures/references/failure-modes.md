# 静かに壊れる型

すべて実プロジェクトで踏んだもの。**例外を出さず、ログも正常に見え、
結果だけが間違う。** 同じ場所を踏まないための一覧。

---

## 同一性を可変な名前から引く

**症状** 住宅のメッシュに店舗のテクスチャが乗る。集計も「lowrise 276 / residential 25」と
実態と逆に出る。

**原因** カテゴリをマテリアル名から引いていた。最適化パスが
「基本色が同じマテリアルは同一とみなして統合する」ため、
`RESIDENTIAL_MANSION` のメッシュが `MAT_LOWRISE_SHOP` を指す状態が普通に起きる。

**核心** その最適化の docstring には前提が書いてあった ——
「テクスチャが無い今は色だけが差なので、色が一致するものは共有してよい」。
**テクスチャ導入がその前提を壊した。**

**対処**
1. 同一性は**安定した識別子**（メッシュ名・アセットID）から引く
2. 統合の鍵に参照画像を含める（画像が違えば畳まない）
3. 「適用したマテリアル」と「アセット同一性」の一致を機械的に数える検査を足す

**一般化** 既存コードの docstring が書いている**前提**を、自分の変更が
壊していないか確かめる。最適化は「今は差が無い」という仮定の上に建っていることが多い。

## `split(prefix)` で接頭辞を落とす

**症状** 予算監査が、テクスチャを当てた9セクターを「0枚」と数えていた。
**予算違反があっても見えない**状態。

**原因** `"MATTEX_OFFICE_MID".split("MAT_", 1)` は分割されない。
文字列に部分列 `"MAT_"` が含まれていないため（`MAT` の次が `T` であって `_` ではない）。
接頭辞除去のつもりが素通りしていた。

**対処** 接頭辞は長い順に `startswith` + スライスで明示的に剥がす。

```python
for prefix in ("MATTEX_", "MAT_"):    # 長いほうを先に
    if name.startswith(prefix):
        name = name[len(prefix):]
        break
```

## 1枚の画像に複数種の絵があるのに、マテリアルで色を掛ける

**症状** 壁をレンガ色に指定したら、屋上まで赤茶になった。

**原因** アトラスは壁も屋根も1枚に持つ。マテリアル側の乗算はメッシュ全体に効く。

**対処** 基調色は**生成時点で区画ごとに焼く**。マテリアル側の乗算は
1.0 のまわりで振る微差だけに使う。

**派生** 暗い配色で屋根が黒く潰れるのを避けるため乗算値に下駄を履かせると、
今度は彩度が失われる（レンガを指定しても淡いピンクにしかならない）。
焼く方式にすれば下駄自体が不要になる。

## 再着色の基準を「全体の平均」にする

**症状** 鈍いレンガ色（`#8c4a3a`）を指定したのに、鮮やかなオレンジの街になった。

**原因** 区画全体の平均を目標色に合わせていた。窓や目地が暗いので平均が下がり、
壁はその **約1.4倍明るく**出る。

**対処** 輝度の中央値以上の画素を「壁」とみなし、そこを目標色に合わせる。

## `str.hash` を「決定論的な乱数」に使う

**症状** 同じ seed から同じ結果が出ない。屋上の設備配置が実行のたびに動く。

**原因** Python の `str.hash` は PYTHONHASHSEED でプロセス毎に変わる。

**対処** 自前の決定論的ハッシュを使う。テストで固定する。

## 出力先をプロジェクト間で共有する

**症状** （実害前に発見）別対象を処理した瞬間に、前の対象の成果物が消える。

**原因** 対象ごとに変わる成果物を共通のディレクトリに書いていた。

**対処** `out/<対象名>/` のように分ける。

## 一括処理が橋渡し層のタイムアウトを超える

**症状** 接続が切れる、あるいは「クライアントがタイムアウト」で落ちる。

**原因** 8,839 オブジェクトを1リクエストで送っていた。

**対処** 分割する（実例では40セクターずつ、8回）。ホスト側で結果を合算する。

**注意** 原因の切り分けを誤りやすい。実測してから直す —— 一度、
purge のコストだと誤認して調べ回ったが、実測すると 0.01 秒だった。

## プレビューに出荷しない物が写る

**症状** 上空図に規則的な無地の格子が写る。

**原因** ひな型ライブラリ90体が格子状に並んだままシーンに残っていた。
**全体が無彩色のうちは街に紛れて気づけず、以前のプレビュー全てに入っていた。**

**対処** 撮影中だけ隠し、`finally` で必ず戻す。対象はライブラリ、破壊状態、
瓦礫、コリジョン殻など。

**一般化** 「今まで気づかなかった」は「今まで無かった」ではない。
見た目を変えると、それまで紛れていた異物が露呈する。

## 幅で分岐して、1棟が2つの建築になる

**症状** 同じ建物の正面が石造、側面がガラス幕壁になる。

**原因** 面は**寸法**で区画を選ぶ。9階建てでも、幅8ベイの壁と幅20ベイの壁は
別の区画に行く。その2区画に別の様式を割り当てていた。

**対処** オブジェクトごとに一定な量（階数）で分岐する。階数の近い区画には
同じ様式を置く。テストで「階数比が N 倍以内の区画どうしは同じ様式」を検査する。

## 屋根の面に壁の絵が乗る

**症状** 上空から見ると全屋上が「寝かせた外壁」になる。

**原因** 屋根も壁と同じ UV 展開（箱投影）で、同じ画像を引いていた。

**対処** アトラス内に屋根区画を設け、上向きの面をそこへ割り当てる。
別マテリアルで解こうとすると「1メッシュ1マテリアル」に触れるので避ける。

## パッチが一度も当たっていない

**症状** 「patched」と表示されるのに、修正の効果が出ない。

**原因** `str.replace` は一致しなくても例外を出さない。置換対象が変わっていても
黙って元の文字列を返す。

**対処** 不一致で失敗する手段を使う（`Edit` ツール、`assert old in s`）。

## 予算超過をそのままにする

超過したら**設計を畳む**（カテゴリを統合する、面積配分を見直す）。
予算のほうを上げて通さない。上限が仕様として凍結されている場合はなおさら。

実例では5カテゴリが同居するセクターが3つあり上限4を超えていた。
2つのカテゴリを1枚のテクスチャで賄えるよう絵柄を作り直して解決した。

## 数値だけ見て終わらせる

実プロジェクトの不具合9件のうち **4件はレンダを見てしか分からなかった**。

- 屋根に窓が寝そべっている
- 無地の格子（ライブラリ）が写り込んでいる
- 色の彩度が想定と違う
- 非常階段が密すぎて壁が鉄格子になる

いずれも検査は全部緑だった。**最低2枚は撮る**（遠景の全体、真上から）。
プレイヤーの視点が決まっているならその高さからも。
