# 手続き的ポーズレイヤー（Transform を書く描画層）

Animator が関節を動かした後に、Motor6D / AnimationConstraint の `Transform` を書き換えて、接地・補正・overlay・二次運動を
重ねる層。アセットの upload が要らず本番でそのまま動き、体格や地面に合わせられる。
骨組み: `assets/PoseLayerTemplate.luau`、部品: `assets/AvatarPoseKit.luau`。

## 目次

1. タイミング（いつ書くか）
2. フレームの順序
3. 接地（平地・坂・階段・空中・着地）
4. overlay: live の track に重ねる
5. 遷移と速さの上限
6. 二次運動
7. 自機・NPC・他プレイヤー
8. 負荷
9. 実測値（sandbox）

## 1. タイミング

- **`RunService.PreSimulation` で書く**。Animator は PreSimulation より前に Transform を書く。PreSimulation で書いた値がこのフレームに描かれる。
- `PreRender` / `RenderStepped` で書いた Transform は描画にも読み戻しにも反映されない（Studio 実測、Root で確認）。
- `PreAnimation` で前フレームの Animator 出力（`e.base`）へ戻す。どの track も動かしていない関節は Animator が書かないので、
  戻さないと PreSimulation で「自分が前フレームに書いた値」を Animator の出力と読み違え、補正が積み上がる。
- 描画は PreSimulation 時点の HumanoidRootPart で計算され、**その後の物理ステップで root が動いてから**描かれる。
  落下中は `root.AssemblyLinearVelocity.Y * dt` を先に足して予測する（`Kit.floorClearance`）。予測できない動き
  （Humanoid の段差の乗り上げ、強い着地の圧縮 0.2〜0.5 stud）は 1〜2 フレーム残る。

## 2. フレームの順序（PoseLayerTemplate の PreSimulation）

1. **base を読む**: 各関節の `Transform`（= このフレームの Animator 出力）。
2. **モードを決める**: 優先順位つき（全身の上位 track > 空中 > 着地 > 攻撃 > 被弾 > 停止 > 要素 > 旋回 overlay > live）。
   切り替わった瞬間に各関節の位置と角速度（`Kit.jointVelocity`）を覚える。
3. **目標を得る**: モードの関数（純粋関数。Instance に触らない → オフラインで同じ値を検証できる）。
4. **補間**: `Kit.carriedStart(from, velocity, elapsed, fade):Lerp(target, smoothstep)` を `Kit.limitRotation(last, desired, 360°/s·dt)` で制限。
   衝撃系（被弾・着地・スピンの開始・ジャンプ）は予算を外して速く応答させる。
5. **接地**: 下の 3 章。
6. **二次運動**: `Kit.Secondary.settle` → `apply`（6 章）。
7. **最後の安全網**: 接地中は低い方の足を床より下へ入れない（上げるだけ、`Kit.raiseLowest`）。
8. **書く・覚える**: `e.previous = e.last; e.last = pose`。属性（モード名など）は値が変わったときだけ書く。

各段は**前の段が描いた姿勢**を入力にする（目標値ではなく）。補間の途中で膝が沈むと刃が埋まる、といった段差はこれで防ぐ。

## 3. 接地

足の最下点（傾いた足の角まで、`Kit.boxBottom`）を HumanoidRootPart の空間で測る。「床」は定数ではなく
**その体が立ったときの足の高さ**（`Kit.neutralLow`）か、raycast した床の高さ。

- **平地・両足を床に置くモード**（待機・停止・着地・よろけ・構え・スピン）: `Kit.groundLowest`（低い方の足を床へ。上げも下げもする。Root の縦移動だけ）。
- **生の track（Animator だけのフレーム）**: 同じく低い方の足を床へ、ただし接地の重み `plantW`（着地で時定数 60 ms で 1、離地で 0）を掛ける。
  購入済みの track は作者のリグと体の寸法差で最大 0.5 沈み 0.2 浮くので、生の track にも必ず掛ける。
- **坂・階段**: `Kit.floorUnderFeet`（足ごとに**つま先とかかとの 2 本**、**root の高さから**撃つ。高い方の当たりに立つ）→
  `Kit.fitFeetToFloor`（低い方の足を自分の床へ、もう片方は元の持ち上げ量を保ったまま二関節 IK で上げる。骨盤は必要な分だけ下げる）。
  - ray を足のすぐ上から撃つと段の中から始まって当たらず、はるか下の床を拾う（足が 3 stud 浮く誤計測・誤補正になる）。
  - 走りの track は両足が浮く区間（flight）を持つことがある。既定は低い方の足を毎フレーム床へ置く。flight を残すなら `keepFlight = true`。
- **片足だけ動かす**（外脚を床へ届かせる、振り足を床の上へ逃がす）: `Kit.reachFoot`（膝で長さ、股関節の最小の振りで向き、足首で足の向きを保つ。
  伸び切り手前 5% は soft IK で指数的に止め、膝が 1 フレームで伸び切らない）。
- **空中**: `Kit.floorClearance`（真下の床、1 ステップ先を予測、強い着地の沈み 0.005·|vY|・最大 0.4 を許す）→ `Kit.raiseLowest(neutral - clearance)`。
  伸ばした脚（空中技）が着地の瞬間に床へ刺さらない。
- **接地判定**: 自機は `Humanoid.FloorMaterial ~= Air`。他の体（NPC・他プレイヤー）はクライアント側の FloorMaterial が平地でも Air と行き来するので、
  root から真下へ `HipHeight + root.Size.Y/2 + 0.6` の ray も併用する。

## 4. overlay: live の track に重ねる

購入済み・既存の track（走り・旋回）の上に、一部の関節だけを差し替える。

- **位相を止めない**: 動かしたい関節以外は live（Animator の値）のまま。例: 旋回のクロスオーバーでは、外脚は live の関節そのもの＋横切りの回転、
  支持脚と上体だけを overlay の姿勢へ。live の関節を補間で包むと踏み替えの位相が一瞬止まり、足が滑る。
- **補正は差分で持つ**: live に足した回転（`e.liveOffset = base:Inverse() * target`）を覚え、解放では差分だけを 0 へ戻す。
- **入りと抜けの補正は速さの上限つき**: `Kit.carryLimit(renderedPrev, uncorrectedPrev, uncorrected, desired, dt)` =
  「補正なしの脚がこのフレームに動いた量 + 360°/s·dt」まで。live の動きは遅らせず、補正の出現・消失だけを滑らかにする。
- **入る遅延**: 入力が続いてから overlay へ入る（旋回 0.6 s、明示の指示 0.25 s）。細かい舵で揺れない。
- 同じ向きの overlay 同士（例: 舵の旋回 ↔ 明示のクロスオーバー）は開始時刻を引き継ぐ。逆向き・解放・別スタイルで開始待ちへ戻す。

## 5. 遷移と速さの上限

- 地上の受け渡しはすべて 1 関節 360°/s（60 fps で 6°/frame）。
- 切替の瞬間に止めず、出ていく動きを短く運ぶ（`Kit.carriedStart`: duration·t·(1−t)² の 3 次の運び、両端で 0）。
- 補間の長さの目安: 既定 0.18 s、要素へ落ち着く 0.30 s、被弾 0.07 s、スピン 0.06 s（予備動作を食わない）、着地 0.05 s。
- 走り → 中間姿勢（両足を揃えた gather）→ 要素 → 走り と経由させると、どの組み合わせでも途中で脚が交差しない。
- 1 関節ずつの角度の上限は、Root を動かす接地補正と両立する（接地は最後に Root の縦移動で合わせる）。

## 6. 二次運動（`Kit.Secondary`）

速度だけから計算するので、入力を持たない NPC・他プレイヤーにも同じに掛かる。

- 測る: 水平速度から角速度 ω（上から見て反時計回り＝左旋回が正）と前後の加速度。0.1 s を超える途切れ（ロード・ワープ）の後は前の速度を捨てる。
- 傾き: atan(gain·v·ω/g) を上限で切り、速度 6→20 stud/s で立ち上げる（その場の向き替えで倒れない）。ばね（7.5 rad/s、減衰 0.72）で少し行き過ぎて戻る。
- **軸は踏んでいる足**: 低い方の足底を中心に Root を回し、回した後に低い方の足の高さを元へ戻す（沈みも浮きも出さない）。両足が同じ高さなら内側の足。
- **作者の傾きと二重にしない**: 目標の傾きから、作者（track・overlay）の Root の roll の同じ向きの分を引く（`extraBank`）。
- 胸: 加速で前（最大 9°）、減速・押し戻しで後ろ（最大 8°）。Waist だけ。
- 頭: 付け足した傾きの 55%（最大 15°）を首で打ち消し、ω に比例して曲がる先を見る（最大 18°）。胸も少し先行（最大 8°）。
- 腕: 付け足した傾き × 0.3 を両肩に（外腕が上がり内腕が寄る）。
- 重み: モードごとに bank / pitch / head / arms を 0〜1 で。全身を持つ動き（エモート・空中技・スピン）は 0。時定数 0.14 s で出し入れ。
- スケートは gain 1.35・上限 26°、走る人型は gain 1.0・上限 18° 程度が出発点（推定。カメラ距離で調整）。

## 7. 自機・NPC・他プレイヤー

- 同じ層・同じ関数で描く。モード名の出どころだけが違う:
  - 自機: コントローラが毎フレーム `setMode`。
  - NPC: サーバーが属性（例 `AnimationStyle`）を書き、クライアントが読む（値が変わったときだけ書く）。
  - 他プレイヤー: 届くのは再生中の track 名と重み。独自のスタイル名は届かない（Studio で登録した派生 track も本番では届かない）。
    → 速度・角速度・加速度・公開属性（ブレーキ中・被弾中など）から推定する（旋回が続いたら旋回、減速が強ければ停止、…）。
- **更新が途切れても外さない**: 自機が倒れている間にコントローラが早期 return して他の体の更新を止める実装がある。
  そこで「更新が古い体」を外すと生の track に戻って沈む（NPC がときどき沈む、に見える）。接地は更新の有無と無関係に続ける。
- 体が消えた・倒れた（Health ≤ 0）ときだけ外し、外すときは base（Animator の値）へ戻す。
- R15 の足は最初のフレームより後に来ることがある → `DescendantAdded` で関節を追加登録。

## 8. 負荷

- 12 体以上で毎フレーム動く前提: Instance の生成なし（RaycastParams は使い回す）、属性は値が変わったときだけ、ray は体あたり接地判定 1 本 + 足 4 本程度。
- IK の反復は 6 回まで（通常 1〜2 回で収束）。表（table）の clone は 1 フレーム数十個なら問題ない（計測で確認する）。
- 遠い体は二次運動や IK を省く（LOD）判断もある（推定: 80 stud 以上、実測で決める）。

## 9. 実測値（素の Baseplate、既定 Animate、R15 の AnimationConstraint アバター、2026-09-25〜26）

`scripts/make_test_place.py` の sandbox（平地・22° の坂・1 stud の階段）で、同じ MoveTo ルートをレイヤー OFF / ON で比較（sink = 足が床の中 −0.05 超、
float = 踏み足が 0.1 超浮く、の地上フレーム数）:

- 平地・移動中: sink 268 → 8、float 421 → 0、踏み足の平均 +0.086 → −0.001。
- 坂・移動中: sink 297 → 3〜6、float 53 → 0〜3。
- 静止（平地・坂・階段）: 0 / 0、誤差 0.000〜0.007。コンソールのエラー 0。
- 階段・移動中（割合）: OFF 53% / 22% → ON 16% / 14%（FLOOR_RATE 40 stud/s + CORRECTION_RATE 1440°/s、関節の 1 フレーム最大 76°）。
  速さの上限を外しても 16% / 15% のまま関節が 128〜160° 跳ぶ。上限を強くする（12 stud/s + 720°/s）と 24% / 16%。
  残差の主因は Humanoid の段の乗り上げ（描画の後の物理ステップで root が 1 段跳ぶ）で、上限ではない。

途中で見つけて直した不具合（同じ失敗をしないために）:

- 足のすぐ上から撃つ ray → 段・坂の中から始まり下の床を拾う（足が 3 stud 浮く誤計測・誤補正）→ root の高さから撃つ。
- 足の中心 1 本の ray → 段の縁で下の段を拾って沈む → つま先とかかとの 2 本、高い方。
- 「作者の浮き（平地基準）」を保つ → 既定 Animate の走りの flight で踏み足が 0.45 浮く → 低い方の足を毎フレーム床へ（`keepFlight` は任意）。
- 段の縁で足の床が 1 stud 不連続に変わり、IK が膝を 160〜175° まで畳んで脚が反転（1 フレーム 120〜150° の跳び）→ 足ごとの床を
  `Kit.smoothFloor` で速さ制限、IK の持ち上げ量を脚長 × 0.55 で頭打ち（膝 ~135°）、補正を `Kit.carryLimit` で速さ制限。
- Studio のウィンドウにフォーカスが無いと Play が ~15 fps に落ち、1 フレームの回転量が 4 倍に見える。跳びは 60 fps で測る（または deg/s で比べる）。

階段の残差をさらに減らす案（未検証）: root の縦の急変（|ΔY| > 0.3 / frame）を検出したら、描画の Root に −ΔY を置いて 0.1 s 程度で 0 へ戻す
（見た目の段差ならし）、階段区間だけ骨盤を動かさず段差の大きい足だけ IK、など。採用するなら sandbox で上の数値と比べてから。
