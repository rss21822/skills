# 作業場所と取り込み（正本を壊さない）

アニメーションの作業は Place 全体に散らばり（共有モジュール・クライアントの描画層・サーバーの NPC）、並行して他の作業も同じファイルを
触る。「どこを変えたか」を常に証明できる形で進める。

## 1. 作業用コピーと差分の層

- 正本の Place（Studio で保存された rbxlx、または Rojo のビルド）を**バイトコピー**して baseline として固定する（時刻と sha256 を記録）。
- 変更は**差分の層**として持つ: 差し替える / 追加するモジュールだけを、Place 内のパスに対応するフォルダへ置く
  （例: `src/<作業名>/client/*.luau` → `StarterPlayer/StarterPlayerScripts/<Folder>/<Name>`、`shared/*` → `ReplicatedStorage/<Folder>/<Name>`）。
- ビルドスクリプト: baseline の該当 Script の `Source` だけを差し替え、無ければ ModuleScript を挿入して、コピーを書き出す。`--check` で
  「コピー = baseline + 層」を検証する（層以外の Script は 1 バイトも変わらないこと、層の Source が一致すること）。
- Studio で試すのはコピー。Studio 専用の検証フックは層に入れず、開いたコピーにだけ一時的に入れる（除去して指紋を確認）。
- 開いている Studio が正本のファイルを握っているなら、その窓は保存しない。作業の報告で「この窓は古い DataModel なので保存しないで」と伝える。

## 2. 並行作業

- 同じツリーを別のセッション（人・エージェント）が未 commit で編集している前提。着手時と再開時に `git status`・更新時刻を確かめる。
- 他人の未 commit の変更は真実として扱い、上書きしない。自分の変更はその上に重ねる（3-way merge）。
- 大きな一括同期（src → Place の全体ビルド）は、Place と src のずれ（他の作業の未反映分）を一緒に持ち込むので、アニメーションの取り込みには使わない。

## 3. 正本への取り込み（採用が決まってから）

1. **前提の確認**: 正本の対象 Script が baseline と同一か。同一なら単純な差し替え。違えば 3-way merge（base = baseline、ours = 層、theirs = 正本の現行）。
2. **書き込みと証明**:
   - 層以外の Script は不変、層の Source は一致、追加したモジュールだけが増えた。
   - **逆に戻すと元のバイト列に戻る**（挿入したテキストを正確に記録して取り除き、差し替えた Source を元へ戻したら、元の bytes と完全一致）。
   - 元のファイルはバックアップへ。書き込み後の sha256 を記録。
3. **ソースツリー**（Rojo の src など）: ファイルごとに 3-way merge。衝突は理由を記録して解決する。改行コード（CRLF / LF の混在）を保つ。
4. **保護ファイル**: byte guard（承認済みの差分を JSON の層で積み、テストが「現在 = 最新の層の after」を逆順に辿って確認する仕組み）があるなら、
   新しい層（before / after / sha256 / 改行の種類）を登録する。層は新しい順に辿るので、最新を先頭に。
5. **同期スクリプト**: Place へ Source を同期するスクリプトの対象一覧に、新しく追加したモジュールを足す（本体だけ同期されて require 先が欠けると本番で落ちる）。
6. **再検証**: 正本 2 つ以上に入れたなら、それぞれから Script を抽出してオフラインテストを回す。正本のバイトコピーを専用の Studio で Play（自機・NPC、コンソール 0）。
7. **記録**: 決定記録（誰の依頼で、何を採用し、何を見送ったか）、QA の README（数値・sha256・再現コマンド）を更新。commit / publish はしない（依頼があるまで）。

## 4. 報告に入れること

- 取り込んだ Place と sha256、差し替え / 追加したモジュール。
- テスト結果（オフラインの件数、Studio の数値）、変更前後の比較。
- 取り込みと無関係に見つけた既存の問題（例: その Place は Studio 単独 Play で自機が出ない）と、それが取り込み前から同じであることの確認方法。
- ユーザーの手が要る事項（開いている窓を保存しない、publish の判断など）。
