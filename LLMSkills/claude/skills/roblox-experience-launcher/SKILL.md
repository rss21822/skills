# Roblox-Experience-Launcher

指定された公開済みExperienceを通常のRoblox Playerから起動し、実際に観察できた範囲で結果を報告する。Private Stagingも検証対象にできるが、一般公開環境とは区別する。

## 範囲と対象の確定

- 「まずPlayまで」「起動だけ」はロビー／ゲームの3D描画までで終了。試合開始などに広げない。
- 検証依頼では、指定シナリオ・期待結果を優先する。指定がなければ起動、スポーン、基本移動、主要UIの表示を軽く確認し、全機能合格とは報告しない。
- Experience名、Universe ID、入口Place ID、ログイン中アカウントを、ユーザー指定・現在のUI・プロジェクトの公開設定から確認する。Creator Dashboardの`experiences/<ID>`はUniverse ID、`places/<ID>`はPlace ID。同じ数値として扱わない。
- 通常は入口Placeから入る。サブPlaceが指定されても、ロビー経由のTeleportが正規経路ならそれを使う。URLだけから直接参加可能と決めつけない。
- 候補が複数あり対象を確定できない場合のみ質問する。既に明確な起動依頼があれば重ねて承認を求めない。

## Computer Useの準備

利用可能な`computer-use`スキルを発見し、SKILL.mdと必須のruntime・API・確認ガイドを読んで、その時点で提供されている操作方式に従う。Windowsネイティブ操作は対応しているComputer Useを使う。ブラウザ専用ツールにネイティブ操作がなくても、Windows操作全体が不可能とは判断しない。

現在のWindows方式が`@oai/sky`なら、永続JavaScriptセッションで次を初期化する。ツール名は現在の環境から発見し、バージョン別パスは固定しない。

```javascript
if (!globalThis.sky) {
  const { sky } = await import('@oai/sky');
  globalThis.sky = sky;
}
```

- `list_apps()`／`list_windows()`からRoblox Playerを選ぶ。Roblox Studioと混同しない。
- 返された単一ウィンドウを選択し、画面を観察する。最新のスクリーンショット／アクセシビリティに基づいて1操作し、直後に状態を取り直す。
- 座標、ウィンドウID、スクリーンショットIDを固定保存して使い回さない。

## 起動と入場

1. Playerが既に対象Experience内ならその状態を確認して再利用する。別ゲームのセッションを終了する必要があれば、その影響を確認する。
2. 未起動ならインストール済みアプリ一覧からRobloxを起動。起動要求がタイムアウトしても、ウィンドウを再取得して成否を確認する。
3. RobloxのアプリIDで起動できない場合、一覧にあるRoblox Player実行ファイルの識別子から起動を再試行できる。`Versions`のハッシュや実行ファイルのパスは過去値を使わず、現在取得したものを使う。
4. ログイン中アカウントを画面で確認。ホームの「続ける」／検索、またはブラウザの対象ゲームページから対象Experienceを開く。既知のゲームURLはブラウザに直接開いてよい。ブラウザからの起動は外部アプリ起動処理の許可ガイドに従う。
5. 詳細画面の名前・作成者を照合しPlayを押す。ホームのカード上のPlay操作で詳細画面に移動するだけの場合もあるため、ゲーム入場とは区別する。
6. 接続・読み込み・タイトル演出は短い待機を挟み観察。ボタン押下だけを成功とせず、実際の3D空間・自分のアバター・ゲーム固有UIが描画されたことを確認する。

### 応答が進まない場合

- 非同期起動の可能性があるため、すぐ連打せず数秒待って画面とウィンドウ一覧を再取得する。
- 状態が変わらない場合、現在の画面からフォーカス／ボタン位置を再確認して再試行する。クリック後のEnterも、そのUIで適切な場合は選択肢になる。
- 2026-10-02のSpinOut試行では、詳細画面でPlay押下後に変化が見えず、Enter操作後の観察でロビー入場を確認した。Enterが必須、または原因が確定したとは扱わない。
- 起動手段の変更は最大2回程度を目安にし、同じ操作の無限再試行を避ける。アクセス拒否・ログイン要求・セキュリティ確認・持続する読み込みエラーは具体的な状態を報告する。
- 認証・アカウント切替・権限変更・セキュリティ設定は自動で解決しない。必要なユーザー操作を簡潔に伝える。強制終了、再インストール、設定変更を起動依頼から推測して実行しない。

## 公開環境検証

起動確認以上が依頼された場合だけ実施する。

- 通常のUI操作で正規経路を通る。例：ロビーPLAY → モード選択 → Teleport → タイトル／カメラ演出 → Ready → 試合 → Result。
- 各チェックで「操作」「期待結果」「観察結果」「判定」を記録する。未到達は未検証、到達できない条件は阻害要因として分ける。
- NPC対戦、実プレイヤーとの通信、複数端末の同期は異なる証拠。1端末の成功から複数人動作を合格にしない。
- 音声は実際に聴取できる対応ツールがある場合に確認する。スクリーンショットだけでBGM・SE成功とは言わない。
- 必要ならPlayerの読取可能なログでエラーや参加先Placeを確認する。UIで見えない内部数値を推測せず、認証情報やチケットは出力しない。
- 対応ツールで証拠を保存できる場合はスクリーンショットやログの時刻・場所を記録する。保存できなければ観察証拠と明記し、架空の証拠ファイルを作らない。
- 課金、アイテム購入、他者への招待、公開設定変更、データ消去、コード改修、再アップロードは別途その操作への依頼がある場合のみ行う。テストに伴う通常のスコア／進行の保存にも注意する。
- 不具合を発見したら再現条件と影響を報告する。検証だけの依頼では修正・再公開しない。

## 報告と終了

対象Experience／参加経路、確認したアカウント、実際に到達した画面、検証済み・未検証・不具合を短く報告する。必要なら次の検証条件を添える。

「起動成功」「ロビー入場成功」「試合検証成功」「Result検証成功」を分ける。Studio Play、アップロードHTTP 200、ゲーム詳細ページの表示だけでは公開環境の動作検証にならない。検証対象がPrivate Stagingならその名称を使う。

起動のみなら原則そのまま開いておく。終了・退出を求められた場合は通常UIで退出する。

## SpinOutの起動例

この例は2026-10-02にPlayerでロビー入場を確認した対象。別Experienceの依頼に適用しない。実行時は名称・公開設定との一致を再確認する。

- Experience：SpinOut Private Staging
- Universe：`10765058710`
- 入口：`116702886109476`
- ゲームページ：<https://www.roblox.com/ja/games/116702886109476/SpinOut-Private-Staging>
- Classicのversion-history URLにある`105061705514538`はサブPlaceであり入口ではない。
- 今回確認したのはロビーの3D描画、アバター、PLAYボタンまで。試合・Resultの検証実績には含めない。
