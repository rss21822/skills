# Roblox Motif UI

投稿されたモチーフを、そのゲームにしか無い画面の手触りに翻訳し、既存コードを壊さずに Luau で着せ替え、Studio で実測して仕上げる。

放っておくと AI が作る UI は「紺〜スレートの半透明パネル、1px の薄い水色の縁、細い白文字、全部同じ角丸カード」に収束する。管理画面には見えても、遊びたくなる画面には見えない。このスキルの仕事は、モチーフから素材・形・色・字・生き物・動きを引き出して、その収束を意図的に外すこと。

実例: SpinOut のロビーを紺の "IceNoir" から "Pop Rink"（クリーム色の紙・プラム色の太い縁・キャンディ色・丸い書体・絵文字・押し込める下縁・ペンギン）へ作り直した作業がこの手順の元になっている。完成形の数値は `assets/skin-spec.example.json`。

## 成果物

1. **モチーフブリーフ**（数行）と **skin spec JSON** → `scripts/skin_preview.py` の lint 結果と style board（HTML / PNG）。コードを書く前に見た目を合意するため。
2. **スキン実装**: `assets/MotifSkinKit.luau` をコピーし、spec から生成した Luau モジュールで初期化。既存 UI へのアダプタと、プレイヤーが一番見る画面（主役画面）の作り直し。
3. **検証**: コンパイル、既存テスト、スキンの Lune テスト、Studio 監査（文字の収まり・48 px のタッチ領域・はみ出し・重なり）、各画面のスクリーンショット確認。
4. **適用と報告**: Place への反映、バックアップ、変更範囲と見送った事項の記録。

## 手順

### 1. モチーフを読む

入力は文章・画像・参考ゲーム・その組み合わせのどれでも来る。まず次の 6 軸で言葉にする（`references/motif-design.md` に読み方とレシピ、作例がある）:

- **素材**: 触ったら何でできているか（紙のステッカー、飴、木の札、ネオン管、羊皮紙、布…）。パネルと縁の描き方が決まる。
- **形**: 丸い / 角張る / 手描きの揺れ / 切り欠き。角丸の半径、縁の太さ、傾きの有無。
- **色**: インク（縁と文字）、紙（面）、主役色 1 つ、キャンディ色 4〜6、意味色（危険・成功）、補助色。
- **字**: 見出し・ボタン・本文の書体。Roblox に実在する書体だけ（`references/fonts.md`）。
- **生き物・小物**: マスコットや象徴物を Frame の組み合わせで描けるか。絵文字アイコンの系統。
- **動き**: 弾む・漂う・キビキビ。ループはすべて reduced motion で止める。

画像が来たら `python scripts/extract_palette.py motif.png` で色を拾い、そのままではなく役割（インク・紙・主役・キャンディ）に割り当て直す。写真の色は彩度が低いので、UI では彩度を上げ、インクはモチーフの色相に寄せた暗色にする。

モチーフが暗い（深海・ホラー・宇宙・夜の街）ときも「暗い紺のダッシュボード」にはしない。暗さはモチーフ固有の色相（深い青緑、茄子紺、血赤、墨紫）で出し、発光色のアクセントと明るい縁取り、テクスチャで遊びを足す。詳しくは motif-design.md の「暗いモチーフ」。

### 2. spec を書き、style board で先に見せる

`assets/skin-spec.example.json` を雛形に spec を書き（形式は `references/spec-format.md`）、次を実行する:

```bash
python scripts/skin_preview.py spec.json --html board.html --png board.png --luau MotifSpec.luau
```

- lint の ERROR（紺スレートの面色、存在しない書体、本文コントラスト不足など）は必ず直す。warning は理由を理解した上で判断する。
- board（PNG）を自分で見て、モチーフが伝わるか、主役の CTA が一目でわかるか、全部が同じ強さで騒いでいないかを確認する。ユーザーが対話中なら board を見せて合意を取る（ブラウザペインで HTML を開くか PNG を示す）。自律モードなら自己レビューして先に進む。
- 見た目の議論はここで済ませる。Luau を書いた後の配色変更は高くつく。

### 3. 既存 UI を棚卸しする

作り直す前に、何がどこで作られ、何に縛られているかを調べる（`references/integration.md`）:

- テーマ/スタイルのモジュール（色表、ボタン生成関数）、各画面の生成コード、画面の一覧。
- テストや他のコードが参照している Instance 名・属性・階層（壊すと機能が壊れる「名前の契約」）。
- 同じファイルを他の人やセッションが編集中か（`git status`、最近の変更）。
- Place の構成: Rojo で組み立てるのか、Studio で保存された Place に直接スクリプトが入っているのか。

その上で方式を選ぶ:
- **A. 実行時スキン（推奨）**: 既存テーマの色表をその場で書き換え、ボタン等の生成関数を包んで見た目だけ差し替える。共有コードを触らずに済み、失敗時は元の見た目に戻せる。
- **B. 直接編集**: 小さいコードベースを自分だけが触っている場合。
- どちらでも主役画面（最初の画面の CTA、ドック、モード選択、ロード/遷移、リザルト）は専用に作り直す。全画面を均等に塗り替えるより、プレイヤーが 8 割の時間見る 2 割の画面に手間をかけた方が効く。

### 4. 実装する

1. `assets/MotifSkinKit.luau` をゲーム側へコピーし、step 2 の `MotifSpec.luau` を隣に置く。`Kit.new(require(MotifSpec))` で初期化。
2. アダプタ（方式 A）か直接編集（方式 B）で既存画面へ適用。技法は `references/luau-techniques.md`。
3. 主役画面を作り直す。

守ること（それぞれ理由がある）:
- **名前と振る舞いは変えない**: Name・Parent 階層・属性・コールバック・有効/無効の判定は元のまま。見た目だけ変える。テストと他の機能がそこに依存している。
- **文字色は面の明るさで決める**: 明るい面にはインク色の文字、濃い面には白文字＋インクの縁取り（`kit:textOn`）。どの面でも読めることが「遊び心」より先。
- **タッチ領域 48 px 以上**、**絵文字は TextSize の約 1.5 倍の箱**（22 pt なら 36 px）。小さいと TextFits が落ち、スマホで押せない。絵文字は Unicode 12 までのものだけ（新しいものは □ になる）。
- **日本語**: Roblox 内蔵書体には日本語グリフが無く、システムの CJK 書体に落ちる。その際、要求した太さで描かれるので本文・ボタンは Bold 以上を要求する。英字専用の飾り書体（Luckiest Guy 等）に日本語を流さない（`latinOnly`）。
- **見出しは画面幅で縮む**ように（`kit:fitHeading`）。電話幅で固定サイズの見出しは収まらない。
- **UIGradient は文字色も掛け算する**。下縁（lip）やグラデーションを文字と同じ Instance に掛けるときは、文字が掛かる帯を白にするか、文字色をインクにする。
- **動きは TweenService 経由で reduced motion を尊重**。常時ループは画面が見えていない間止める。点滅・高速フラッシュは使わない。
- **全段 pcall**: 書体やプロパティが無くても画面は必ず出る。スキンの失敗で UI が消えるのが最悪の結果。

### 5. 検証する

`references/verification.md` の順に:

1. 変更した全 Luau のコンパイル（`luau.compile` か Studio での読み込み）と既存テスト。
2. スキンの Lune テスト（`assets/lune_gui_mock.luau` と `assets/test_skin_example.luau` を雛形に）: 名前の契約、色の割り当て、無効状態、押下、reduced motion。
3. Studio で Play し `scripts/studio_ui_audit.luau` を execute_luau（Client）に貼って監査。サイズ 3 種（例 1080x720 / 828x369 / 366x820）× 対応言語 × 全画面。失敗 0 まで直す。
4. 各画面のスクリーンショットを見て、モチーフが伝わるか・主役が立っているか・読めない箇所が無いかを目で確認する。数値の監査は「壊れていない」しか保証しない。

### 6. 適用して報告する

- Rojo 構成なら通常のビルド。Studio 保存の Place なら、変更したスクリプトの Source だけを差し込み、それ以外が変わっていないことを確かめる。差し込み前の Place はバックアップする。
- 他の人・セッションの未完了の変更を巻き込んでいないか、差し込むファイルの差分が自分の変更だけかを確認する。
- 報告には: 何をどう変えたか（モチーフの翻訳のしかた）、変えていない範囲とその理由、検証結果（数値と目視）、未検証のもの（実機など）、次の候補。

## 品質基準（AI っぽさを外すチェック）

- 面の色がモチーフ固有の色相を持つ（紺・スレート・無彩色の黒に逃げていない）。
- 縁がはっきりしている（インク色で 3 px 前後。1 px の半透明の縁は使わない）。
- 主役の CTA が画面で一番大きく、一番明るく、少し傾いたり弾んだりしていて、他の要素と同じ強さで並んでいない。
- 同じ種類の要素にも色や大きさの変化がある（全カードが同色・同寸ではない）。
- 文字の階層が 3 段以上ある（飾り見出し / 丸い見出し・ボタン / 読みやすい本文）。
- モチーフの「物」がどこかにいる（マスコット、小物、柄、看板の形）。
- 空白が「空き」ではなく「演出」になっている（ドット・縞・紙の重なり・影）。
- 全部を盛らない。1 画面の主役は 1 つ。

## よくある失敗

- lint を通したのに Studio で書体が変わらない → spec の書体名が Roblox に無い（Web フォント名を書いた）。`references/fonts.md` の一覧から選ぶ。
- 日本語だけ細く見える → 本文やボタンに Regular を要求している。Bold 以上に。
- 絵文字や見出しが TextFits で落ちる → 箱が小さい。絵文字は 1.5 倍、見出しは fitHeading。
- ボタンの文字色がくすむ → 同じ Instance の UIGradient が文字も掛け算している。
- 画面を開くと同じ内容が二重に並ぶ → 描画中に自分のサイズを変え、AbsoluteSize の監視から描画が再入している（integration.md）。
- 既存テストが落ちる → Instance 名や階層を変えた。見た目の部品は子として足し、元の部品は残す。
- 絵文字が □（豆腐）になる → Roblox の絵文字フォントは Unicode 12 まで。🪙🪄🫧🪼 などは使えない（`references/fonts.md`）。
- スクリーンショットに BillboardGui が写らない → AlwaysOnTop の Billboard は Studio の画面キャプチャに出ない。確認時だけ AlwaysOnTop を切る。
