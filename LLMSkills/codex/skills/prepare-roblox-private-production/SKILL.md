# 非公開本番Experienceのリリース準備

既存の本番用Experienceを、一般公開の直前まで整える。Placeの「公開済みバージョン」へのアップロードは、Experienceの一般公開とは別。後者はこのSkillでは実行しない。

新規Experience作成は `create-roblox-private-experience`、既存の非公開ステージング更新は `publish-roblox-private-staging` の担当。対象が本番用か検証用か不明なら、操作前に確認する。

作業開始時と最終報告時に [references/release-checklist.md](references/release-checklist.md) を読む。ゲーム固有の設定値は仕様・現行設定・ユーザー指示から確定し、例の値を転用しない。

## 境界と停止条件

- 対象の所有者、Universe ID、入口と各Place ID、認証アカウント、ローカル正本を実際の画面・応答で確定。名前だけで本番とステージングを判断しない。
- 作業中、Creator HubのAudience/AccessとRoblox.comの表示を確認し、Experienceを**非公開**に維持。公開切替、公開対象者の拡大、一般ユーザーへの招待、Kids/Select有料早期審査は実行しない。予期しない公開状態は追加更新を止めて報告する。
- 既存のユーザーデータ、商品価格、所有者、権限、外部SNS投稿を「リリース準備」の名目で変更しない。設定値に判断が要る場合は根拠を示して確認。課金購入・広告出稿・有料審査は別承認。
- 年齢・コンテンツ・地域コンプライアンスの質問票は、実装と実機証拠に一致する回答のみ。静的コード確認だけで準拠・審査通過を宣言しない。
- 意図した設定画面・アップロード先・版が照合できない、API応答が曖昧、認証やアセット権限が不足、Playerが起動不能な場合、推測で次の外部変更へ進まない。完了分と残課題を分ける。

## 実行

1. **対象と差分を固定** — Git/作業ツリー、正本ソースとPlace成果物、現行Cloud版、希望設定を棚卸し。未保存Studioや別Universeに接続されたStudioを正本扱いしない。変更前の設定と戻し方を記録。
2. **Placeを更新する場合だけ** — 全Placeを環境別IDで構築・テストし、ファイルのSHA-256を凍結。公開直前にもファイルと宛先を照合し、サブPlace→入口Placeの順にアップロード。API/Studioの成功表示に加え、各PlaceのCreator Hub公開済み履歴で版を独立確認。更新後のソース変更は「未公開」と区別。必要な一時APIキーは対象Universe・最小権限・短寿命に限定し、値を残さず使用後に失効を確認。
3. **Experience設定** — 入口、サブPlaceの直接入場制御、アクセス年齢・地域・端末・料金・サーバー、ジャンル、説明、アイコン、サムネイル、質問票、商品、SNSリンクを依頼範囲で設定。各保存後に再読込して永続化を確認。非公開中に動画アップロードが拒否されるなら未設定と記録し、動画のためだけに公開しない。
4. **収益導線** — 商品IDが対象Universeに属すること、販売状態、ベース価格、ゲーム内表示、購入リクエスト、レシート処理を別々に確認。購入なしでは実際の課金・付与を「確認済み」にしない。ステージング売上、保留中収益、使用可能なグループ資金を混同しない。表示価格と管理価格が違う場合は、ユーザー向け価格・割引内訳・購入プロンプトを調べ、原因未確定なら未確定と記録。
5. **実機とリリースゲート** — Creator Hub、Roblox.com、Roblox Playerを別の証拠として扱う。通常UIからLobby→全ゲームモード→試合→Result→戻る/再試合を可能な範囲で確認。Resultが放置で遷移しない等、仕様上の滞在条件は実際に待って確認。端末別・権限別の未検証は明記。起動や操作が遅い場合、ログ時刻と画面を照合し、クリック成功や障害原因を推測しない。
6. **引渡し** — 設定一覧、Place版/ハッシュ、実施した変更、Cloud保存確認、Player到達点、未検証、公開を妨げる不一致を1つの記録にまとめる。一般公開は別依頼として残す。

ゲームや権利の条件次第で、配信アセットの権限・画像/音源の来歴も公開前ゲート。Creator Storeで閲覧できること、Studioで取得できること、公開済みPlayerで動くこと、再利用権利は別々に判定する。
