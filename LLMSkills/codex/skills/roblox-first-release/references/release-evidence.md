# 完了・再開・復旧

## 四つの判定

1. **設定・アップロード**: 依頼範囲の設定保存、全Placeの凍結成果物と公開済み版、必要な商品連携・原文登録、終了処理を確認。ビルド・HTTP 200・単一Place成功では不足。
2. **翻訳生成**: 指定対象・言語の生成状態。100%は登録済み原文の範囲で、全UIや品質の保証ではない。割当不足・生成待ちはここに残す。
3. **実機受入**: 依頼シナリオだけ。未依頼は実機未検証であり、アップロード未完了ではない。Studio Play、Player、複数人・端末別を代替しない。
4. **一般公開**: 明示依頼、資格・適用質問票・権利／権限・完成版ゲートがそろい、Audience保存を再確認した場合だけ完了。PrivateのPlace公開済み版をPublicと呼ばない。

Playerスキップでも質問票の根拠不足は公開ブロッカー。設定・アップロード完了を、一般公開・実機・実購入完了としない。

各項目に意図値／観測値／判定／証拠／確認時刻／未確認を持つ。Placeの応答と独立履歴を対応させる。履歴にhashがなければクラウドhash一致とは書かず、アップロードしたローカルhashと確認版の対応を記す。

## 再開・証拠無効化

- ソース、成果物、Skill契約、認証アカウント、Cloud版、商品、翻訳、設定を再取得。旧記録は探索手掛かりで、現在値の上書き根拠ではない。
- 作成結果不明: 一覧とIDを照合。結果未確認なら追加作成しない。
- 公開結果不明: 独立履歴・時刻・応答を照合。結果確定前に再送しない。
- 翻訳結果不明: テーブル／previewで不足分だけ再送。手動翻訳や原文を削除しない。
- ソース／ID／価格／原文変更: 依存するビルド、試験、hash、公開、登録証拠を無効化。他PC変更は照合してから採否を確定する。
- 安全な代替経路と1回の結果確認付き再試行を使う。同じ不明状態で連打せず、生成待ちを無期限待機しない。監視登録は別依頼。
- 中断時も一時資格情報の終了処理を試みる。不可なら残存リスクを報告する。

## 部分成功と復旧

子Place失敗なら入口を更新しない。成功版、未更新版、入口旧版、互換性と再開地点を残す。初期版と完成版を区別する。

復旧対象はPlace版、設定、販売／外部掲載、Audience、データに分ける。旧版復旧が許可されても別PCの新しい版を戻さない。データ移行・消去・巻戻しは別作業。Place復旧は商品・翻訳・ユーザーデータ復旧ではない。

## 模擬受入

`python <skill-dir>/scripts/test_audit_release.py` は隔離した一時ファイルでID／hash／記録上のゲートを試験する。実環境の証明とはしない。運用判断は次も確認する。

- 他環境ID混在 → 最初の外部変更前に停止。
- 商品作成後の応答途絶 → 既存商品再読取、未確認再作成禁止。
- 一部子Place成功 → root gate不合格、入口更新禁止。
- 原文不一致 → 原文整理／方針確定前に生成しない。
- 生成待ち → 登録完了と生成未完了を分離。
- 他PCファイル更新 → 依存証拠無効化、旧hashで公開しない。
- Player未依頼 → 起動せず設定・アップロードで終了可能。
- Public未依頼 → Audienceを変えず非公開準備のみ完了可能。
- 子契約衝突／更新 → 再点検、黙示的override禁止。
- 独立した二つのrun → 記録・ファイル・許可・終了条件を混ぜない。意図的な共有設定変更は再読取する。

Skill本文・リンク・補助監査の合格はRoblox本番リリース合格ではない。
