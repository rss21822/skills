# Roblox購入収益の確認

既定は読み取り専用。購入、返金、公開、権限変更、グループ支払い、DevEx申請は実行しない。取引確認のためにテスト購入を作らない。

## 確認

1. 対象を特定: Experience名とUniverse、所有者（個人/グループ）、環境（公開用/ステージング）、商品名・商品ID、購入時期。Place名だけでExperienceを同一視しない。複数候補なら取引明細で照合する。
2. Roblox Creator Hubの「経済活動 → 取引」で対象所有者に切り替え、日付範囲を購入時期まで広げる。ゲーム内商品は「バーチャル」の明細を確認。商品名、販売元Experience、日時、購入者、ステータス、クリエイター側のRobux額を記録する。取引が見つからなければ「未確認」とし、収益ゼロと断定しない。
3. 購入者の実支払額が必要なら、そのアカウントの取引履歴または購入確定画面で確認する。商品設定・ゲーム内UIの表示価格だけを実支払額と扱わない。地域別価格、価格最適化、特典・割引の可能性を分ける。
4. グループ所有ならコミュニティの収入画面で「承認待ちRobux」と「利用可能なグループ資金」を別々に確認。グループ売上を個人のRobux残高やDevEx対象額と同一視しない。必要なときだけ、支払い制限・分配・個人DevExを追加確認する。
5. 購入が商品付与まで完了したか問われた場合のみ、`ProcessReceipt`による付与・永続化を別途確認する。売上明細の存在はゲーム内特典付与の証拠ではない。

## 金額の説明

Robloxの[公式収益説明](https://create.roblox.com/docs/monetize)と対象商品の最新規則を確認してから、実支払額と開発者取り分を比較する。ゲーム内Robux販売は原則クリエイター70%だが、商品・販売経路・価格調整を確認する。小数の端数処理は明細と整合する範囲で説明し、公式根拠がなければ丸め方式を断定しない。例: 表示価格18、収益13なら `18 × 0.70 = 12.6 ≈ 13` と整合。ただし実支払18は購入明細なしには未確認。

## 報告

短く「収益記録の有無 → どのExperienceの売上か → 何Robuxでどの状態か → 実支払額との差の根拠 → 未確認点」を示す。確認日時、取引画面へのリンクを添える。確定事実・計算上の推定・未検証を混ぜない。取引相手の個人情報は必要最小限のみ扱う。
