# Robloxゲームフォーマット合成

提示されたゲームアイデアの核を保ちながら、カタログ掲載フォーマットを組み合わせ、プレイヤー行動として説明できる新企画へ変換する。

## 必須参照

候補選定前に [references/format-catalog.md](references/format-catalog.md) を最後まで読む。カタログのIDとフォーマット名を正式な合成素材として扱う。

- 命名テンプレートをフォーマットとして数えない。
- カタログ外の要素を採用する場合は「Original Spin」と明記し、掲載フォーマットを装わない。
- 2026年の流行状況や現在人気であることを断定しない。必要なら別途、最新情報を調査する。

## ワークフロー

### 1. 元案の核を固定する

入力から以下を短く抽出する。不明点は妥当な仮定を置き、企画を止めない。

- Theme / Trend: 世界、題材、キャラクター、雰囲気
- Fantasy: プレイヤーが何者になり、何を感じたいか
- Theme Verbs: その題材だからこそ行う2〜4個の動詞
- Visceral Core: 触った瞬間に気持ちよい行為または緊張
- Social Seed: 協力、競争、投票、取引、救助、盗難などの関係
- Constraints: 想定人数、セッション長、対象年齢、制作規模など

元案の固有性を失うほど題材を一般化しない。

### 2. フォーマット候補を広く選ぶ

全9カテゴリを一度走査し、元案との相性がある候補を最低6件挙げる。次の役割で考える。

1. Primary: 最初の30秒から1セッションまで反復する主行動
2. Secondary: Primaryへ判断、成長、収集、物理、危機などを加える仕組み
3. Social / Retention Support: 友達と遊ぶ理由、または翌日戻る理由を作る仕組み

同じカテゴリだけで固めず、少なくとも1案では異なるカテゴリを交差させる。

### 3. 内部で複数スタックを作る

主フォーマット1つ＋補助フォーマット1〜2つで、最低6通りを内部検討する。原則3つを超えて積まない。

各スタックについて、以下を1〜5点で評価する。

- 題材固有の動詞とフォーマットが一致する
- タイトルや一文から3秒で行動が分かる
- フォーマット同士が因果的につながる
- 友達と遊ぶ理由が生まれる
- 1ラン後に即再挑戦したくなる
- 更新・収集・習熟など継続理由がある
- 既存作との差が感情、社会関係、または操作感にある
- 与えられた制作条件に収まる（条件がある場合のみ）

合計点だけで決めず、元案の核を最も強く表現するスタックを優先する。

### 4. 足し算を相互作用へ変える

採用フォーマットを別々のモードとして並べない。一方の結果が他方の入力、危険、選択、報酬になるよう接続する。

良い接続の型:

- 作ったものを次の危険コースで実際に試す
- 昼に集めた資源だけで夜の危機を耐える
- 業務を正確に行うほど異変を見抜く手掛かりが増える
- 捕獲した対象が移動、戦闘、交渉の能力を変える
- 投票結果が次ラウンドの地形や役割を変える

「ObbyもTycoonもRPGもある」のような独立機能の羅列は不採用とする。

### 5. Original Spinを加える

カタログの既知文法を入口にし、次のうち最低1つを新しくする。

- 感情: 守る、疑う、別れる、誇る、焦るなど
- 社会関係: 非対称な役割、相互依存、交渉、裏切り、継承など
- Visceral Core: 独自の手触り、変形、破壊、運搬、同期操作など
- Meta: 図鑑、世代、拠点履歴、分岐世界、共同記録など

既存人気作の名称、キャラクター、意匠をそのまま流用しない。

### 6. 60秒で約束を証明する

初回60秒の流れを書き、プレイヤーが一文の約束を実際に体験できることを確認する。

- 0〜10秒: 役割と目標が見える
- 10〜30秒: Primaryを一度成功または失敗する
- 30〜60秒: Secondaryまたは社会関係がPrimaryを変える

## 出力形式

ユーザーが形式を指定しない場合、次の順で日本語出力する。

### 元案の核

Theme、Fantasy、Theme Verbsを3〜5行で示す。

### 採用フォーマット

| 役割 | ID | カテゴリ | フォーマット | この企画での働き |
|---|---|---|---|---|
| Primary | ... | ... | ... | ... |
| Secondary | ... | ... | ... | ... |

必要な場合のみ3行目を追加する。IDと名称はカタログ表記を保つ。

### 新ゲーム案

- 仮タイトル: 固有名詞へ依存せず、行動の約束が伝わる名称
- 一文の約束: 「誰が、何をし、何が気持ちよい／怖いか」を1文で表す
- プレイヤー役割
- 1セッションの流れ
- フォーマット同士の相互作用
- 成功、失敗、即再挑戦の理由
- 社会構造
- 定着エンジン
- Original Spin
- 最初の60秒
- Non-goals: 入れない要素を2〜3件

### 選定理由

なぜこの組み合わせが元案を強くし、単なる機能追加ではないかを3点以内で説明する。

### 別方向の短案

異なるPrimaryを使った代替スタックを2案、各2〜3行で示す。ユーザーが1案のみを求めた場合は省略する。

## 品質基準

- 主フォーマットを一文で特定できる。
- 採用した全フォーマットが1セッション内で因果的につながる。
- 元案固有の動詞がコアループへ入っている。
- 既存作の外見差し替えではなく、感情・社会関係・操作感のどれかに独自性がある。
- 入口の分かりやすさと長期定着を別々に説明できる。
- 技術的実現可能性、Roblox API、実装方法、詳細工数は、ユーザーが明示的に求めない限り検討しない。
