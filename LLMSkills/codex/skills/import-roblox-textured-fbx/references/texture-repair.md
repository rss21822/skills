# テクスチャ欠落時の切り分けと修復

## 症状を分ける

| 状態 | 次の確認 |
| --- | --- |
| プレビューだけ着色、Workspaceにモデルがない | キューの実行状態、Add to Workspace、登録エラー、対象Placeを確認。再インポート前に重複を検索する |
| TextureIDが空 | SurfaceAppearanceのColorMapなどを調べる。有効な別方式の材質を壊さない |
| 参照はあるが白・灰色 | 読み込み結果、アセット種別、所有者・Experience利用権限、審査状態、ローカル参照を調べる |
| 色はあるが模様が違う | パーツと画像の対応、UV、複数マテリアル、頂点カラーや色の乗算を調べる |
| サイズや組み立てが違う | 軸・単位・Pivot・FBX変換情報を確認。テクスチャを貼るために形状を推測し直さない |

確認中の登録処理を並行して再送しない。不明な結果はキューとアセット一覧で照合する。同じ失敗は、原因が変わらないまま繰り返さない。権限・審査が原因なら、無断の再登録や別所有者へのアップロードで回避しない。

## 元画像を明示的に登録する

1. パーツごとの対応表を作る：一意のInstanceパス、MeshId、材質名、画像の絶対パスと用途、登録済みasset ID。重複名を`FindFirstChild`一件だけで処理しない。
2. 既存の有効な画像asset IDがあれば再利用する。必要な画像だけを、対象Placeで使う所有者へ登録する。目的の画像が存在しないなら、ユーザーに素材を求めるかDCCから取り出す。無関係な画像で代用しない。
3. 現在のStudioツールに`upload_image`があればそのスキーマを確認する。2026-09-14に確認した契約は`imagePaths: string[]`（HTTP URL）と`studio_id: string`、戻り値はURLから`rbxassetid://...`への対応表。必ず実行時の契約を優先する。
4. ローカル画像をURL化する場合は、必要画像だけのフォルダをループバック限定の一時HTTPサーバーで配信する。例えば、空いているポートと実在フォルダを選び、既存Pythonの`python -m http.server PORT --bind 127.0.0.1 --directory IMAGE_DIRECTORY`を通常の実行ツールで起動する。UIにコマンドを入力しない。リポジトリ全体やユーザーフォルダを配信しない。
5. URLの各パス要素をエンコードする。特に`+`、空白、日本語を手作業で置換しない。サーバーが応答することを確認し、登録結果を記録する。ツール側がループバックへ到達できなければ、外部公開トンネルではなくStudioの画像インポートUIへ切り替える。
6. `store_image`の`IMAGEID_...`はツール間の参照であり、Robloxの画像asset IDではない。TextureIDやColorMapに入れない。

## 既存モデルに割り当てる

- 単純なベースカラーだけのMeshPartなら、対応する画像asset IDをTextureIDへ設定できる。色の乗算が意図せず暗くしている場合だけ白へ戻す。既存の意図的な色付けを消さない。
- SurfaceAppearanceを使うモデルは、正しいColorMap・NormalMap・RoughnessMap・MetalnessMapの対応を保つ。TextureIDだけに置き換えてPBRを失わせない。ベースカラー画像を法線・粗さマップに流用しない。
- 透明度・AlphaMode・UV・複数マテリアルを保持する。単一メッシュ内の異なる材質を一枚の画像で誤って覆わない。必要なら元の材質境界を保った再エクスポートを行い、ユーザーのDCC操作方針に従う。
- 大きな処理はUndo可能な変更記録でまとめ、まず対象の少数パーツで目視確認する。アセット登録はUndoでは取り消せないことに注意する。

## メッシュだけがアップロード済みの場合

まず元FBXから階層・配置・材質付きで取り込む経路を優先する。既存Workspaceのメッシュがあれば作り直さない。

モデルassetと生のmesh assetは異なる。生meshを`game:GetObjects`で読み込むとInvalid XMLになる場合がある。mesh assetの復元が必要なら、利用可能なAssetServiceのCreateMeshPartAsyncなど、実行環境で確認できるAPIを使う。

ただし、生meshのIDだけでは組み立てを復元できない。元のパーツ相対CFrame、Size、Pivot、軸と単位の変換を確認できた場合に限り再構成する。過去の別モデルの位置・大きさ・asset IDを流用しない。特に同じ高さへ揃える、CFrameを全て原点にする、既知でない倍率を掛ける、リグを静的パーツへ置き換える処理は禁止する。

配置情報が不足する場合は、既存FBXをDCCで確認するか、階層を保持する再取り込みへ戻る。完成確認はSKILL.mdの検証・保存手順で行う。
