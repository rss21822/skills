# テクスチャ付きFBXをRobloxへ取り込む

指定FBXの形状・組み立て・テクスチャを保ち、指定Placeに保存する。インポートプレビューの成功と、Workspaceへの挿入・画像登録・保存の成功を区別する。

## 対象と作業境界

- 入力FBX、関連画像、対象Placeを特定する。会話から明確なら再質問しない。複数候補があり判断できない場合だけ質問する。
- 新規インポートか、既存モデルのテクスチャ修復かを先に決める。修復なら既存モデルを使い、重複を作らない。
- 今回の対象以外のモデル・スクリプト・設定は変更しない。反発処理などのゲームロジック、Experience公開、Git操作は別の依頼が必要。
- 静止プロップ、可動物、リグ付きモデルを区別する。すべてを無条件にAnchoredにしたり、統合・拡縮したりしない。既存配置・衝突設定・階層・リグを保持する。

## 1. 入力とStudioの確認

1. プロジェクトのAGENTS.mdなど適用指示を確認し、既存変更を把握する。対象ファイルのサイズ・更新時刻・ハッシュを記録し、上書き前に一意のバックアップを作る。
2. FBXと画像を読み取り確認する。ZIPは原本を残し、別の作業用ディレクトリへ安全に展開する。画像候補はFBXの隣、同名`.fbm`、元の書き出しフォルダを調べる。名前だけでなく、材質・UV・見た目でパーツとの対応を確認する。
3. Blenderでの正常表示や埋め込み済みFBXだけでは、Roblox側の成功としない。外部画像がなければ、既存のDCCアプリで埋め込み画像の取り出しを検討する。無断で画像やモデルを作り直さない。
4. 利用可能なStudioツールを探索し、実際のスキーマを読む。`list_roblox_studios`でIDとPlaceを対応付け、`get_studio_state`でEdit状態を確認する。現在のツール契約・確認要件に従う。`execute_luau`を使う場合は現在の`studio_id`、`datamodel_type`、明示的な`return`を指定する。
5. 対象の既存モデルについて、MeshId、TextureID、SurfaceAppearanceの各マップ、名前、CFrame、Size、Pivot、Anchored、衝突設定を記録する。空のTextureIDだけで欠落と判断しない。SurfaceAppearanceで表示している可能性がある。

## 2. 通常インポートを優先

Windowsのファイル選択・インポート・保存が必要なら、利用可能なComputer Useスキルを読み、その操作・確認規則に従う。過去の座標やウィンドウIDを固定せず、その都度観測したUIを使う。

- StudioのFile > ImportからFBXのプレビューを開く。キューだけが出たら該当ファイルの個別プレビュー・設定を確認する。
- アップロード先の所有者（個人・グループ）を確認する。ユーザーが指定したRobloxへのインポートに必要なアセット登録と、Experience公開・ストア配布は別物。所有者や権限が不明なら勝手に別アカウントへ切り替えない。
- 組み立てた複数パーツを保持する場合はモデルとして取り込み、Workspace追加を確認する。単一モデル化とメッシュ結合を混同しない。
- 軸、単位、寸法、パーツ相対位置、材質、画像、警告を確認してインポートする。前回のプリセットを無条件に信頼しない。
- Workspace内の実体と登録アセットを調べる。キューに並んだ、プレビューが着色された、インポートを押した、のいずれも完了証拠ではない。

正常なら検証・保存へ。欠落や登録失敗があれば [references/texture-repair.md](references/texture-repair.md) を読み、該当する部分だけ修復する。

## 3. 検証・保存

- 対象モデルだけを検査し、期待したパーツ数・階層・マップ対応・相対配置・寸法・固定状態になっていることを確認する。意図しないスクリプトの混入があれば実行せず調査する。
- 対象メッシュと画像についてContentProviderのPreloadAsync結果を取得し、タイムアウトを含め成功・失敗を記録する。長時間待機は非同期化し、有限の待機期限を設ける。
- Studioの実際のビューで上面・側面などを確認する。色の読み込み成功だけでUVやマップ対応の正しさを断定しない。必要なら対象モデルを選択し、見える位置へカメラを向ける。撮影用の移動をモデル本体へ適用しない。
- Playは必要性に応じて実施する。Edit表示確認、Playのクライアント確認、公開ゲームでの権限確認は別々に報告する。テストの一時変更は元に戻す。
- 開いているPlaceを外部から書き換えず、StudioのFile > Save to Fileで対象の正本へ保存する。Save to RobloxやPublishを代用しない。存在しない`game:Save()`を使わない。
- 保存先・更新時刻・サイズ・ハッシュを確認する。rbxlxは保存されたMeshIdと画像参照、対象モデル数を読み直す。既存スクリプトなど対象外の内容が変わっていないか比較する。
- 作業記録には入力FBX、モデル配置先、メッシュと画像の対応、登録先、保存証拠、実施した検証、未検証事項を残す。起動した一時サーバーは停止する。

完了報告は短く「どこへ保存したか／何を確認したか／未実施事項」を示す。素材不足、権限、審査、登録失敗が残る場合は完了扱いにしない。
