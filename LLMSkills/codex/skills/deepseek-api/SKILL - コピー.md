# DeepSeek API

DeepSeekへリクエストを投げ、応答をファイルに落とすまでの一連の手順。主な用途は
Roblox/Luau実装の外注（コード生成・レビュー・設計相談）だが、汎用の問い合わせにも使える。

DeepSeekは別系統のモデルなので、こちらが見落とした前提を突いてくることがある。
そこに価値があるので、返ってきた内容を鵜呑みにも黙殺にもせず、**必ず自分で検証してから**
ユーザーに渡すこと。詳しくは「応答の扱い方」を参照。

Codexにセカンドオピニオンを求める `codex-run` と役割が近い。CLIを介さず
HTTPで直接叩く分こちらのほうが速く、コストも見積もれる。

## 0. 最初に必ずやること: キーの確認

```bash
python scripts/ds_ask.py --check
```

`OK: authenticated` が出たらそのまま先へ進む。出なければ「APIキーの解決」へ。
キーが無い状態でリクエストを組み立てても401で捨てるだけなので、**先に確認する**。

Git Bash で `python` が見つからない場合は `py -3 scripts/ds_ask.py --check` を試す。
以降のコマンドも同様に読み替える。

## 1. APIキーの解決

スクリプトは次の順で探し、最初に見つかったものを使う。

| 優先 | 場所 | 備考 |
|---|---|---|
| 1 | 環境変数 `DEEPSEEK_API_KEY` | Windowsのユーザー環境変数に入れておくのが最も楽 |
| 2 | `~/.deepseek/api_key` | 全プロジェクト共通。ホーム直下 |
| 3 | `<リポジトリルート>/.deepseek/api_key` | プロジェクト単位でキーを分けたいとき |
| 4 | `./.deepseek/api_key` | カレントディレクトリ |

どれも無ければ `references/setup.md` の手順をユーザーに案内する。
設定は初回の1回だけで、以降は何もしなくてよい。

**チャットにキーを貼らせない。** 会話履歴に残る。環境変数かファイルに置いてもらう。

キーが手に入らないまま先へ進まないこと。「たぶん動く」前提のリクエストは
コストだけ払って401が返る。

## 2. リクエストを投げる

```bash
python scripts/ds_ask.py \
  --prompt-file prompt.md \
  --files "src/ReplicatedStorage/**/*.lua" \
  --system-preset luau-review \
  --out out/review.md
```

主なオプション:

| オプション | 意味 |
|---|---|
| `--prompt` / `--prompt-file` | 本文。長い依頼は必ずファイルで渡す（シェルのクォート事故を避ける） |
| `--files GLOB` | 既存コードを自動収集して本文に埋め込む。複数指定可 |
| `--model` | 既定 `deepseek-v4-pro`。軽い依頼は `deepseek-v4-flash` |
| `--system-preset` | `luau-impl` / `luau-review` / `design` / `plain`（`references/prompts.md`） |
| `--system-file` | 独自のシステムプロンプトを使う場合 |
| `--no-thinking` | 思考モードを切る。定型の量産や翻訳向け。切ると`--temperature`が効くようになる |
| `--effort` | `low` / `high`(既定) / `max` |
| `--max-tokens` | 既定 16000。長い実装を頼むときは上げる |
| `--out` | 応答の保存先。省略時は `out/deepseek-<timestamp>.md` |
| `--show-reasoning` | `reasoning_content` も保存する |
| `--json` | JSON出力モード。プロンプト側にも "json" と例を書くこと |
| `--dry-run` | 送らずに、組み上がったプロンプトとトークン概算・想定コストだけ出す |

**大きいコンテキストを送る前は `--dry-run` を通す。** 巨大なコードベースを丸ごと投げると
入力側だけで無視できない額になる。何がいくらで送られるかを一度見てから本番を打つ。

### Windows での注意

- `--files` のグロブは**必ずクォートで囲む**。囲まないとGit Bashが展開して
  スクリプトに渡らないことがある
- パスに空白が含まれる場合も同様にクォートする
- 出力ファイルはUTF-8で書かれる。PowerShellで開くときは
  `Get-Content -Encoding utf8` を使う

## 3. Roblox/Luauの使い分け

**実装を書かせる（`--system-preset luau-impl`）**
仕様は箇条書きより「何がどう動けば正解か」で書く。DeepSeekはRobloxのAPI名を
それらしく捏造することがあるので、依頼文に「実在するRoblox APIのみ使用し、
自信がないAPIは使わずコメントで代替案を示すこと」を含める。生成された`.lua`は
`--out` でファイルに落とし、そのまま渡さず自分で読んでから統合する。

**レビュー・デバッグさせる（`--system-preset luau-review`）**
`--files` で該当スクリプトを集め、症状（再現手順・エラーメッセージ・期待動作）を添える。
コードだけ投げると一般論しか返らない。RemoteEvent周りの検証漏れ、
サーバー/クライアント境界の取り違え、`while true do` のyield漏れあたりは
指摘が的確なことが多い。

**設計の別案を出させる（`--system-preset design`）**
既にこちらの案がある場合は、それを明示した上で「この案の弱点」と「異なる前提に立った代替案」を
求める。同意を求めない。追認だけ返ってくる依頼文になっていないか、投げる前に読み返す。

**量産（軽い定型作業）**
`--model deepseek-v4-flash --no-thinking` にすると速く安い。v4-proの1/3の価格。
判断を含まない機械的な変換ならこちらで十分。

## 4. 応答の扱い方

DeepSeekの出力は**下書き**であって成果物ではない。ユーザーに渡す前に:

- コード中のRoblox APIが実在するか確認する（捏造しがち）
- サーバー/クライアントの実行文脈が正しいか見る
- レビュー指摘は、実際に該当コードを読んで裏を取る。存在しない行を指摘してくることがある
- 採用しなかった指摘があるなら、その理由も添えてユーザーに伝える

丸ごと転記するとレビューの意味が消える。**どこに同意し、どこに同意しないか**を自分の言葉で
足すのが、このスキルを使う目的そのもの。

コストは毎回スクリプトが標準出力に出す。高額になった場合は黙って飲み込まず報告する。

## 5. 詰まったとき

| 症状 | 原因と対処 |
|---|---|
| 401 | キーの前後に空白・改行・BOM。`--check` が桁数を出すので確認。`setx` 後は**ターミナルを開き直す**（起動済みプロセスには新しい環境変数が届かない） |
| 402 | 残高不足。DeepSeekのコンソールでチャージが必要 |
| 429 | 同時実行数の上限。時間ではなく並列数の問題なので、待つより同時リクエストを減らす |
| 接続失敗 / タイムアウト | プロキシ環境なら `HTTPS_PROXY` を設定。企業ネットワークではTLS検査で落ちることがある |
| 応答が途中で切れる | `finish_reason: length`。`--max-tokens` を上げる |
| 長時間無応答 | 思考モードでは数分かかることがある。スクリプトは長めのタイムアウトとkeep-alive対応済み |
| `temperature` が効かない | 思考モードでは無視される仕様。`--no-thinking` を付ける |
| 日本語が文字化け | Git Bashの `LANG` 未設定。`export LANG=ja_JP.UTF-8` を試す |
| `python` が見つからない | `py -3` で代用。`python3` はGit Bashでは存在しないことがある |

APIの細かい仕様は `references/api.md`、キー配置の手順書は `references/setup.md`、
システムプロンプトの中身は `references/prompts.md` にある。必要になったときだけ読めばよい。
