# Create Roblox Private Experience

ローカルプロジェクトを正として、ユーザー指定の**片方**の非公開Experienceを作る。「本番用」は将来の一般公開先を意味するが、このSkill実行中は非公開のまま。公開切替・一般ユーザーへの招待は行わない。

実行前に [references/workflow.md](references/workflow.md) を読む。実機起動時は、利用可能なら `roblox-experience-launcher` と、その指定するComputer Use手順に従う。

## 対象の確定

- ユーザーが「本番用」か「検証用」を指定していなければ、二択を聞いて停止。過去の会話や既存Experience名から推定しない。
- 指定された種類について、作成者アカウント／グループ、ローカル正本、入口PlaceとサブPlace構成を確認。所有者や正本が複数候補で決まらなければ質問する。
- 新規作成が既存の同種Experienceと重複しそうなら、既存IDと目的を確認してから続行。既存Experienceの上書きへ自動変更しない。
- 本番用・検証用を同時に作らない。片方の作業から他方のID・データ・商品設定へ変更を波及させない。

## 不変条件

- Experience作成直後とPlace公開後の双方で、アクセスと対象範囲が**非公開**であることを確認。予期せず公開ならそれ以上の公開処理を停止し、安全な範囲で非公開へ戻す。
- Universe ID、各Place ID、入口Place、所有者を実画面／API応答で確定。表示名やファイル名だけで宛先を判断しない。既存本番・検証環境のPlaceへ誤公開しない。
- ローカル正本の未保存・未反映変更を確認し、ビルド後の全Placeをハッシュで凍結。オープン中のStudioが正本と一致すると確認できない限り、そこから保存・公開しない。
- 環境別のルーティング、永続データ、外部サービス、分析、課金商品を点検。異なるUniverseのIDを流用しない。未設定の購入導線は失敗時に安全側へ倒し、収益化を推測で有効化しない。
- APIキーは必要時だけ最小権限・対象Universe限定・短寿命で使用。値をファイル、ログ、チャット、コマンド履歴に残さない。使用後に失効・削除し、実際の消失を確認。上位の確認・認証ルールを回避しない。
- ユーザーが指定した非公開Experienceの作成・アップロードはこの依頼の範囲。一般公開、販売、購入、権限拡大、他環境更新、既存データ削除は別依頼。

## 完了判定

次を別々に検証して報告する。

1. `LOCAL`: ローカル正本からの全Placeビルドと利用可能な自動・Studio検証。
2. `CLOUD`: 指定側の新しいUniverseに全Placeを依存順で公開し、公開済みバージョン、所有者、入口Place、非公開設定をCreator Hubで独立確認。
3. `PLAYER`: 指定アカウントでRoblox Playerを使い、入口Placeの3D描画・主要UIを確認。複数Placeゲームでは通常UIから少なくとも1回サブPlaceへ移動。ゲーム固有の試合・結果は実際に到達した範囲だけ報告。

Playerが開けない、認証やアセット権限で止まる等の場合も、アップロード完了と実機未検証を混同しない。作成したID、URL、バージョン、ローカルハッシュ、未確認事項を残す。
