# 指標・Discoveryの扱い

公式資料の入口は `official-sources.md` のR01〜R07。名称・定義・可視範囲は実行時に確認する。以下は指標を混同しないための調査手順であり、固定された攻略公式ではない。

## 1. 指標台帳

各ゲームの `metrics` に、値だけでなく定義、出典、時間、対象、測定方法、観測の制約を入れる。

| 指標 | 扱い | 推論してはいけないこと |
|---|---|---|
| Visits | 公開された延べ訪問の累計。ページ／APIの集計対象を確認 | その人数が実在、現在も人気、全員が継続 |
| 現在CCU | 取得時刻の同時接続スナップショット | 日平均、最大値、DAU、継続率 |
| Peak CCU | 対象期間・取得方法のある最大値 | 通常運営での集客力 |
| 期間平均CCU | 十分な時系列と欠測・頻度の定義がある集計 | 平日／週末／地域差を無視した比較 |
| Likes・評価率 | 母数、取得日、計算式が必要 | 視聴者・全プレイヤーの満足率 |
| Favorites | その集計時点の登録指標 | MAU、通知受信、次回訪問 |
| 外部動画再生 | 媒体・日時・有料露出不明等を記録 | ゲームへの流入・課金の実数 |
| D1/D7/D30 | 許可済み内部データまたは制作者の明示公表 | CCU、累計Visitsから推定した「実測値」 |
| セッション時間 | 分子・分母・AFK・端末・流入を確認 | 動画の長さやラウンド時間との同一視 |
| 意図した共遊 | 現行定義と流入・対象期間を確認 | 同じサーバーにいるだけで友人共遊 |
| 課金率・ARPDAU・ARPPU | 対象日・通貨・収益範囲・母数を確認 | 価格×Visitsで代用 |
| 売上・利益 | 売上／手取り／外注・広告費／利益を分ける | Robux残高や流通総額を利益とする |

**入手できない値はnull＋理由。公表されていないことは0ではない。**
公開された制作者自己申告と、自分で確認した内部実測も区別する。他者の非公開アクセスを推測・回避して取得しない。

## 2. 日時と同一性

`observed_at` = 収集した日時、`period_start / period_end` = データの対象期間。
累計値は「開始点不明」を許容し、取得時点までの値であることを記す。記事の公開日を数値の対象日に流用しない。
同じExperienceの複数Placeを重複計上しない。データ提供元間の差を勝手に平均しない。

同じ条件の2回の累計観測から差分は計算できるが、それはその指標の差分であり、新規ユニーク人数ではない。差分のマイナスや集計範囲の変更を無視しない。
欠測を補間する場合は方法・仮定を記す。瞬間値の少数観測を「平均CCU」にしない。

## 3. Discoveryの確認表

実行ごとに `platform_checks` で以下を調べる。

| 確認項目 | 調査後の出力 |
|---|---|
| 推薦の対象面 | HomeのRecommended For Youとその他の検索・発見面を区別 |
| 指標の意味と期間 | 現在の名称、対象流入、分母、日別・期間別の定義 |
| 過去の資料との差 | 廃止・改名・期間変更・資料間の不一致 |
| 公式に示された重要度 | 公表範囲だけ。非公開の数式や重みを捏造しない |
| 自作で確認できる値 | 認可済みデータと、これから計測するものを分離 |
| 企画への意味 | 指標を増やす作業ではなく、価値と摩擦の改善へ変換 |

作成時点の公式発表には2026年6月15日の変更がある（R02）。ゆえに古い資料の「7日」や旧指標名を永続ルールにしない。現在の詳細はR01を再取得する。
公式文書に記載された流入母集団を守る。広告や外部流入の増加と推薦順位の改善を同義にしない。
ベンチマークは比較の参考。比較集合や対象期間が違うデータから一律の合格ラインを作らない。

## 4. 自作ゲームの分析

まず流入・端末・新規/既存・友人参加・バージョンを分ける。各KPIはその画面・データの定義を保存する。同じ「D7」というラベルでも、起算点や対象が一致するか確認する。

初回ファネル例（概念名）：
`join → controllable → first_core_action → first_result → retry_started`

割合には分母を付ける。再戦率なら「再戦可能な結果画面に到達したユーザー」か「全入場ユーザー」かを固定する。UIクリックと、実際に次のプレイが始まったことを分ける。
未成熟なD7/D30を0にせず未確定にする。平均の上昇が、待機・AFK・既存ファン偏重によるものかを点検する。

## 5. 数値のシナリオを求められたとき

内部の計画用試算は可。ただし仮定をすべて明記し、第三者作品の実績と同じグラフに混ぜない。
たとえば売上の構成を考えるなら、対象期間・アクティブ母数・課金率・支払者当たり金額・収益範囲を揃えた式を示す。料率・換金・税などは最新公式情報とユーザーの条件が必要で、勝手に固定しない。
成功確率や「必ず10億Visits」は出さない。目標は段階的な検証・人口・運営能力の問いへ分解する。
