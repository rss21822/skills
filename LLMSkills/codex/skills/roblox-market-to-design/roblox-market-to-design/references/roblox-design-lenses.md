# Roblox用の設計分解レンズ

これは分析用の分類。Robloxの公式ジャンル体系や、特定作品の実装を保証するものではない。全項目を強制せず、判断に効くものを選ぶ。

## A. プレイヤーが感じる価値

| 価値の軸 | 観察するもの | 企画に返す問い |
|---|---|---|
| 分かりやすさ | 入場直後に何をするか分かるか | 説明を読まなくても一度成功できるか |
| 操作・身体感覚 | 加速、当たり、音、応答、カメラ | 小画面でも気持ちよさが残るか |
| 技量と上達 | 見える差、学べる失敗、練習 | 熟練者以外も成長を感じるか |
| 公平な対戦 | マッチ、課金、装備、通信 | 負けた理由を納得できるか |
| 再挑戦の速さ | 敗退後の操作不能時間 | 失敗の直後に次の意図が生まれるか |
| 社会的事件 | 救助、逆転、協力、裏切り | 誰かと遊ぶことで何が増えるか |
| 自己表現・所有 | アバター、拠点、コレクション | 何を誰に見せたくなるか |
| 驚き・発見 | ランダム変化、秘密、組み合わせ | ただの数値抽選以上の発見があるか |
| 居場所・安心 | 訪問、交流、自由、失敗負荷 | 常に勝たなくても滞在価値があるか |
| 世界観・細部 | 役割、音楽、物理、反応 | 大量制作なしで個性を出せるか |

全軸で最高を狙わない。中核の1〜2軸、必要最低限の軸、意図的に捨てる軸を説明する。この数も計画用の目安で、ヒットの法則ではない。

## B. 時間構造を混ぜない

```text
アクション → ラウンド → 複数ラウンドのマッチ → ログイン1回のセッション → 次回以降
```

試合時間だけでなく、ロード、チュートリアル、待機、選択、観戦、結果表示、再戦を記録する。
タイムラインの区間は重複なく定義する。たとえば `敗退→再びコアを操作できる` は結果画面やロードを含める。一人の映像から中央値やp95を創作しない。

### 構成の候補

| 構成 | 比較する利点 | 比較する負担 |
|---|---|---|
| 常設ワールド・自由参加 | すぐ動ける、途中参加 | 技能・進行差、目的の曖昧さ |
| 全員同期ラウンド | 共通の緊張、分かる結果 | 敗退待ち、開始の人口要件 |
| ロビー＋並列の小規模試合 | パーティ・対戦単位の明確さ | マッチング、人数分散、復帰 |
| ロビー＋遠征・協力ラン | 旅・役割・協力の連続性 | 所要時間、途中離脱、全滅 |
| 共通ハブ＋別Placeモード | 世界と負荷の分割 | テレポート、友人、権限、人口 |
| 非同期・放置を含む進行 | 間欠的な参加、累積 | 待機を価値と誤認、能動体験の薄さ |

画面で並列試合が見えても、それが同一サーバー内か別サーバーかは別問題。確認できない実装はunknown。

## C. ジャンル別の追加項目

| ジャンル・機構 | 調査する項目 | 新企画で検証する問い |
|---|---|---|
| Tower / Obby / Escape | チェックポイント、落下、再開、難度、競争、追跡 | 初心者の失敗が学習になるか、待たずに再開できるか |
| Fighting / Battleground | 判定、コンボ、硬直、技量差、第三者介入、狙われ方 | 不慣れでも操作する余地と対抗策があるか |
| FPS / 決闘 | 照準、端末差、マップ、装備、ラウンド・マッチ・再戦 | 熟練と入口の分かりやすさが両立するか |
| 物理・リングアウト・スポーツ | 慣性、衝突、見える勝敗、逆転、チーム | 失敗を見てルールと改善方法が理解できるか |
| 協力サバイバル・遠征 | 役割、資源、危機、道中、救助、全滅・復旧 | 友人との会話が自然に生まれ、欠員でも遊べるか |
| ダンジョン・ローグライト | ラン内成長、ラン外成長、生成、拾得、合成、喪失 | 再挑戦が単なるやり直しでなく別の判断になるか |
| ホラー・探索 | 情報不足、緊張と休息、驚き、逃走、再訪 | 初見だけの価値か、繰り返して別の面白さがあるか |
| Tycoon / Simulator / 経営 | 生産、投資、待ち、拡張、リセット、見せる拠点 | 作業量を増やす以外の選択と個性があるか |
| 収集・RNG・育成 | 抽選、希少性、成長、展示、交換、能動遊び | 報酬を入手する過程と入手後の用途に価値があるか |
| Steal系・所有競争 | 取得、保持、警戒、防御、奪還、オフライン扱い | 対人の面白さと喪失の納得が両立するか |
| RP・生活・UGC・着せ替え | 役割、舞台、小道具、自由度、公開、評価 | コンテンツ消費者が自分の出来事を作れるか |
| 音楽・リズム・演奏 | 入力と音の関係、テンポ、音源、失敗、同期 | 音なしの入口と演奏の快感、権利と制作負荷が両立するか |
| パズル・質問・パーティ | 理解、情報差、回答、待機、全員参加 | 外部知識や言語に依存しすぎず会話が生まれるか |

## D. 低人数・端末・ソーシャルの必須シナリオ

1人、新規2人、熟練者＋初心者、友人グループ、通常人数、途中離脱、再接続を観察または試作する。
モバイルは操作数、指で隠れる範囲、文字、カメラ、同時入力、メモリ、通信を点検する。PCの動画だけで全端末に適合としない。
チャット・音声が使えなくてもコアが成立するかを検討し、利用条件を現行資料で確認する。

## E. 深掘りの結論

作品ごとに「入口で売っている価値」「続ける価値」「友人に話す価値」「払う価値」「必要な制作能力」を別々に書く。
さらに「今回そのまま持ち込めないもの」を書く。豪華な演出や既存ファンを削った状態でも、その機構が動くかを考える。
