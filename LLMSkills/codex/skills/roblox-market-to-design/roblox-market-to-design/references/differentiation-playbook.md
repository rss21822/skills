# 差別化・再定義プレイブック

## 1. 特徴の数ではなく、選ばれる理由

「競合と違う」を先に作らない。「誰にとって、何がよくなるか」を先に定める。

```text
対象者の場面 → 今の代替手段 → 欲しい満足 → 届かない理由
→ 残す核 → 変える構造 → 自分の優位 → 検証
```

別ジャンルの仕組みを持ち込む場合は、入力、端末、1回の時間、同時人数、言語、課金、文化的理解、制作供給量を比較する。Steam等でのヒットを、そのままRobloxでの需要の証明としない。

## 2. 変更の種類をラベル付けする

| 種類 | 判定の問い |
|---|---|
| モチーフ変更 | 見た目・名称・舞台を変えただけか |
| 品質改善 | 応答、UI、音、演出、初心者理解を改善したか |
| 機能追加 | 同じ目的を達成する手段を追加したか |
| 構成変更 | プレイ単位、勝敗、復帰、マッチ方式を変えたか |
| 相互補完 | Aの弱点をBが埋め、Bの弱点をAが埋めるか |
| 引き算 | 価値の低い操作・待機・経済を捨て、核を濃くしたか |
| 再定義 | 誰が、何のために、何を成功とし、他者とどう関係するかが変わるか |

再定義が他より常に優れているわけではない。品質改善だけで重要な需要を満たす場合もある。

## 3. 再定義テスト

前案と新案について、以下を並べる。
`プレイヤーの役割 / 目的 / 成功・失敗 / 中心の動詞 / 判断 / 他者の役割 / 報酬 / 反復`
変更したモチーフを元に戻しても、遊びが変わっているか。違いが新しい選択と感情を生むか。新しい操作負荷だけを増やしていないか。

## 4. 発想操作の候補

以下は設計仮例。特定ヒット作の由来や検証済み効果を主張しない。

- **離脱者の障壁を除く**：長い敗退待機が問題という証拠があれば、即時再戦・敗退中の別役割・短ラウンドを比較する。
- **旧来の満足を新しい入力へ**：音楽演奏の快感を足場移動へ翻訳する案なら、入力と音の理解、テンポ、失敗、権利を試す。
- **対立の目的を変える**：相手を倒す以外に、運ぶ・守る・押し出す・奪還する等を考え、役割や勝敗の変化を明示する。
- **自己表現を追加の報酬ではなく遊びにする**：収集物を見せる場と他者の反応をコアにする。展示がない希少性だけの案と比較する。
- **少人数の協力を大きな事件へ変える**：役割が相互依存する一つの乗り物・拠点などを検討する。欠員で機能不全にならないかを確認する。
- **人口を集約する引き算**：モードを減らして友人が同じ試合へ入れる価値を検証する。モード販売の機会損失も並べる。

## 5. 相互補完の評価

各組み合わせで「Aだけでは何が足りない」「Bはそれをどう解決する」「Bのせいで何が複雑になる」「それでも残す理由」を書く。
足し算の結果、勝ち方が二つに分かれて混乱する、モバイル操作が増える、人口が足りなくなる、追加運営が続かない、というケースを点検する。

## 6. フックの構造

```text
理解できる状況 → 選択・技能・偶然 → 見える変化 → 感情と他者反応 → 本編の結果
```

候補は逆転、際どい回避、救助、連鎖、失敗の笑い、希少な発見、劇的な変身、合奏、比較、持ち物自慢など。
短尺動画ではルール説明なしに何が起きたか伝わるか。本編では通常の遊びから出るか。仕込み映像ならその性質を隠さない。
外部の動画の人気とゲームへのコンバージョンは別に測る。上級者しか出せない見せ場は、初心者が同種の価値を感じる入口も考える。

## 7. 出力する機会カード

`OP / 対象者 / 欲求 / 既存の代替 / 障壁 / 歴史的な核 / 今の条件 / 自分の能力 / 根拠C / 反証 / D / T`
アイデアの選定は「魅力」「需要証拠」「差別化の理解」「低人数」「実装・運営」「学習できる試作」で行う。重みや点数はユーザーが指定しない限り固定しない。
