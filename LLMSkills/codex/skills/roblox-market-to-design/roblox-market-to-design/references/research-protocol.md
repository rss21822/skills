# 調査プロトコル

## 1. 調査と意思決定の接続

検索の前に重要な判断IDを用意する。たとえば「短ラウンド制にすべきか」なら、人気作のラウンド時間ではなく、初心者の初回操作、勝敗の理解、敗退から再参加まで、友人の待機、低人数、実装・運営負荷の証拠が必要になる。

調査カード：
`D / 問い / 現状と代替 / 必要な観察 / 必要な市場の裏付け / 反証 / 未取得の影響`

見つかった人気作に企画を合わせるために、後から問いを改変しない。問いが変わった場合は変更履歴に残す。

## 2. 候補集合の作り方

| 集合 | 調べる意味 | 注意 |
|---|---|---|
| 長期定番 | 繰り返し選ばれる価値、更新への依存 | 長い累計実績を現在の優勢と混同しない |
| 近年の伸長 | 新しい欲求・形式・集客経路 | イベント直後・広告・配信の一時性を分ける |
| 同型の比較対象 | 見た目が似ても成果が違う条件 | 低知名度だけで失敗と呼ばない |
| 歴史的転換点 | 誰の何を引き継ぎ、何を変えたか | 類似と作者が認める影響関係を分ける |
| Roblox外の隣接作 | 未移植の満足、別プラットフォームでの解決 | 操作、時間、課金、年齢、ネットワークの差を評価 |

対象ジャンルの同義語、旧名称、英語表記、機構名でも探す。主市場の言語を優先し、必要に応じ日本語以外へ広げる。日本語記事だけで世界市場の意見を代表させない。
検索例はプレースホルダーであり、実行済み検索ではない。

```text
"<title>" Roblox "<developer>"
"<title>" developer interview inspired by
"<title>" first time gameplay no commentary
"<mechanic>" Roblox similar games
"<title>" beginner confusing waiting pay to win mobile
site:create.roblox.com/docs <relevant feature>
site:devforum.roblox.com "<feature>" announcement
```

公式ゲームページと制作者から同一性を解決する。universe IDなどが得られなければnullのまま、URLと開発者を根拠に暫定同定する。似たタイトルの別ゲームへ黙って置き換えない。

## 3. 出典が証明できる範囲

| 情報 | 主な根拠 | その根拠だけでは言えないこと |
|---|---|---|
| ゲームの公開仕様 | 公式説明、更新履歴、観察 | 全員が同じ遊び方をする |
| 企画の意図 | 開発者の発言、企画資料 | その意図だけでヒットした |
| 現在の人気 | 定義・日時付き公開指標 | 継続率・収益・長期寿命 |
| 操作・UX | 実機、連続したプレイ映像 | 自分が触っていない端末での快適さ |
| 不満・愛着 | 原投稿、レビュー | 市場全体の割合、投稿者の実年齢 |
| 公式仕様 | Creator Hub、公式発表 | 特定ゲームが実装済みか |
| 第三者統計 | 収集方法が確認できる元データ | Roblox公式値との完全一致 |

「公式が主張した」は事実にできるが、その宣伝内容が第三者検証されたとは限らない。専門記事も転載元・独自取材の有無を確認する。SNS投稿を量的集計する場合は匿名化し、重複・転載を除き、母数と抽出法を示す。

## 4. 最小の観察記録

`OBS` に以下を残す。
- 対象ゲーム、資料S、方法（実機／動画／テキスト／提供された内部データ）。
- 観察日、分かる範囲のバージョン・端末・言語・人数・新規/既存。
- 動画のタイムスタンプ、資料の見出し、ローカルログなど再確認する場所。
- 見えた行動と画面。推測した心情や一般化はCの解釈へ分離。
- 未観察の箇所。編集カット、ロード省略、上級者の技量、課金済み状態。

「動画では即座に再戦した」は、その観察の事実にとどめる。「再戦待ちが常にゼロ」と拡張しない。観察の件数・時間が少ない場合は「全ラウンドを確認した」と書かない。

## 5. ユーザーの声

肯定／否定／要望を分け、何が話題かだけでなく「誰が、どんな場面で、その問題に遭うか」を整理する。
おすすめの分類：初心者の理解、技能差、友人参加、待機、モバイル、課金、公平感、更新、収集、世界観、反復疲労。

抽出の条件を先に置く。例：「直近90日の閲覧可能な原投稿を、肯定・否定・初見の検索語で探索し、同一内容の転載を除く」。これは代表標本の保証ではない。
プラットフォーム、確認件数、期間、見られなかった面を記録する。感情分類器やLLMによる判定は推定。原文を短く示し、翻訳・要約と区別する。非公開Discord等へ無断参加しない。

## 6. 歴史を企画に使う

単なる年表の代わりに、転換点ごとに以下を埋める。
`従来の満足 / 当時の制約 / 残した核 / 変更した入口・操作・時間・関係 / 新しく参加した層 / 失った価値 / 今回の適用条件`

ゲーム内の改修前後も別の版として扱う。現在のUIを初期ヒットの理由にしない。発売前のインタビュー、発売後の回顧、研究者の推測を明示する。

## 7. 反証と交絡

候補：既存IP・既存ファン、広告、配信者、プラットフォーム特集、季節、ライブイベント、無料特典、ボット疑惑、改名、所有者変更、データ欠測。
これらは「検討項目」であり、証拠なしに特定作品に存在すると書かない。
似た作品の差を、単一機能の因果効果と断定しない。失敗例が見つからなければ「見つからなかった範囲」と結論の限界を残す。

## 8. 終了と再調査

候補集合の多様性、重要Dの証拠、反証、新しい資料が判断を変える可能性を見て区切る。検索語・採用除外・アクセス失敗・未完了をresearch_logに保存する。
「全件」「唯一」「世界初」は、探索範囲がそれを正当化しない限り使わない。調査不足と機会の不在を混同しない。
