# 市場史・主流の偏り・普遍的ニーズ分析 — Codex Skill

Skill名：`market-history-to-needs`  
バージョン：1.0.0  
作成日：2026-09-18

## 何をするものか

ユーザーが指定したゲーム・コンテンツ市場について、次の3段階を実行するための手順です。

1. **過去20〜30年の歴史と、現在プレイヤーが集中するタイトルを調べる。**
2. **ヒット作に共通する要素を比較し、現在の主流がどの方向へ偏っているかを解釈する。**
3. **題材や形式が変わっても残る、持続的なプレイヤーニーズを考える。**

市場は毎回指定します。Roblox、日本の美少女ゲーム、特定ジャンルなどに固定していません。
「ゲーム案を作る」前の市場理解に用途を絞っています。既定では新作アイデア、差別化案、仕様書、実装を生成しません。
これまでの `content-market-to-design` や `roblox-market-to-design` とは別名の独立Skillです。どちらも導入必須ではなく、それらのファイルを変更しません。

## 分析の中心

| 段階 | 実行内容 | 欲しい成果 |
|---|---|---|
| 長期史 | 代表作・当時の成果・転換・残った価値を確認 | 流行の入れ替わりを説明できる年表 |
| 現在の集中 | 同じ指標・期間・地域で活動を確認 | 根拠付きのタイトル一覧 |
| 共通要素 | 題材、体験の仕組み、受け取る価値、供給条件を分解 | 上位群の比較表 |
| 主流の偏り | 過去や現在の周辺作、例外と比較 | 何に対して偏っているかが分かる解釈 |
| 持続的ニーズ | 異なる時代・作品形式で同じ満足を照合 | 対象者と反証を伴うニーズ仮説 |

「普遍的」は、調査期間・対象者の範囲で反復して確認できる、という意味で使います。全人類や永遠の未来に通じると証明するものではありません。
過去の表現と現在の表現が似ているだけでなく、その背後の満足が継続しているかを考えます。

## インストール

### このプロジェクトだけで使う

ZIPを展開し、中の `market-history-to-needs` フォルダーを次へ配置します。

```text
<プロジェクトのルート>/.agents/skills/market-history-to-needs/SKILL.md
```

フォルダー全体の配置を推奨します。単体のSKILL.mdでも使えます。
同名のフォルダーに独自変更がある場合は、比較・退避してから配置し、無断で上書きしないでください。

### 複数のプロジェクトで使う

```text
macOS / Linux:
~/.agents/skills/market-history-to-needs/

Windows（ユーザーホーム）:
$HOME\.agents\skills\market-history-to-needs\
```

`$HOME` はユーザーホームを表すシェル表記であり、その文字をフォルダー名にするのではありません。
WSL内のCodexではWSL側のホームを確認してください。

Codex CLI・IDE拡張では `/skills` または `$` によるSkill選択が公式に案内されています。変更が反映されない場合は配置を確認して再起動します。

配置と呼び出しの確認元（OpenAI公式、2026-09-18確認）：

```text
https://developers.openai.com/codex/skills/
転送先：https://learn.chatgpt.com/docs/build-skills
```

本Skillの分析方法・期間・深度は本パッケージ独自の規約であり、OpenAIが保証する市場調査の標準ではありません。

## 最短の呼び出し

```text
$market-history-to-needs

対象市場：［調べたい市場］

過去25年間の歴史と、現在プレイヤーが集中するタイトルを調べ、
現在の主流がどのトレンドに偏っているか、
時代を超えて残るニーズは何かを分析してください。
```

市場名だけでも進められます。資料や地域を指定すると範囲を絞れます。
市場が25年前に存在しない場合は、中核市場の実際の歴史と、その外側の源流史を分けます。

## 詳細な呼び出し

```text
$market-history-to-needs

対象市場：［調べたい市場］
対象地域：［日本／世界／特定地域など］
対象プラットフォーム：［指定があれば］
歴史：過去30年間
深度：deep
モード：full

1. 各時代の代表的なヒット作と転換点をリストアップしてください。
2. 現在プレイヤーが集中している作品を、指標と期間付きで示してください。
3. ヒット作の共通要素を、題材・仕組み・価値に分けてください。
4. 過去の主流と現在の周辺作品を比較し、主流の偏りを解釈してください。
5. 形式が変わっても残るニーズを、複数時代の作品と反証で検討してください。

事実・解釈・仮説を分け、累計人気と現在の活動を混同しないでください。
同じ系列だけでなく、異なる作品形式でも成立するか確認してください。
企画案や実装には進まず、分析に限定してください。
```

地域・プラットフォームの指定を省くと、仮の範囲とその限界を明示して調べます。過去の会話の趣向で市場を置き換えない設計です。

`full / refresh / standard / deep` はこのSkill内の作業指定であり、Codexのコマンドライン引数ではありません。

## 既定の調査窓

- 歴史：実行日から25年。20年・30年などのユーザー指定を優先。
- 現在の集中先：直近90日を初期窓とする。ただし取得できた期間・時点を正確に記録。
- 構造的主流：直近12か月を基本に、必要に応じて24か月の既存資料と比較。

これらは実務上の初期値です。必ずその期間のデータが取得できるとは限りません。
未来の観測、常時監視、自動の定期実行を設定するものではありません。

## 出力されるもの

```text
research/<市場名のslug>/<実行日>/
├── market-analysis.md
├── evidence-ledger.json
├── research-log.md
└── CHANGELOG.md
```

統合レポートに、市場史、歴史作品一覧、現在作品一覧、特徴の比較、主流の偏り、ニーズの時代別比較、対応表が入ります。
証拠台帳は `S / C / W / M / E / F / B / N` のIDで、出典・主張・作品・指標・時代・特徴・偏り・ニーズを結びます。
HTMLダッシュボードや画像は既定では作りません。明示的に追加を依頼した場合のみ対象にします。

## 調査の品質と限界

成功例だけでは因果は分からないため、比較作品・例外・別解を調べます。
市場全体の分母が不明なら、観測作品内の割合として扱います。
プレイヤーの心理は推測を含むため、作り手の意図、作品上の仕組み、ユーザーの反応を分けます。

作成環境ではファイル構造・YAML・JSON・内部参照・ZIPを検査します。実際のCodexでの起動と、実市場を対象にした調査全体の実行は未検証です。
`references/quality-checks.md` の挙動ケースは、今後の導入環境で実施するための設計であり、合格済みの実行記録ではありません。
