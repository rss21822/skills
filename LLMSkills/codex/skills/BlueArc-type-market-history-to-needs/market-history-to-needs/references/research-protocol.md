# 調査プロトコル

この文書は独自に設計した調査手順である。件数・期間は実務上の目安であり、統計的代表性や因果識別を保証するものではない。

## 1. 市場を先に定義する

### 最小ブリーフ

- ユーザーの市場指定を原文で保存する。
- 中核市場を「対象者／欲求・用途／ジャンル／地域／プラットフォーム／商流」で必要な範囲だけ定義する。
- 同じ市場内で互いに代替される作品と、歴史的・表現的に似るだけの作品を分ける。
- 媒体をまたぐ場合は、集計は分け、価値・歴史の比較でつなぐ。
- 定義の変遷を許容する。ただし、その時代に存在しない現在のジャンル名を当時の公式分類として扱わない。

### 狭い市場・若い市場

対象が特定プラットフォーム内のジャンルで、25年前に存在しないときは次の二段にする。

1. **中核市場史**：成立から現在まで。現在表の母集団になる。
2. **系譜・代替形式の歴史**：その前の端末・媒体・ジャンル。ニーズの照合に使うが、中核市場の25年史とは名付けない。

市場成立年の根拠が曖昧なら一点に固定せず、初期事例の確認範囲と未確認部分を書く。

### 地域が未指定の場合

言語からユーザーの対象市場を勝手に日本に絞らない。提供資料から合理的な暫定範囲を置き、主要地域の違いを別節にする。市場名そのものが不明なときだけ市場名を確認する。

## 2. 探索を6つの資料群へ分ける

| 資料群 | 探すもの | 注意 |
|---|---|---|
| 現在の活動 | 同時接続、アクティブ利用、プレイ時間、利用調査 | 定義・母集団・時期の一致 |
| 当時の成果 | 当時の販売、利用、順位、事業報告 | 累計と期間、国内と世界を分ける |
| 作品内容 | 対象版の仕様、実際のプレイ、公式説明、更新履歴 | 発売当初と現行版を混ぜない |
| 作り手の判断 | 開発講演、直接インタビュー、企画資料 | 意図、回顧、実測効果を区別 |
| ユーザーの価値 | 利用調査、レビュー、掲示板、行動・参加の記録 | 抽出方法・偏り・否定反応を保存 |
| 市場の構造 | 端末普及、商流、制作・運営、流通や規約の変化 | 嗜好変化の代わりに説明できるか |

一次資料を優先し、消失した公式資料は正当な保存版を検討する。専門媒体の現地取材も価値があるが、元の発言と記者の解釈を区別する。
同一ニュースの転載10本は、独立した10件の根拠ではない。元資料を `origin_group` で束ねる。

## 3. 検索計画を先に書く

市場の現地語と英語・日本語を必要に応じて使う。翻訳表記・旧称・運営名・作品IDも確認する。
検索語のひな形は以下。年は実行時の範囲に置き換える。

```text
[市場] history / retrospective / 歴史 / 変遷
[市場] [年] most played / active users / 売上 / ランキング
[作品名] developer interview / postmortem / 開発講演
[作品名] [年] player survey / reviews / update / concurrent players
[市場] [旧時代の用語] [年代]
[共通要素候補] [同時代の比較作品]
[ニーズ仮説] [異なる形式の作品] [反対意見・離脱理由]
```

最初は市場と時代から作品を選ぶ。後半で、仮説の支持例と反例を対にして探す。望む結論を先に検索語へ入れ続けない。
検索ログに日時、検索語、採用・除外、次に必要な資料を残す。検索結果件数を市場規模にしない。

## 4. 歴史資料の扱い

### 作品の役割

- `historical_hit`：当時の大きな成果を確認できる。
- `influential`：影響・転換への関与を確認できる。大ヒットと別。
- `current_leader`：現在の活動の大きさに根拠がある。
- `current_candidate`：代理資料しかなく直接活動を未確認。
- `counterexample`：主流と違うが支持された作品、共通要素があるのに成果が異なる作品など。
- `revival`：過去の形式・体験が後年に再び支持されたことを検討する作品。

役割は複数付けてよい。『影響があった』の確認にユーザー移動が必要とは限らないが、移動を主張するときは移動を示す根拠を別に要する。

### 時代区分の検査

境界候補は、新しい成功群、旧主流の変化、流通や端末の転換などから作る。
各時代に「その区分にした理由」「代表作の選定理由」「少数派として続いた方向」を添える。移行期は重なってよい。
同じ作品が複数時代に存在しても、各時代の版・表現・利用状況を個別に記録する。
数値が違う期間・単位なら、その時代の文脈内で示し、25年間の一つの人気スコアへ変換しない。

### 史料の弱さ

回顧記事しかない時代はそう書く。当時のユーザー調査がないなら、好まれた価値を断定しない。
作品の不在、資料の消失、データ提供のない地域を「需要がなかった」へ変換しない。

## 5. 現在の指標を検査する

### 1件の観測に必要な項目

```text
metric_id / work_id
指標名 / 元資料での定義 / 単位
値 / 欠測理由 / 推計範囲（存在する場合のみ）
対象開始・終了 / 瞬間観測の時刻 / 取得日時
地域 / 端末 / サービス版 / 対象ユーザー群
測定方法 / 出典 / 実測・推計・代理の区別
比較可能群 / イベント等の注記
```

- アクティブ人数、接続数、プレイ時間は異なる。
- 日次ピークの平均は、期間内の全時刻平均CCUではない。
- 売上には課金額や価格の差が入り、人数を直接表さない。
- 購入・DL・登録・Visitsの累計は、現在の活動人数ではない。
- 順位だけの資料から人数や隣接順位間の差を推計しない。
- 第三者推計は測定法、対象外のストア・地域、更新遅延を確認する。不明は不明。
- 値が0なのと欠測は別。欠測は `null` と理由で保持する。
- 記事が新しくても、数字が過去のものなら現在値ではない。

### 比較可能群

指標・観測法・期間・地域・端末・母集団が十分に揃うものだけ同じ群へ置く。集計法の違いが大きければ別群。
現在時点のCCUを使うなら同じ時刻帯の範囲を示す。過去時点のスナップショットを混ぜたランキングは作らない。
同じ期間の資料が得られない場合は、値をそのまま並記し「非比較」と書く。恣意的な補正をして比較可能に見せない。

### 集中度の計算

同じ比較可能群の観測値を `x_i` とすると、`x_i / sum(x_i)` は、その群に含まれた**指標量の構成比**である。
市場全体の網羅性を示せない限り「市場シェア」と呼ばない。
複数作品で同じ人が活動するDAU・MAUでは、この計算はユニークな人の配分ではない。異なる利用強度もあり、プレイヤーの選好割合とはいえない。
同時CCUであっても複数端末や重複接続の扱いが不明なら、ユニーク人口へ読み替えない。

### 実行中の制約

既存の時系列がないなら取得時点のスナップショットとして出す。後日まで待つ、24時間監視したことにする、バックグラウンドで観測を約束することはしない。
取得制限・有料壁・規約上の制約がある場合は回避しない。公開代替資料を探し、残る制約を示す。

## 6. ユーザー反応を、心理の証拠として扱う

母集団、期間、件数、抽出方法、言語、否定反応の採り方を記録する。
レビュー抜粋は、人気順だけでなく新着・評価差・継続者と離脱者などを可能な範囲で比較する。
ただし投稿者と全プレイヤー、現在のファンと過去のファンは一致しない。極端な発言を市場の総意にしない。

制作者の「この価値を狙った」は意図の証拠。レビューの「ここが好き」はその投稿者が受け取った価値の証拠。実際の行動は行動の証拠であり、内心の証明ではない。
これらが同じ解釈を支えるかを照合し、一致しない点も残す。

## 7. 調査の終わり方

依頼範囲・利用可能資料・実行上の制約を優先し、際限なく候補を増やさない。
主要時代、現在の主要群、重要な偏り、ニーズの反証まで確認し、新規探索が主に重複情報になるなら区切る。
終わるときに、確認済み範囲、弱い時代・地域・指標、残った対立仮説、追加資料によって変わりうる結論を記録する。
全件を数えられる母集団と照合していない限り、網羅・全作品・完全なランキングと名乗らない。
