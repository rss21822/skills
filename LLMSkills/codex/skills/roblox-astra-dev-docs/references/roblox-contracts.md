# 必要なRoblox契約だけを選ぶ

全文を生成文書へ写さない。MVPに該当する節だけ使用する。ここで挙げる数や方法は、システムの採用を強制するものではない。

## 共通: 現物と責務

- ソース管理: どのファイルまたはPlaceが編集対象か。Rojoで対応づけたInstanceと、Studioだけで管理するもの。
- 実在／予定: 既存のファイル・モジュール・Instanceは現物を確認する。新設名には追加予定と付ける。未作成のフォルダを既存構成として図示しない。
- 最低限の画面: プレイ状態の見分け、操作対象、結果、復帰に必要なもの。装飾仕様は核に関係するものに絞る。
- キャラクター: 標準アバター、独自キャラクターなど、操作やアセット互換性に影響する選択だけを決める。
- 初回準備: 新規で構成がなければ、最初の作業で何を用意すれば試遊できるかを示す。既存プロジェクトへ新しいツールチェーンを持ち込まない。

## マルチプレイ・通信がある

何人で、どの共有状態を、誰が決定するか。途中参加・退出で役割、目標、進行がどう変わるかを書く。Serverは共有結果を確定し、Clientは操作要求と表示を担うなど、責務をゲームに即して定める。

通信は実装に必要な範囲で、次の契約を持たせる。

`通信名／方向／送る場面／引数の型・必須性・範囲／検証する状態・所有・距離など／受理と拒否の結果`

数値を受け取るなら非有限値、対象を指すなら有効な対象・所有・現在状態など、入力に対応した検証条件を書く。頻度制限、重複要求、遅れて届いた要求は、その操作で起こる問題に対応させる。全通信へ同じ巨大なエンベロープや再送システムを導入しない。

共有資源の取得など同時要求があり得る場合は、同じ物を二重取得できないなどの不変条件と、その確認方法を示す。クライアントから送った得点や所持数を、そのまま確定値として使う設計にしない。[Robloxのクライアント・サーバー境界](https://create.roblox.com/docs/scripting/security/client-server-boundary)は入力と文脈の検証を説明している。APIや仕様を実案件の根拠に使う時点で再確認する。

## 永続保存がある

以下が実装判断に必要になる。

- 保存する項目、型、初期値、キーの単位、スキーマの扱い。
- 読込・保存のタイミング、更新の主体、競合時の扱い。
- 読込失敗時に既存データを初期値で上書きしないなど、欠損と失敗の区別。
- 保存失敗時の通知、再試行、退出時の扱いと、検証に使うデータ環境。

具体的な失敗時挙動は仕様として決める。まだ根拠のないAPI上限や再試行秒数を「Roblox標準」として固定しない。保存を使わないMVPなら「セッション内のみ」で足り、保存用スキーマやスタブを追加しない。現行仕様は[Data stores](https://create.roblox.com/docs/cloud-services/data-stores)を参照する。

## 複数Place・外部サービス・課金がある

採用済みの場合だけ、対象環境、識別子の出所、入力と返答、失敗時の戻り先、重複実行の影響、実行に必要な授権と検証環境を明記する。

Place移動なら出発・到着・失敗の挙動、課金なら購入成立と付与の一貫性など、中心となる契約を省略しない。一方、MVPにない場合は設計を始めない。

現環境で対象サービスを使えない場合、仕様の必要条件として残す。ローカルの模擬処理を実サービスの検証完了としない。ID、購入実績、公開状態、権限を架空の値で埋めない。

## 物理・負荷・アセットが核にある

- 物理: 衝突・移動・判定の決定主体と、演出に任せる部分。意図した入力とサーバーの結果を一緒に観測する。
- 負荷: 対象端末、最大想定場面、同時人数・物体など負荷の要因、測定場所、仮の予算。FPSなどは目標と実測を分ける。
- アセット: 必須のモデル・アニメーション・音、実在IDと追加予定の区別、検証用代替が許される範囲。体験の核に必要な素材を汎用Partへ置き換えたまま完成扱いにしない。

## 受入条件の具体性

弱い: 「通信が安全」「スマホで動く」「保存できる」。

具体化: 「同じ対象へ二人が取得要求を出しても、所有者と供給総数が一意で全員の表示が一致する」。

具体化: 「対象タッチ端末で移動を続けながら主操作を実行し、指を離した後に入力状態が残らない」。

具体化: 「読込失敗を注入した試験では既存値を書き換えず、定義した復帰表示になる」。

これらは必要なゲームだけで採用する。試験結果は、実際に行った層・対象・入力・観測結果で報告する。Studio上の複数Client試験、実機操作、人間同士の遊び、公開環境の動作は別の証拠である。
