# Tripo生成・テクスチャ・取得

## 開始前

1. 現在のTripoワークスペースを観察する。実行中・完了済みジョブがあれば、名前だけでなく入力画像、形状、ジョブURLから対象を特定する。
2. 入力モードと **Smart Mesh P2.0** の選択を現在のUIで確認する。名称がP2.0 Preview等なら実際の表記を記録する。P2.0がない、権限で選べない場合は停止して制約を伝える。
3. 公開範囲、消費クレジット、テクスチャ工程の別料金を確認する。過去の価格やサブスクリプション状態を使い回さない。公開を許可されていない成果物をコミュニティへ公開しない。ツールが禁止するプライバシー設定操作を迂回しない。
4. メッシュ密度、トポロジー、テクスチャ解像度は用途で選ぶ。3000ポリゴン、Quad、4K等を一律の必須値にしない。対象のゲーム・機器に予算があるなら優先する。

## 入力を作るときのひな型

画像生成に渡す条件を次の要素で構成する。ひな型内の内容は対象に置き換える。

> 完成三面図のデザインを保持し、部品「[名前]」だけを孤立して表示する。含むものは[範囲]、含まないものは[隣接部品]。形状は[輪郭・厚みの比率・底面・接続面]。穴は[貫通/窪み]。材質・配色は[指定]。全体と厚みが読める単一の斜め正投影、十分な余白、無地背景、穏やかな照明。文字・寸法線・複数ビュー・床・強い影は不要。

この画像を確認してからTripoに渡す。文字で除外した部品が画像に残っていれば先に画像を修正する。

## 各パーツの工程

1. 確認済み入力を投入し、プレビューが意図した画像であることを確認する。
2. 必要な設定と消費を記録して生成する。複数の生成を無制限に並列投入しない。
3. ジョブが完了したらモデルを回転して、裏面、穴、シルエット、不要な融合、離れた破片を確認する。画像の見た目だけで合格にしない。
4. テクスチャが未生成なら必要な工程を実行する。ジオメトリ完了とテクスチャ完了を別々に記録する。正投影との寸法差は記録し、Blenderでの単純な寸法合わせで済むか判断する。
5. FBXなど依頼された形式で、テクスチャ付きの書き出しを選ぶ。形式・オプションは現在のUIから確認する。
6. ダウンロード先で実ファイルを確認する。Exportボタンが再び有効になっただけではダウンロード成功ではない。アーカイブ名、容量、内容一覧を照合する。
7. パーツ別の保存先に元ZIPを保持する。安全な展開先を指定し、パストラバーサルや既存成果物への上書きを避けて展開する。FBXと `.fbm` 等の画像フォルダの関係を維持する。
8. テクスチャの有無と対応を確認する。ファイル名に空白や `+` があっても勝手にリネームして参照を壊さない。外部転送が必要な別工程では正しくエンコードする。

## 再開・失敗時

- ダウンロードだけ失敗した場合、同じ完了ジョブの取得を再試行する。新しい生成ジョブは作らない。
- UI状態を観察してから再操作する。同じ失敗を2回繰り返したら、ダウンロード履歴・保存先・ジョブ状態を診断する。理由不明のままクリックし続けない。
- ユーザーがZIPを保存して渡した場合、そのファイルを調べて続行する。手渡し経路と自動取得を区別して記録する。
- P2.0利用不可、認証、課金、公開条件などが障害なら、完了済みの画像とジョブURL、必要な操作を残して引き継ぐ。別サービスやBlenderでの自作に切り替えない。
