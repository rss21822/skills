# Blender GUIでのセットアップと検証

Blenderの画面をComputer Useで操作する。実行前に利用可能なComputer Useスキルを読み、現在のウィンドウとモードを確認する。MCP、Python Console、bpy、スクリプトによる組み立ては使わない。

## 作業ファイルを守る

- 既に開いているシーンの保存先と未保存変更を確認する。別作業の変更を破棄しない。
- 元ZIP/FBX/テクスチャは変更せず保管する。組み立ては版付きの専用 `.blend` に保存する。
- Save Asはショートカットの成功を推測しない。実際の保存ダイアログと宛先ファイル名を確認する。保存後はタイトル、実ファイルの更新日時・容量で照合する。
- 既存のチェックポイントを上書きしない。`.blend1` 等のバックアップを無断で消さない。もし誤上書きが起きたら、まず現在の組み立てを別名保存し、復元可能な版を確認してから復旧する。

## インポートと配置

1. 各パーツをGUIからインポートし、Outlinerで元のパーツと対応する名前を付ける。不要なCamera/Light等は既存作業を壊さず非表示・書き出し対象外にする。
2. マテリアルプレビューで全パーツを確認する。画像参照が切れていれば、展開済みの元画像へGUIから再接続する。勝手に単色材質で代用しない。
3. PBRマップがある場合はBase Color、Normal、Roughness、Metallic等の役割を区別する。元画像を維持し、用途に合う色空間と接続を確認する。
4. 三面図に対して上面・正面・側面で輪郭と比率を合わせる。単位、実寸、前方・上方向、原点・回転中心を決めて記録する。画像生成の寸法を絶対値とみなさない。
5. 移動、回転、スケールで部品を接続する。隙間、めり込み、底面の段差、意図しない反転を複数方向から確認する。左右非対称のものは鏡像を見落とさない。
6. 必要な変換のみ適用する。リグ・アニメーション付きモデルでは変換適用や結合が挙動を壊さないか先に確認する。静的モデルの手順を一律適用しない。
7. 形状そのものが不足する場合はTripoの入力・生成工程へ戻す。新規形状の自作、穴埋めモデリング、リトポロジー等が必要なら工程変更として説明し、勝手に行わない。

## `.blend` を完成保存

1. 必要な画像をPack Resources等の現在のGUI機能で内包し、参照切れを確認する。元の画像ファイルも残す。
2. 組み立て用 `.blend` を保存する。
3. 保存済みファイルを再オープンし、パーツ数、寸法、配置、テクスチャを確認する。単に保存操作をしたことと再オープン成功を区別する。

## 書き出しとラウンドトリップ

1. 完成品を構成するオブジェクトのみ選択する。比較用モデルや既定Cube、Camera、Light等を含めない。
2. 対象アプリに合う形式、単位、倍率、軸、メッシュ/リグ、アニメーション設定を確認する。静的小物では不要なアニメーションを書き出さない。
3. FBXの場合、現在のエクスポーターが対応するなら画像をコピー・埋め込みする設定を使う。ただし埋め込みだけで他アプリが読めるとは保証しない。対応する画像ファイルも同梱できる形で保持する。
4. 実ファイルの存在、容量、SHA-256を確認する。元モデルとは別の空シーンへ書き出しファイルをGUIで読み込む。
5. パーツ数、寸法・軸・向き、接続、全テクスチャを確認する。複数メッシュへの分割自体は失敗ではない。対象仕様で結合が必要かどうかを判断する。
6. 検証シーンを保存するなら名前に `roundtrip-check` 等を付け、正本と区別する。最後は完成 `.blend` を再オープンして見せる。

## 成果物の区別

- **入力**：参考画像、三面図、パーツ画像、各プロンプト。
- **生成元**：Tripoジョブ記録、元ZIP、元FBX、元画像。
- **完成正本**：組み立て `.blend` とテクスチャ付き書き出し一式。
- **検証**：複数方向の画面、再オープン/再インポートの結果、必要なら検証用 `.blend`。

Blenderへの再インポートで材質が見えても、Robloxや他エンジンでの表示を検証したことにはならない。ゲームへの導入、当たり判定、リグ・アニメーション、LOD、公開は、依頼された次工程として別に扱う。
