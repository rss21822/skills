# Tripo P2.0 → Blender モデル制作

参考画像 → 整合した三面図 → Tripoによる生成 → Blenderでのセットアップを一貫して行う。単一パーツの小物にも、複数パーツの装置・キャラクターにも適用する。

## 必須方針

- **形状生成には必ずTripo Smart Mesh P2.0を使う。** 現在の画面で選択を確認する。別の生成モデルへ黙って変更しない。
- **Blenderは原則99% Computer Use。** 生成済み形状の配置、回転、寸法調整、マテリアル設定、保存・書き出しを行う。Blender MCP、Python Console、bpy、ヘッドレス処理による代替や、プリミティブからの作り直しはしない。例外はユーザーが明示的に工程変更を指示した場合だけ。
- Astraが生成物をセットアップする制作フローを想定するが、実際の担当モデルを偽らない。特定モデルが必須なのに利用できない場合は、その制約を伝える。モデル切り替えや別タスク作成を無断で行わない。
- シェルは入力の一覧、アーカイブの検査・安全な展開、コピー、サイズ・ハッシュ確認など補助用途に限定する。モデル加工の迂回経路にしない。
- Tripoによる生成物には寸法誤差や形状の揺らぎがある。三面図を寸法保証済みCADと呼ばず、画像だけで3D生成完了とも報告しない。

## 1. 入力と現在地を確認

1. 参考画像・既存三面図・用途・必要なパーツ・保存先を確認する。大きさ、可動部分、リグ、テクスチャ、出力形式のうち結果を左右する不明点だけ質問する。それ以外は仮定を明記して進める。
2. 作業先の指示ファイルと既存成果物を確認する。既存のジョブ記録、ZIP、FBX、テクスチャ、`.blend` があれば再利用できる段階から再開する。
3. 実行時の利用可能ツールを調べる。画像生成には `imagegen`、WindowsのBlender操作には `computer-use` のスキルを読み、その制約を守る。ブラウザ操作は利用可能なブラウザツールの契約に従う。キャッシュ版番号、座標、古いMCPスキーマを固定しない。
4. Blenderの画面操作が使えない場合は不足を伝える。MCPやスクリプトで代替しない。チュートリアルを指定された場合はその内容を確認する。たまたま開いている動画を指定資料扱いしない。
5. 新規生成前に、現在のクレジット消費、無料・有料範囲、公開範囲を確認する。依頼の範囲を超える支出・追加生成や購入は行わない。ログイン、支払い、CAPTCHA、変更できない公開条件はユーザーに引き継ぐ。

## 2. 三面図と生成用画像

- 参考画像を実際に見てから、形状・材質・配色・接続関係を言語化する。既存の適切な三面図があれば再生成しない。
- 新規三面図は同一縮尺の正投影で作る。標準は正面・右側面・背面、平たい機械部品などでは上面・正面・右側面を選ぶ。選択した3方向を明記する。
- 輪郭、突起、穴、厚み、模様、材質境界が各方向で一致するか確認する。左右対称な形状を除き、正面と側面の単なる複製を認めない。透視図、不要な背景、強い影、文字の混入を避ける。
- 元作品からオリジナル化する依頼では、形状と意匠を設計し直し、固有ロゴなどを引き継がない。権利上安全だと断定しない。
- 分割数は目的から決める。単一小物は1つでもよい。可動、材質の分離、交換、組み立てが必要な箇所を分割し、必ず3パーツにしない。
- パーツごとに、完成三面図を参照した孤立画像を用意する。単画像入力しかない場合は、三面図シートをそのまま投入せず、形状が読める1パーツの斜め画像にする。複数ビュー入力は現在のTripoが対応し方向対応を確認できた場合だけ使う。
- 生成用画像では接続面、穴が貫通か窪みか、平らな底面、部品の含有・除外範囲を明確にする。画像とプロンプトを保存する。

## 3. Tripoで生成

実行前に [Tripo生成手順](references/tripo-production.md) を全文読む。

各パーツのP2.0選択・生成・テクスチャ・ダウンロードを確認する。品質不足は原則Tripo側で修正し、Blenderでゼロから補作しない。生成し直す前に入力の問題と追加費用を確認する。

## 4. Blenderで組み立て・保存

実行前に [Blenderセットアップ手順](references/blender-assembly.md) を全文読む。

生成形状の比率、接続、材質を確認して組み立てる。元ファイルを保持し、版付きの組み立て用 `.blend` に保存する。テクスチャ同梱の書き出しと別シーンへの再読み込みまで検証する。

## 記録と完了条件

作業先に短い制作記録を残す。最低限、以下を含める。

- 依頼範囲、用途、寸法・軸・単位の仮定、入力画像とプロンプトの場所。
- パーツ名ごとのジョブURL、確認した生成設定、生成・テクスチャ・ダウンロードの各状態、費用が発生した操作。
- 元ZIP/FBX/画像、組み立て `.blend`、書き出しファイルの場所。完成ファイルのサイズとSHA-256。
- ビュー確認、テクスチャ確認、保存後の再オープン、書き出し後の再読み込みの結果。未確認項目と次の作業。

完成報告では「三面図」「Tripo生成」「Blender組み立て」「保存」「再読み込み」を分けて証拠のある項目だけ完了とする。キャラクターのリグ・アニメーション、ゲーム内物理や衝突、Robloxの実表示・公開を、この工程の成功から推定しない。

Robloxへの取り込みも依頼された場合のみ、次工程で `import-roblox-textured-fbx` を使う。このスキル単体ではPlace編集やExperience公開を行わない。
