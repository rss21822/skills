# Roblox設計レンズ

Roblox適合性を「Robloxに公開できるか」ではなく、「Robloxの特性によって企画が強くなるか」で判定する。具体的なAPI、料金、年齢区分、プラットフォーム制限に依存する案では、実装前に最新の公式情報を確認する。

## 媒体特性

各案で少なくとも1つ、統合案で3つ以上を中核へ組み込む。

| 特性 | 企画へ変換する問い |
|---|---|
| アバターとしての身体性 | 見るだけでなく、身振り、装着、変身、運搬、共同作業をどう遊びにするか。 |
| リアルタイム共在 | 他プレイヤーの存在が、情報、役割、感情、出来事をどう変えるか。 |
| 3D空間と物理 | 距離、地形、可視性、重さ、連結、破壊、建築が判断をどう生むか。 |
| サーバー単位の出来事 | その場に居合わせた人だけの事件、共同記憶、役割分担をどう作るか。 |
| 持続するアイデンティティ | 所有物、評判、関係、発見、制作物が次回へ何を持ち越すか。 |
| 複数デバイスからの参加 | 単純な基本操作と、判断・協力による奥深さをどう両立するか。 |
| 継続更新 | 新地域、新役割、新異常、新組み合わせを同じ文法でどう追加するか。 |
| プレイヤー表現 | アバター、拠点、収集、称号、制作物で、推しや価値観をどう見せるか。 |

## 適合性チェック

### 1. 30秒以内に固有動詞へ触れられるか

長い設定説明を避け、移動、接触、選択、協力などの操作から中心の面白さを理解させる。チュートリアルは固有動詞の弱さを埋める説明書にしない。

### 2. 一人でも開始でき、他者で意味が変わるか

参加人数が揃うまで遊べない構造を避ける。一人では基本ループが成立し、他者が入ると役割、取引、驚き、効率ではなく意味そのものが増える設計を優先する。

### 3. モバイルでも基本操作が明快か

高精度の照準や大量の同時入力だけに依存しない。複雑さはボタン数ではなく、観察、タイミング、役割選択、組み合わせ、社会判断から作る。

### 4. セッションとメタループが分かれているか

- セッション: 今回の目的、事件、判断、結末がある。
- メタループ: 所有、関係、知識、制作、世界変化のいずれかが次回へ残る。

単なる数値上昇だけを長期目的にしない。

### 5. 社会性が人数ボーナス以上か

役割分担、交渉、贈与、評判、共同制作、非対称情報、観戦、教える行為のいずれかを入れる。チャットがなくても意味のある意思表示と安全な協力ができるようにする。

### 6. コンテンツ追加が同じ遊びの水増しにならないか

追加単位を、敵の強さやアイテム数だけでなく、新しい相互作用へ接続する。新要素が既存要素との組み合わせを増やし、古い推しや選択を無価値にしないようにする。

### 7. 摩擦と不可逆性が公正か

愛着を作る摩擦は、理解できる因果、回復手段、事前の警告を持たせる。誤操作、切断、課金不足による重大喪失を避ける。限定性や取り逃しへの不安だけを反復理由にしない。

### 8. 子どもを含む場として安全か

詐取、いじめ、排除、賭博的圧力、過度な損失回避を誘発する仕組みを避ける。交換やUGCには確認、取り消し、報告、権限、可視範囲などの安全策を企画段階で添える。外部サービスの利用を必須にしない。

### 9. 収益化を快楽の破壊に使っていないか

支払いで摩擦を消す、対戦優位を買う、愛着対象の喪失を回避する、といった設計をヒット仮説の中核にしない。表現、選択肢、便利さなども、非購入者の社会的価値を下げない形で検討する。

### 10. MVPで仮説を検証できるか

最初の試作では、広い世界や大量コンテンツより次を優先する。

1. 10秒フックが伝わる小さな場面
2. 固有動詞が一度成立する操作
3. 他者が入ると意味が変わる最小の社会関係
4. 1回の結果が次回の選択へ影響する小さな持続要素

## Roblox適合性の記述形式

各案で次の3点を具体的に書く。

1. **使う特性**: 例「サーバー単位の出来事」「アバターの身体性」。
2. **遊びへの因果**: その特性が固有動詞、判断、社会関係をどう生むか。
3. **注意点**: 操作、人数依存、安全性、性能、制作量、継続運営の最大リスク。

「人気ジャンルだから」「マルチプレイだから」「アバターを使えるから」だけでは適合性の説明にならない。
