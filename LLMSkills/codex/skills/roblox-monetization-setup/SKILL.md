# Roblox Monetization Setup

単独実行でも対象発見から保存・連携確認まで行う。親Skillが準備した状態を前提にしない。実行前に [references/product-workflow.md](references/product-workflow.md) を読む。

## 入力と境界

- 所有者、認証アカウント、環境、Universe、対象Place、正本を現在の画面／公式サービスと照合する。商品はUniverseに属するものとして扱い、他ゲームの商品IDを流用しない。
- 商品ごとに安定したローカルキー、種別、既存IDの有無、内容、名称／説明／画像、承認済み価格、販売状態、外部掲載状態、付与先を確定する。未指定の価格・内容・販売開始は選ばない。APIや管理画面で無効化できない状態は「無効」と偽らず、ゲーム内購入導線の停止と区別する。
- 設定／登録、許可されたコード編集、Place公開、実購入、広告・有料処理は別許可。明示された範囲は最後まで続行する。一般公開、ロール変更、返金、データ消去、実購入を設定依頼から推定しない。
- 今回専用の記録先と一時状態を使用する。他Skillのファイル・既定profile・環境変数を変えず、他実行の承認や完了記録を引き継がない。親から受け取る契約も今回の範囲のみ有効。

## 実行

1. 最新の公式仕様、対象商品一覧、所属Universe、既存設定を読む。新規Developer Product登録の前提が不足なら、別途許可された非公開初期登録を完了するか、その前提で停止する。新しいExperienceを勝手に作らない。
2. 既存商品の照合を優先し、未存在が確認できた項目だけ登録する。作成後のタイムアウトは、一覧・ID・時刻・商品仕様で結果を確認してから不足分を再実行。同名だけで同一商品と決めつけない。
3. ID・商品種別・所有者・ベース価格を再確認し、許可されたIDマッピングとUI／購入処理を連携する。表示価格は現在の公式取得経路と地域価格／最適化に合わせ、固定した表示額を購入確定額と扱わない。
4. Developer Productはサーバーのレシート処理と永続的な重複防止、Passは所有権確認と特典付与を点検する。重複通知、保存失敗、再入場、同時サーバーを含む確認を分ける。詳細は参照ファイルに従う。
5. 変更したコードのビルド・テスト・Place反映を確認する。公開が許可されていれば対象全Placeを正式な本番更新手順で公開・版確認、親が担当するならハッシュ付き連携結果を返し、親の公開完了まで販売／外部掲載を保留する。Staging公開Skillを本番に転用しない。
6. 依頼された販売・外部掲載を必要条件の成立後に適用し、保存後再読取する。実購入なしの確認を実購入・実付与・実収益と混同しない。既存売上の確認が依頼された場合だけ `roblox-purchase-revenue-check` を読む。

## 出力と終了

商品ごとにキー／種別／ID／Universe、現在の価格・販売・掲載、変更ファイルとハッシュ、ローカル試験、公開版、実購入・付与・収益の検証状態、未解決を返す。商品ID取得だけで課金連携完了とはしない。

「商品設定完了」「コード連携・公開完了」「実取引確認」を別判定。設定だけの依頼なら設定保存確認で終了し、未公開コードや実取引未検証を記録する。連携・公開まで依頼された場合はそこまで完了するか、具体的な阻害条件を返す。元の販売状態と復旧手段を残し、障害対応として商品削除やデータ巻戻しを行わない。
