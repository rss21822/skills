# 原文登録と確認

## 原文を集める

対象Experienceの全Placeについて、実際に使われる表示文言と翻訳経路を調べる。翻訳移行一覧だけでは、元から原文言語だったTipsやUI定数が欠落する。抽出結果は候補であり、内部名・デバッグ出力・正規表現・削除済み文言・プレイヤー入力を自動登録しない。

大文字小文字、前後の空白、改行を保持する。同じSourceでもContextが異なる場合は区別する。既存Keyの意味を変更しない。画像に埋め込まれた文字、標準チャット等はATCだけで処理できないため、別対応が必要か記録する。

動的UIは、時刻やユーザー名が埋め込まれた毎回異なる文字列ではなく、`Hello {player}!`等の式として登録する。既に整形済みの表示を照合する場合は文字列パラメータを利用できる。数値の書式指定を使う場合は公式の型制約を確認する。複数パラメータで文字列型と数値型を無計画に混在させない。

`Searching m:ss`とNPC待機通知を連結するUIなら、断片だけではなく最終的に1つのTextLabelへ渡される全文式を確認する。一般的すぎる式（名前だけ、任意の全文を1パラメータにする式）は誤一致するため登録しない。

## 追加CSV

レビュー済みJSON配列を`scripts/build_source_csv.py`へ渡す。各要素は`Source`必須、`Key`・`Context`・`Example`任意。UTF-8 BOM / CRLFの原文のみCSVを新規出力する。翻訳列を出さず、クラウド送信はしない。

```powershell
python <skill-dir>/scripts/build_source_csv.py --input <reviewed-sources.json> --output-dir <new-output-directory> --batch-size 50
```

50件は大きなアップロードが失敗する場合の開始値であり、Robloxの固定上限ではない。スクリプトは出力先が既に存在したら停止する。新しい保存先で実行する。

CSV upload前に、対象Universe、追加件数、既存翻訳の変更、削除件数をプレビューで照合する。追加のみの予定なのに削除・翻訳変更が出たら確定しない。既存の手動翻訳を空欄で上書きしない。

## 失敗時の再開

- タイムアウトでもサーバー側で保存される場合がある。画面の処理完了を待ち、次にテーブルまたは同じCSVのプレビューで確認する。進行中にページを繰り返し更新・再送しない。
- 同じ追加CSVが追加0・翻訳変更0・削除0なら、保存済み原文の確認証拠として記録し、確認用プレビューはキャンセルする。翻訳生成完了とは別判定。
- 残りがある場合のみ不足分を再送する。解消しない同一障害は1回の検証付き再試行後に止め、他の対象ゲームを進める。
- CSV downloadが画面の全件数と一致しない場合、部分取得の可能性を調べる。1ページのダウンロードをテーブル全件と扱わない。確認できないバックアップを根拠に削除や置換を行わない。
- ATCは即時ではない。必要な原文は直接追加またはStudio captureで登録し、割当と生成を確認する。翻訳欄を消して強制再生成しない。

## 新セッションの確認

公開済み環境の表示とローカルコード検査を分ける。ロビー、試合前、試合中、Result、エラー・再試行から到達可能な代表例を確認する。動的文言では数字・名前が維持され、文全体が対象言語になるか見る。後から追加したTipsは旧セッションの表示だけで判定しない。

Playerが原文言語で動いていた場合、ゲーム翻訳の故障と断定しない。ユーザーのRoblox言語設定、実行中クライアントの言語、新セッション、翻訳テーブル参照を順に確認する。Studio Playと公開Playerは別の証拠。
