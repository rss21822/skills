# 定量化ガイド

目的は数字を増やすことではなく、**狙う体験を再現し、成立しない組み合わせを見つけ、試作後に調整できる状態にすること**。

## 感覚語を観測可能にする

感覚から直接「楽しさ80点」へ飛ばさない。次の形で設計する。

`感覚 → そう感じる状況 → 操作と結果の関係 → 制御する値 → 観測方法`

例は発想の補助であり、推奨値や必須ジャンルではない。

| 原案の言葉 | 遊びとしての解釈候補 | 制御する値の候補 | 観測すること |
|---|---|---|---|
| すいすい気持ちいい | 進路を選ぶと流れに乗って滑らかに進む | 加速時間、曲がれる範囲、障害間隔、復帰時間 | 立ち止まる箇所、意図しない衝突、連続して操作する時間 |
| 巨大な存在になりたい | 体で道を変え、他者を運ぶ | 体と道の比率、到達距離、同時運搬数 | 大きさを使う選択が発生した場面、対象の見失い |
| わちゃわちゃ | 他者の行動で予定が変わり、助けたり立て直したりする | 同時作業人数、共有対象数、干渉頻度、復旧時間 | 他者への反応、何が起きたか説明できる割合 |
| のんびり癒やされたい | 急かされず触れたり世話したりして、小さな反応を楽しむ | 反応までの時間、活動の長さ、選択肢数 | 放置と鑑賞の区別、自発的な触れ直し、本人の説明 |
| じわじわ怖い | 手掛かりはあるが全情報はなく、進むか待つか迷う | 安全区間、予兆時間、情報範囲、失敗後の損失 | 迷った原因、不公平と感じた失敗、リスク選択 |

原案の別解釈がある場合はユーザーの文脈を優先する。「癒やし」にリスクを足すなど、表の都合で核を変えない。

## 数値の書き方

主要値には次の情報を残す。表でも箇条書きでもよい。

`項目 / 初期値・単位 / 根拠の種別 / 体験との関係 / 調整候補 / 依存する値`

- 初期値と調整幅を分ける。「活動時間2〜10分」だけでは試作時の設定が決まらない。
- 目標と設定値を分ける。「初回成功まで30秒以内」は観測目標であり、成功を強制するタイマーとは限らない。
- 最小・標準・最大や、初心者・習熟者を混ぜない。必要な場面だけ別条件で計算する。
- 対象・単位を明記する。サーバー人数と1チーム人数、プレイヤー1人の報酬とチーム合計、秒と分を区別する。
- 経路距離を直線距離で置き換えない。並行作業を全て直列加算したり、その逆をしたりしない。
- 「1体」「1画面」などMVPの固定数量は、採用理由をまとめて示してよい。全てに調整範囲を付ける必要はない。
- 値を変更したら依存する合計・式・例・判定条件も更新する。

## 関係式を選ぶ

該当する関係だけ使う。式は単純化モデルであり、成立前提を添える。

### 時間と空間

- 直列の活動周期: `周期 = 準備 + 移動 + 主行動 + 結果表示 + 次の開始待ち`。
- 一定速度の移動: `秒 = 経路距離(studs) / 速度(studs/秒)`。加速、旋回、停止がある場合は各区間を分けるか追加時間の仮定を置く。
- 定常的な反復機会の概算: `回数 ≈ 活動可能時間 / 周期`。初回を時刻0に実行できるか、終了時刻ちょうどの完了を数えるかで整数回数が変わる。上限を約束する場合は時系列で列挙する。
- 自由滞在型は退出時刻を強制しない。「代表的な世話1回90秒」など活動単位を計算し、滞在時間とは別に扱う。

### 供給・収集・達成

- 供給総量: `出現回数 × 1回の個数`。開始時配置、補充、共有／個人所有を区別する。
- 運搬容量: `運搬回数 × 1回の持てる個数 × 実際に運搬する人数`。全員が同時に最短経路で動く計算なら理論上限と呼ぶ。
- 最終成立条件: `達成に必要な量 ≤ 時間内の供給量・運搬量・処理量の最小値`。到達可能でも簡単・面白いとは限らない。
- 到達時間: `必要量 / 単位時間当たりの獲得量`。成功率、ボーナス、待ち時間を仮定した場合は明記する。
- 経済を扱う場合: `終了残高 = 開始残高 + 獲得 - 消費`。通貨の供給元・消費先・使い道を対応させ、購入しない通常経路も同じ条件で計算する。

### 戦闘を扱う場合だけ

- 命中回数: `必要命中数 = ceil(HP / 1命中の有効ダメージ)`。
- 初弾が時刻0に命中し、以降全弾命中する単純モデル: `撃破秒 = (必要命中数 - 1) × 命中間隔`。
- 発生前の溜め、飛翔時間、防御、外し、再装填などは別項として扱う。理論値と人間の実戦値を区別する。

### 人数と負荷

- 入力人数に対して、役割数、共有道具数、同時作業枠、待ち時間が成立するか確認する。
- 総参加人数、同時描画される人数、同時に物理計算される物体数を区別する。
- 負荷の仮予算を置く場合は、対象端末、描画条件、最大想定場面、測定方法とセットにする。物体数だけでフレームレートを保証しない。
- 原案が大人数を必須とする場合は、少人数で確認できる操作仮説と、大人数でしか確認できない社会性・負荷の仮説を分ける。少人数成功を大人数成立の証明にしない。

## 計算例: 雲を集めて、空を光らせる

これは計算方法を示す架空の例。人数・周期・難度を他の企画へコピーしない。

**原案**: 「小さな配達屋がふわふわ雲を運び、友達と空に光の道を描く」。核は、運ぶ手触りと共同制作による変化。自動的に対戦にはしない。

**設計仮説**: 1つの道を作る活動は4人で180秒。最初の15秒に選択と準備、続く150秒が運搬可能時間、最後の15秒に道の完成・途中成果を見る。完成目標は24個。未達でも置いた雲は光り、罰や没収はない。1人は1回に2個運ぶ。

**計算前提**: 運搬開始は準備終了後。1往復は経路距離240 studs、速度20 studs/秒で12秒。積み下ろし合計6秒、立ち止まって置き方を選ぶ時間を仮に12秒とする。成功率は置かず、全員がこの周期で運搬する理想条件を計算する。

- 1往復: `240 / 20 + 6 + 12 = 30秒`。
- 全時間: `15 + 150 + 15 = 180秒`。
- 運搬完了は活動開始から45、75、105、135、165秒。165秒ちょうどの完了を含む。
- 1人5回、4人の運搬容量: `5 × 4 × 2 = 40個`。
- 開始時供給を40個と仮定すると、24個の目標は理想容量40個の60%。実際の達成率を示す値ではない。
- 人間1人だけなら容量は10個。24個固定は成立しない。参加人数が確定する準備終了時に、目標を1人6個、2人12個、3人18個、4人24個とする案なら、理想容量に対する比率は揃う。途中退出後の扱いも別途決める必要がある。

**体験との接続**: 「ふわふわ」は雲を持つ・置く操作への反応、運搬時の動き、見通せる経路で表す。計算が正しくても手触りは未検証。最初の運搬で光の道が変わる場面を作り、人間が試す。

## 試作の指標を定義する

指標ごとに、対象集団、計測開始と終了、数える出来事、重複処理、分母、観測期間、仮の合格条件を定める。内部の観測名は設計上の仮称とし、RobloxのAPI名と混同しない。

- **初回体験への到達**: 初見参加者のうち、開始から指定時間内に中心行動の結果を得た人数。未到達と途中離脱も記録する。成功者の平均時間だけで全員の体験を代表させない。
- **目的の理解**: 説明後に目標を自分の言葉で説明し、次の行動を選べた人数／対象の初見参加者数。誘導して得た答えは区別する。
- **自発的な反復**: 再挑戦できる状態になった対象者のうち、指定した時間窓内に、自ら次の活動を開始した人数。再挑戦機会が来る前の離脱も別に報告し、都合のよい分母にしない。
- **他者による変化**: 協力、譲り合い、妨害への対処など、企画が狙った出来事が起きたセッション数／観測セッション数。発生だけでなく、本人が他者との関係を理解したか確認する。
- **操作の支障**: 同じ端末・入力条件で、誤操作、対象の見失い、復帰不能などを回数と原因で記録する。

たとえば「初見8人中6人以上が開始60秒以内に最初の雲を置く」は、この例の形成的な試作基準として提案できる。8人を全市場の代表と扱わず、75%を業界基準や推定成功確率と呼ばない。仮条件を選ぶ理由、失敗箇所、次に変える変数を添える。

同じ人の反復試行を独立した新規ユーザー数にしない。実測がまだなければ結果欄を埋めず、計画として書く。D1など継続率を扱う際は初回訪問の対象集団、日付・時間窓、追跡完了条件を定義し、1回の試遊や再挑戦意向から推定しない。

## 必要なときに確認する公式資料

以下は2026-09-15に確認した参照先。固定の数値推奨ではない。実案件で現行仕様を根拠にする場合は再確認する。

- [Roblox Input](https://create.roblox.com/docs/input): タッチ、マウス／キーボード、ゲームパッドなどの入力と、動作に入力を対応させる仕組み。端末ごとの操作案を検討するときに参照。
- [Roblox Event types](https://create.roblox.com/docs/production/analytics/event-types): 経済・ファネル・カスタムイベントの使い分け。試作で決めた観測を実装へ渡すときに参照。イベント送信の成功は、体験が面白い証拠とは別。
- [Roblox Retention](https://create.roblox.com/docs/production/analytics/retention): 初回訪問の集団ごとにD1・D7・D30を追跡する考え方。公開後の継続率を設計する場合だけ参照。
