# 変更履歴

## 2.0.0 — 2026-09-17

### 統合
問題再定義、切り口変更、ゲームテンプレートの刷新、元ネタからの継承分析を同じ骨格へ統合。
ゲームを中心にしつつ、事業・コンテンツ向けの適用を残した。

### 追加
- Generate / Compare / Redesign / Audit のタスク分岐。
- 共有物・資源・関係の役割からの抽象化。
- 残す・変える・捨てると、中心変更から周辺変更を導く手順。
- 分業、調整、時間、空間、感情の交互運転、相互依存の検査。
- 30の再定義レンズと、同じ判断の候補をまとめる規則。
- 事実、発言、ユーザー情報、仮説、提案、未確認の区別。
- 初期成功と継続運営、仕様差と成功因果、競合仮説の区別。
- 例題、入力テンプレート、回帰テスト、ローカル配置説明。

### 修正
1. 「二項目以上変われば再定義」から、価値側と実装側の両方を確認する方式へ。
2. 深い再定義を常に高価値とはしない。品質・UI・題材・表現の変更も独立に評価。
3. ゲーム初期案へB2Bの支払者・予算ゲートを一律適用しない。
4. 独自資産がない新規企画を自動棄却しない。
5. 既知の操作文法と、所有する模倣耐性のある資産を区別。
6. Compareに候補15案の生成や一位選定を強制しない。
7. 点数と証拠確度を分離し、固定点数で採用・ヒットを保証しない。
8. 人気作の現行機能を初期ヒット原因に流用しない。
9. 前作を弱く説明して新作を過大評価しない。
10. 物語的な一文だけでなく、ルール・判断・行動の連鎖を必須化。
11. 新しい構造が増やす制作、運営、負担、退出の問題も評価。
12. 数値のない推論を市場データやプレイテスト結果に見せない。

### 互換性
Skillの識別名は `problem-redefinition` を維持。
配布は新しいv2フォルダとZIPで行い、会話に添付された旧版のファイルは上書きしない。
旧版の長い一括手順を、短い入口と必要時に読む参照資料へ再構成した。
