# 問題再定義 Skill v2.0.0

これまでの「問題の再定義」「切り口を変える」「人気テンプレートの刷新」「元ネタと派生作の構造比較」を一つの実行型Skillに統合した改訂版。
主な適用はRobloxを含むゲーム企画。事業とコンテンツにも分野別の評価で使える。

> 残す価値を特定し、中心前提を変え、周辺設計を整合させ、捨てる価値を明示し、行動で検証する。

## どのファイルを使うか
- **Skill対応環境**：この `problem-redefinition` フォルダをまとめて使う。入口は [SKILL.md](SKILL.md)。
- **通常のチャット**：配布される `problem-redefinition-v2-complete.md` を添付し、そこに従って対象を分析するよう指定する。一体版はこのフォルダ外の別配布物。
- **手順を把握する**：[共通方法](references/core-method.md)、[30のレンズ](references/reframing-lenses.md) を読む。

SKILL.md単独にも中核手順はあるが、詳細な比較・採点・演習には同梱参照資料が必要。
本パッケージはファイルとして作成したもので、アプリへの登録やPCへのインストールを実行したものではない。

## 4つのタスク
| 呼び方 | 行うこと | 呼び出し例 |
|---|---|---|
| Generate | 既存テンプレートから異なる新案を生成 | 「問題再定義Skillで、Battlegroundの案を10個」 |
| Compare | 元作と派生作の変更を分析 | 「AがBをどう再定義したか、Compare / Deep」 |
| Redesign | 採用済み企画の条件を守って改修 | 「この企画をRedesign。操作と試合時間は変更しない」 |
| Audit | 既存案や分析の飛躍を検査 | 「このヒット要因分析をAudit。未確認の因果を分けて」 |

モード名を指定しなくても、依頼内容から選ぶ設計。
深さはQuick / Standard / Deep。既定はStandard。
Generateの候補は目安5 / 10 / 15。ユーザーの指定件数を優先する。
Compareで意味のない15案を生成することはしない。

## 使い方の例

### 新しいゲームを考える
> 添付の問題再定義Skill v2に従って、BattlegroundをGenerate / Deepで再定義してください。操作の分かりやすさは残し、異なる判断を生む15案を出してください。上位3案の代償を比較し、試作優先案と最小検証まで示してください。

### 既存ヒット作を比較する
> 添付SkillのCompare / Deepで、99 Nights in the ForestとDead Railsを比較してください。両作の対象時点を明示し、残した価値、中心変更、周辺設計の連動、人気への作用仮説を分析してください。開発者の発言と分析者の解釈を分けてください。

### 自分の企画を改修する
> 添付SkillのRedesign / Standardで、以下の企画を改修してください。採用済み条件は維持し、中心価値を変える案を比較してください。追加機能は必須・補強・後回しに分け、変更しない範囲と反証テストも示してください。

## ローカルSkill環境で使う場合
フォルダ名は `problem-redefinition`、入口名は `SKILL.md` のままにする。
Codex向けのローカル配置例は次のとおり。参照資料もまとめて置く。

```text
<project>/.agents/skills/problem-redefinition/SKILL.md
<project>/.agents/skills/problem-redefinition/references/...
```

配置後の呼び出し例：

```text
$problem-redefinition この企画をGenerate / Standardで再定義してください。
```

旧版と同名のSkillを複数の探索先へ置くより、旧版を保存した上で一つの版を有効にする。
利用するクライアントの対応・配置・表示は環境による。実環境での読み込み試験はこのパッケージ作成時には行っていない。
形式・配置の根拠は [形式確認メモ](references/format-and-provenance.md) を参照。

## 含まれるもの
- `SKILL.md`：起動条件、分岐、実行手順、完了条件。
- `agents/openai.yaml`：任意の表示・呼び出し用メタデータ。
- `references/`：判定方法、30レンズ、ゲーム適用、比較、証拠、採点。
- `templates/`：入力、キャンバス、差分表、候補カード、検証計画。
- `examples/`：移動拠点/固定キャンプ比較、Battleground新案、短時間就業、未確認事例。
- `evals/`：回帰テスト入力、期待する振る舞い、採点重み、セルフチェック。
- `CHANGELOG.md`：旧版から何を修正したか。

## 事例の扱い
99 Nights / Dead Railsの例は、会話から抽出した構造を演習条件にしたもの。
タイミーの例は、ユーザー提示の解釈を使ったもの。
Battlegroundの例は架空の新企画。
Steal An Eggの例は、確認できていない仕様を推測で埋めないための演習。
**いずれも現行仕様・最新順位・開発意図・成功因果を確定させる外部証拠の代用にしない。**

## 検証の範囲
YAML/JSON構文、必須フィールド、相対参照、候補レンズ数、採点重み、ZIP整合性を点検する。
回帰テストは入力と期待条件を提供する。作成者の例題セルフチェックと、独立したモデルでの性能評価を区別する。
本Skillはヒットや売上を保証せず、思考・比較・試作の品質を揃えるための道具である。
