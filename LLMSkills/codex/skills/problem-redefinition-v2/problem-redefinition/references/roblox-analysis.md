# ゲーム・Roblox向け適用

本資料は設計上の分析枠組みである。現行の人気順位、仕様、規約、推薦方式の資料ではない。
Robloxを対象とする時は、その時点の公式情報と実際の作品を確認する。

## 1. まず「どんな体験を得たいか」
苦痛の解消だけでなく、挑戦、予測の的中、成長、表現、創作、所属、貢献、驚きも扱う。
難しさ・制約・リスクが楽しさを生む場合は、それを残す。
「簡単で、短く、何でもできる」を常に正解にしない。

問題文の型：
> 【状況にあるプレイヤー/仲間】が、【欲しい体験】を得たい。
> 現行テンプレートでは【制約や役割の偏り】があり、それを【新しい判断・関係】に変える。

この欲求は観察済みか仮説かを明記する。

## 2. 14項目で骨格を読む
| 項目 | 確認すること |
|---|---|
| 初見の約束 | 一文・一場面で何の体験を想像できるか |
| 操作文法 | 移動、選択、攻撃、回避、取得、運搬など |
| 繰り返す判断 | 毎回何を見て何を選ぶか。正解が固定されないか |
| 成功・失敗 | 何を成し遂げ、何を失うか。ゲーム内成果とKPIを分ける |
| 中心物・共有対象 | 拠点、ボール、目標物、敵、順番、共同記録など |
| 資源・成長 | 何を得て消費し、次にできることがどう変わるか |
| 空間 | 前進、周回、帰還、領土、交通、見通し |
| 時間 | 昼夜、短ラウンド、自由参加、締め切り、待機 |
| セッション | 入室、合流、試合、敗北、観戦、再試行、退出 |
| 社会的役割 | 誰が何で役に立ち、誰が決定権を持つか |
| 感情 | 平穏、準備、不安、危機、安堵、達成の順序 |
| 上達・表現 | 知識、操作、判断、創作、スタイルのどれが伸びるか |
| 蓄積・継続 | 一回の挑戦内とセッション間で何が残るか |
| 運営・収益・制約 | 更新、モデレーション、性能、課金、制作負担 |

## 3. 貢献の経路を分ける
敵を倒す、物資を集める、作る、運ぶ、情報を伝える、救助する、場を整える、など。
各経路について本人の楽しさ、成果の可視性、選択可能性、交代可能性を確認する。
非戦闘役を追加しただけで初心者対応が完了したとしない。
重要なのは「違う技能で同じ目的に関与できるか」で、固定職業の多さではない。

比較単位を変える：ソロ／友人グループ／初対面の組み合わせ。
同じ設計でも、会話や合意の前提が違うため効果は同一とは限らない。
属性別の効果は実測なしに断定しない。

## 4. 調整負担を設計する
集合、待機、役割決定、資源配分、情報伝達、退出のどこに負担があるか。
同時行動を減らすと自由度は増え得るが、一体感が弱まる場合もある。
全員が同じ場所へ行く方式、分散して集約する方式、短い同期区間と自由区間を交互にする方式を比較する。
「固定拠点にしたから短時間で遊べる」など、別の軸への飛躍を防ぐ。

## 5. 感情を状態変化に結びつける
感情の名称だけでは設計にならない。
状態→行動可能性→判断→結果→次の状態を書く。
例：物資不足→外出が必要→どこまで行くか→帰還成功→設備が増えて次の遠出が可能。
恐怖は帰還先の価値を強め得るが、恐怖を強めれば必ず継続が増すわけではない。
プレイヤーが危機を予測し、対処し、回復できるかを見る。

## 6. 再定義後の整合を点検する
新しい勝利条件に旧報酬が逆行していないか。
新しい目的に対して、地形・カメラ・情報提示・再挑戦が足りているか。
「都市破壊が目的」なのに遠くの破壊結果が見えないなら、価値の証拠が不足している。
「因縁を育てる」なら、再会・合意・記録の導線が要るが、追跡や粘着を促す仕様は避ける。

## 7. 理解しやすさと新しさ
既知の操作を残し、目的や関係の違いを一つの具体場面で伝える案を検討する。
全く新しい操作が必要な場合も、それだけで却下しない。学習コストに見合う体験かを試す。
「3秒で理解」「30秒で快感」などは目標仮説なら使えるが、普遍的法則として固定しない。

## 8. 集客・継続・共有・課金を別々に説明する
初見のフックが継続理由になるとは限らない。
繰り返す判断が深くても、それが発見されるとは限らない。
動画映えがよくても、参加後に同じ体験が得られるとは限らない。
無料参加者にも十分な価値があり、課金者の体験が他者の楽しさを壊さないかを確認する。
課金候補は化粧品、表現、追加体験等も含めて評価し、能力販売を既定にしない。
確率商品、未成年者、安全、個人データ、知的財産の扱いは適用される最新規約と法令を別途確認する。

## 9. 指標の使い方
分析上の目標、ゲーム内スコア、事業指標、プラットフォーム側の指標を別欄にする。
例：目標=異なる得意分野で協力、行動=貢献の分散、結果=同じグループの再挑戦。
分母、期間、対象群、重複の数え方を定義する。
Visitsはユニーク人数ではなく、プレイ時間だけで満足度を証明しない。
特定の指標を推薦の唯一の目標とせず、公式情報で確認できる範囲と自社仮説を分ける。

## 10. 実装・運営コスト
グラフィックの量だけでなく、同時物理、通信同期、ラウンド状態、途中参加、保存、権限、モデレーション、バランスの組合せ数を見る。
UGCは「ユーザーが作るのでコンテンツ制作費ゼロ」と評価しない。
LLMを使う場合も、統合、テスト、品質管理、実運用が不要になると仮定しない。
最小試作は新しい判断を試す部分に絞り、永続進行・豪華演出・課金を必要なく先に作らない。

## 11. 一文の出力型
> 元の【既知の操作・快感】は残す。
> 【共有対象/成功/時間/空間/関係】を変え、プレイヤーが【新しい判断】を繰り返す。
> その結果、【得たい感情・貢献・表現】を中心に遊べるという仮説を試す。
