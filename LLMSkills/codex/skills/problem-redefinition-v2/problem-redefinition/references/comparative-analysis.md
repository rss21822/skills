# Compare：元ネタと派生作品を比較する

## 入力と出力
入力：AとBの正確な識別、時点、目的、提供資料。
出力：証拠付き共通骨格、差分、主再定義、作用仮説、代償、代替説明、再利用可能な設計原則。
「AがBを再定義した」は検証対象であり、結論として先に固定しない。

## 1. 五つの証拠を別々に確かめる
1. 元作Aが何を提供しているか。
2. 比較作Bが何を提供しているか。
3. AからBへの影響関係が確認できるか。
4. 作り手が具体的に何を意図したと述べているか。
5. どの設計が、どの人気・利用指標に作用したと確認できるか。

似た仕様は3の証明ではなく、3は4や5の証明ではない。
開発者の回顧談は重要だが、実験やプレイログとは証拠の種類が違う。

## 2. 時間を揃える
初期公開版、伸長期、現在を混ぜない。
片方が更新後、片方が初期版しか確認できないなら、比較の限界を明記する。
初期成功に関係し得る仕様と、成功後の維持に関係し得る仕様を分ける。
掲載日・発言日・ゲームの対象時点・計測日を可能な範囲で記録する。

## 3. 比較軸
目的と成果、中心物の役割、反復判断、資源の意味、空間、時間、参加/終了、失敗、協力、感情、上達、進行、共有、収益、運営。
「両方にあるが、役割が違う」を重視する。存在/不存在だけにしない。

差分ごとに分類する：
- 継承：共通する価値・文法。
- 中心変更：新しい目的や判断を作る候補。
- 従属変更：中心変更を成立させる仕組み。
- 独立改善：UIや品質など別に効くもの。
- 運営/流通：露出、更新、配信など。
- 不明：証拠不足。

## 4. 主解釈を競わせる
例えば「共同生活への変更」という仮説に対し、
「分かりやすい日数チャレンジ」「ホラー表現」「協力の分業化」も主要因になり得る。
各解釈が説明できる差分、説明しにくい差分、必要な証拠を比べる。
響きのよい一文が全体を説明していると決めつけない。

## 5. 人気への作用を段階に分ける
| 段階 | 問い | 例となる指標候補 |
|---|---|---|
| 発見 | なぜ見つけてもらえるか | 流入元、露出 |
| 選択 | なぜ他作でなく選ぶか | 同条件でのクリック、参加 |
| 初回 | 約束された体験に到達できるか | 最初の意味ある行動、初回離脱 |
| 反復 | 次の挑戦に理由があるか | 再試行、再訪、別戦略の試行 |
| 社会 | 誰かと遊ぶ理由があるか | 友人同伴、役割選択、グループ再訪 |
| 運営 | 新要素が体験を更新できるか | 更新前後の構成別変化 |
| 収益 | 体験を損ねず価値を売れるか | 支払者構成、満足、離脱との関係 |

以上は分析用の候補であり、特定プラットフォームの公式推薦式ではない。
指標の改善を確認していないときは「作用し得る」と書き、その仮説の測り方を示す。

## 6. 競合仮説と反例
公開タイミング、広告、既存ファン、配信、推薦露出、更新イベント、技術品質、競合作品の状況を代替説明として検討する。
事実確認していないものは「可能な説明」であり、実際に起きた出来事として書かない。
同じ構造で伸びなかった作品、別構造で伸びた作品があれば、主張を絞る。
「再定義したから成功」「大ヒットだから設計が正しい」という循環説明を避ける。

## 7. 最終形式
- 結論：主再定義。設計分析か、開発者意図の確認かを明記。
- 確認できたこと／確認できないこと。
- 共通骨格と元作の強み。
- Before/After表。両作の根拠を各差分に付ける。
- 主要な変更から、行動・感情・協力への作用を説明。
- 初期の選択理由と、その後の継続理由を分ける。
- 元作が勝る場面、失った価値、副作用。
- 主解釈に対する有力な別解、因果検証の限界。
- 自分の企画へ持ち帰れる「操作」。表面的なモチーフの模倣で終えない。
