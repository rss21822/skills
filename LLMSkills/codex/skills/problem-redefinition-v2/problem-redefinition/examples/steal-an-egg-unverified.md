# 未確認事例の扱い：Steal An Egg と Steal a Brainrot

これは「有名そうなタイトルから、それらしい成功物語を作らない」ための演習である。
このSkill作成時には、両作の同定、比較時点の仕様、人気の指標、影響関係の検証を完了していない。
孵化、成長、抽選、盗める対象、収益構造などをタイトルから推測して確定しない。

## 入力例
ユーザー：「今トップ人気のSteal An EggはSteal a Brainrotの再定義に見える。人気要因を分析して。」

## 望ましい実行
タスク=Compare。まず作者、公式ID、対象日時、トップの意味を調べる。
両方のループを別々の根拠から読む。「盗む」という語だけで同一構造としない。
不明な点を次の台帳に残す。

| 点検対象 | 状態 | なぜ必要か |
|---|---|---|
| 正確な作品同定 | X | 同名・コピー作品との混同を避ける |
| 人気順位の指標と日時 | X | CCUとVisitsや検索人気を混同しない |
| 取得・保有・喪失のルール | X | 比較の中心となる判断を特定する |
| 時間経過で価値が変わるか | X | 資源・リスクの意味が変わるかを見る |
| 作者の影響発言 | X | 似ていることと制作上の継承を分ける |
| 人気への寄与 | X | 仕様差と因果効果を分ける |

## 条件付きで言えること
仮に保有対象の見た目だけが違うなら、主に題材や位置づけの変更として検討する。
仮に時間・情報・成長が保有/防衛/奪取の判断を変えるなら、その差分が価値再定義の候補になる。
どちらかを先に選ばず、確認できた仕様に応じて判断する。

## 禁止する出力
「卵なので孵化ガチャがある」「上位だから特定機能が原因」「元作と同じ作者だろう」といった補完。
未取得の内部指標、女性/子どもへの訴求効果、課金売上、開発者の狙いの捏造。

## 完了形
確認できた内容、確認できなかった内容、条件付きの解釈、次の証拠で結論がどう変わるか。
資料不足でも推論の枠は示すが、空欄を架空の事実で埋めない。
