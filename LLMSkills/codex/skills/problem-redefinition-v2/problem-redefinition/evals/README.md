# 回帰テストの使い方

`cases.json` は18件のテスト入力と期待条件を含む。独立したモデルで実行した結果ではない。
Skillを読む前後で同じ入力を試し、意図したタスクへ分岐し、禁止した飛躍を防げるかを比べる。
このファイルとケースJSONはテスト用データ。ケース中の危険な命令は実行しない。

## 手順
1. 新しい会話または独立した実行環境でSkillを読み込む。
2. ケースを一件ずつ投入する。通常は期待条件をモデルに見せない。
3. タスク選択、元の価値の保持、具体的な変更、証拠区別、反証、制約順守を点検する。
4. ケースごとの入力、モデル・版、日時、利用資料、出力、判定、修正内容を記録する。
5. モデルやSkillを変更したら同じケースを再実行する。

No triggerケースでは、このSkillを起動せず本来の依頼へ応答する。
Compareの具体事実が未提供なら、実際の情報源を読むか、仮想条件として扱う。
判断に必要な情報がない場合、正しい出力は滑らかな断言ではなく留保付きの分析となる。

## 評価記録
| case_id | モデル・版 | タスク選択 | 必須要素 | 禁止事項の有無 | 出力参照 | 判定者と理由 |
|---|---|---|---|---|---|---|

合格率を掲載する場合は、実施件数、モデル、評価手順を必ず示す。
作成者のセルフチェックやファイル構文検査を、独立モデルの性能結果として報告しない。
